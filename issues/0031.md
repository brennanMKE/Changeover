# 0031 — Extras have nowhere to go, so ripping them would pollute the Plex Movies library

| | |
|---|---|
| **Status** | open |
| **Phase** | 2 — Choose what gets ripped |
| **Module** | DiscSelection / PlexOrganizer / RipController |
| **Platform** | macOS |
| **First seen** | 2026-09-11 |

## Description

Only movies belong in the Plex library. Extras — featurettes, deleted scenes,
behind-the-scenes pieces — are worth keeping and cheap to rip from a disc that is
already spinning, but they must land **outside** the Plex roots. Plex is pointed at
`Movies` and `TV Shows`, so a new derived path such as `<root>/Clips` is invisible
to it. Nothing in the app expresses that distinction today, and
`PlexOrganizer.move(encodedFile:metadata:plexMoviesPath:log:)`
(`Changeover/PlexOrganizer.swift:8-13`) takes the destination as a bare `String`,
which means an extra can be routed into `Movies/` by passing the wrong argument.

## Long Description

The disc-selection experiment (`DiscSelection.md`) made this ticket necessary by
making it cheap. One scan now yields a confident feature identification
([#0025](0025.md)) *and* a complete, classified list of everything else on the disc.
The rip is already happening; the disc is already spinning; the marginal cost of a
few extra titles is disk space and a few minutes.

### What extras actually cost

Measured from the fixtures, at the default `--minlength` (which is where a human
would look — the `min0` captures are full of 5-second stubs nobody wants):

| disc | feature | extras | overhead | extras kept |
|---|---|---|---|---|
| The Girl With The Dragon Tattoo | 7.43 GB | 0.03 GB | **0.4%** | 4 |
| Hornets' Nest | 6.10 GB | 0.85 GB | **13.9%** | 3 |
| Hanna | 6.80 GB | 1.40 GB | **20.7%** | 7 |
| The Girl in the Spider's Web | 5.85 GB | 1.74 GB | **29.7%** | 4 |
| Super Troopers | 5.38 GB | 1.72 GB | **32.0%** | 8 |
| Weird Science | 6.30 GB | 2.29 GB | **36.3%** | 10 |
| Super Troopers 2 | 5.45 GB | 2.82 GB | **51.8%** | 6 |

The commonly quoted "13–29%" understates the tail. The real range across the corpus
is **0.4% to 51.8%**, and the worst case is a disc with a 39-minute
behind-the-scenes documentary (`super-troopers-2-min0.txt` title 30, 1.4 GB on its
own). Extras are cheap *on average* and occasionally cost half again as much as the
movie. That argues for extras being **opt-in per disc**, visible in the UI with a
running size total, rather than a global "always rip extras" setting the user sets
once and forgets.

### Why the destination must be a type, not a string

This is the substance of the ticket. `PlexOrganizer.move` currently takes
`plexMoviesPath: String` and does `createDirectory` + `moveItem` into it
(`Changeover/PlexOrganizer.swift:16-27`). Adding a second call site that passes a
different string is the obvious implementation and the wrong one: the two calls are
then distinguished only by which variable the caller happened to pass, and the
failure mode — an extra filed as a movie, with a `Title (Year) {tmdb-ID}` folder
and a `.mp4` Plex will happily index — is silent and only visible in Plex.

Make it impossible by construction:

```swift
nonisolated enum Destination {
    case feature      // <root>/Movies/<Title (Year) {tmdb-ID}>/<Title (Year).mp4>
    case extra        // <root>/Clips/<Title (Year) {tmdb-ID}>/<extra name>.<ext>
}
```

The organizer takes a `Destination` and an `AppSettings`-derived root, and *it*
computes the path. A caller cannot supply a path, so a caller cannot supply the
wrong one. The Plex naming convention (`Plan.md`, `Movies.txt`) applies to
`.feature` only; `.extra` is deliberately *not* Plex-shaped, because looking like a
Plex movie is the thing being avoided.

Keeping the extras grouped under the same `Title (Year) {tmdb-ID}` folder name is
worth doing anyway — it makes them findable, and it is what [#0120](0120.md)'s clip
library will want to walk.

### Open question: do extras need encoding at all?

**Genuinely unresolved — do not invent an answer.** Two defensible positions:

- **Keep the ripped MKV.** Extras are an archive, not a playback target. Skipping
  HandBrake saves the encode time entirely (which is most of the wall clock), keeps
  the source lossless, and avoids [#0029](0029.md)'s audio- and subtitle-selection
  problems on titles nobody curated. Costs disk: roughly 2× the encoded size.
- **Encode like the feature.** Consistent, smaller, directly playable, and if
  [#0120](0120.md) ends up sourcing montage clips from extras it will want a format
  something can actually decode on a Raspberry Pi.

The answer probably depends on what Phase 7 decides it needs, which is exactly the
kind of question [#0120](0120.md) says should not be pre-answered. Until then,
**write the destination logic so the file extension is not hard-coded** —
`MovieMetadata.fileName` hard-codes `.mp4` (`Changeover/MovieMetadata.swift:22-24`)
and `.extra` must not inherit that assumption.

## Expected behavior

A single scan produces one feature and a list of extras. The feature is encoded and
moved to `<root>/Movies/…` exactly as today. Any extras the user opted into are
ripped in the same session and land under a separate derived root — `<root>/Clips`
— which Plex does not index. The destination is chosen by a type, not a path, so
there is no code path that can place an extra in `Movies/`.

## Actual behavior

`RipController.rip` rips everything with `"all"`
(`Changeover/RipController.swift:19-24`), `largestMKV(in:)` (`:66-77`) picks one file
by size, and the rest are left in the working directory. `PlexOrganizer.move`
(`Changeover/PlexOrganizer.swift:8-32`) knows only one destination and takes it as a
`String`. `AppSettings` derives `plexMoviesPath`, `plexTVPath`, `workingRipPath` and
`workingEncodePath` from `plexMediaRoot` (`Changeover/AppSettings.swift:20-30`) —
there is no `Clips` path and no notion of a non-Plex destination.

## Notes

Mostly unit-testable, and the important part entirely so:

- **Destination path derivation** — assert that `.feature` produces
  `<root>/Movies/Blade Runner (1982) {tmdb-78}/Blade Runner (1982).mp4` and that
  `.extra` produces a path under `<root>/Clips` that does **not** begin with
  `<root>/Movies`. A test asserting "no destination derivation for `.extra` ever
  yields a path inside `plexMoviesPath`" is the one that encodes the whole point of
  the ticket.
- **Extras classification** — over the fixtures, assert the extras count and total
  size per disc against the table above.
- The `AppSettings` derivation of `clipsPath`, alongside the existing derived paths.

Needs a disc: that a multi-title rip actually produces N files with the right
durations, and that nothing appears in Plex that should not. Say which disc in
`## Verification`, and check Plex's library view — not just the filesystem — because
"invisible to Plex" is the actual claim being made.

**Do not start this before [#0028](0028.md).** Extras are ripped by the same
function, at the same `--minlength`, from the same scan; building a second rip path
while the first is still being rewritten would produce two of them.

## Plan

### Stale assumptions — read these first

The ticket was filed before MakeMKV came off the pipeline (#0014, #0020's
Re-triage). Its core point, that the destination must be a type, still holds.
Much of the surrounding detail no longer does:

1. **There is no rip stage.** `RipController`, `largestMKV(in:)` and the `"all"`
   rip are gone, and #0028 is closed by construction. That changes the encoding
   question: "keep the ripped MKV" was free when MakeMKV ripped everything, but
   now it isn't. HandBrakeCLI can't pass video through, so on the happy path
   every extra is an **encode**. MakeMKV survives only as #0015's feature
   fallback and is never used for extras.
2. **The cost table measures the wrong thing now.** It lists MakeMKV MPEG-2 rip
   sizes. The real cost is encode wall clock: x265 `slow` is the bottleneck, and
   the drive reads at about 5.6 MB/s. Super Troopers 2's 39-minute documentary
   would take roughly a third of a feature's encode time. That strengthens
   "opt-in per disc".
3. **A HandBrake scan reports no size.** `HandBrakeScanParser` sets
   `sizeBytes: 0`, so the "running size total" can only be a running
   **duration** total. #0026's size column has the same gap.
4. **The `--minlength` index shift was a MakeMKV problem.** HandBrake numbers
   titles the way the disc does. The rule that still matters is that extra
   indices come from the *same scan* as the feature index.
5. **The "extras count and size per disc vs the table" fixture test can't be
   built.** The table comes from `Fixtures/makemkvcon/`. The only HandBrake scan
   fixture is `Fixtures/handbrake-scan/dragon-tattoo-title0-min1.json`.
6. **"A single scan produces one feature and a list of extras" hasn't happened
   yet.**
   - `DiscScanner.scan` is called only from tests.
   - `DVDPipeline.run()` still encodes `.mainFeature` (`DVDPipeline.swift:99`).
   - #0027's `RipRequest` doesn't exist.
   - #0025's `DiscTitleHeuristic` is uncommitted. Its `applyingSuggestedRoles`
     already marks titles of 300 s or longer as `.extra` and shorter ones as
     `.ignore`.
7. **`PlexOrganizer.move` has changed.** It is now
   `@concurrent nonisolated async throws(JobFailure)`, with #0012's
   stage-then-`replaceItemAt` body. Its callers are `DVDPipeline` and five sites
   in `JobOutcomeTests`. `JobOutcome` and `JobFailure` are wire format.

### Step A — types

```swift
nonisolated enum LibraryDestination: Equatable, Sendable {
    case feature                    // <root>/Movies/<folderName>/<fileName>
    case extra(titleIndex: Int)     // <root>/Clips/<folderName>/<baseName> - tNN.<ext>
}

/// The only way to get library paths. There is no memberwise init taking
/// three strings, so a caller cannot build roots where clips == movies.
nonisolated struct LibraryRoots: Equatable, Sendable {
    let moviesPath: String   // <root>/Movies
    let tvPath: String       // <root>/TV Shows (used only by the overlap guard)
    let clipsPath: String    // <root>/Clips
    init(mediaRoot: String)
}

nonisolated enum LibraryPaths {
    struct Resolved: Equatable, Sendable { let folder: String; let file: String }
    /// Pure. `sourceExtension` comes from the encoded file, never from
    /// `MovieMetadata.fileName`.
    static func resolve(_ destination: LibraryDestination,
                        metadata: MovieMetadata,
                        roots: LibraryRoots,
                        sourceExtension: String) -> Resolved
}
```

**Resolution rules**

- `.feature` resolves byte-for-byte to today's path and keeps
  `metadata.fileName`, including its `.mp4`.
- `.extra(n)` resolves to
  `clipsPath/<folderName>/<baseName> - t<NN>.<sourceExtension>`.
  - `NN` is zero-padded to two digits.
  - Keeping `folderName` keeps extras findable and gives #0120 a folder to walk.
  - The filename carries the title index because HandBrake gives extras no
    names. It is deliberately not Plex-shaped.
  - Add `nonisolated var baseName` to `MovieMetadata`, and redefine `fileName`
    as `baseName + ".mp4"`, so the extension is written in exactly one place.

**`AppSettings`**

- Gains `var libraryRoots: LibraryRoots { LibraryRoots(mediaRoot: plexMediaRoot) }`
  and `var clipsPath`.
- `plexMoviesPath` and `plexTVPath` delegate to it. They stay as-is for
  `Preflight`, `WorkingFiles` and `SettingsView`.

**`PlexOrganizer.move`**

The new signature. No destination `String` survives:

```swift
@discardableResult @concurrent
nonisolated static func move(encodedFile: String, metadata: MovieMetadata,
                             destination: LibraryDestination, roots: LibraryRoots,
                             log: @MainActor (String) -> Void,
                             onBegin: @Sendable () -> Void = {}) async throws(JobFailure) -> URL
```

- **Guard for `.extra`, before any `createDirectory`.** If the resolved folder
  canonically equals, contains or sits inside `moviesPath` or `tvPath`, throw
  `JobFailure(stage: .organize, reason: .destinationUnwritable(path:))`. This
  catches a `Clips` symlink pointing into `Movies`. Use the `realpath`-based
  overlap check from `WorkingFiles`.
- The rest of the body stays shared and unchanged: directory creation, staging,
  replace, restore on failure.

**Concurrency**

- The new types are `nonisolated` and `Sendable`. The project default is
  MainActor, and the organizer resolves paths off-actor.
- `DVDPipeline` captures `settings.libraryRoots` on MainActor next to its other
  captures (`:68-77`) and passes the value down.

### Step B — the pure seam

```swift
nonisolated struct ExtrasPlan: Equatable, Sendable {
    struct Item: Equatable, Sendable {
        let titleIndex: Int
        let durationSeconds: Int
        let frameRate: Double?          // fed to DeinterlaceDecision per title
        let interlaceDetected: Bool?
    }
    let items: [Item]
    var totalDurationSeconds: Int       // #0026's running total (no bytes: see stale item 3)
    static func make(featureIndex: Int, requested: [Int], disc: DiscInfo) -> ExtrasPlan
}
```

`make` rules:

- Remove duplicate indices.
- Drop `featureIndex`: an extra can never be the feature.
- Drop indices that aren't in `disc.titles`.
- Sort ascending.
- An empty request gives an empty plan. Zero extras is the default and a valid
  job.

### Step B — how it fits encode → move

**Feature first, and pin its index**

- Encode the feature with `.index(featureIndex)` from the same scan, not
  `.mainFeature`. Otherwise HandBrake's own pick could differ from the scan's,
  and an "extra" could be the title that was actually encoded as the movie.
- If #0026/#0027 haven't already swapped `DVDPipeline.swift:99`, this ticket
  does. That line's comment calls the swap "the whole migration".

**Run order**

1. Preflight.
2. Feature encode, with the #0015 fallback unchanged.
3. Feature `move(.feature)`.
4. **Extras loop.**
5. Eject, which moves after the loop because the disc must stay in.
6. `finish(.succeeded(destination: featureURL))`.

**Per extra**

- `EncodeController.encode(source: discPath, title: .index(n), output: <jobDirectory>/<baseName> - tNN.mp4, filter: DeinterlaceDecision.decide(item's fields))`.
- Then `PlexOrganizer.move(destination: .extra(titleIndex: n), roots:)`.
- Use the same job directory, so the #0004 guards, sweep and dispose all still
  apply.

**When an extra fails**

- If either the encode or the move fails:
  1. Log one line.
  2. Remove that extra's file with `WorkingFiles.removeFile`. The disc is the
     source, so an extra is never the only copy, unlike the feature (#0012).
  3. Continue with the next extra.
- `FallbackPolicy` is never consulted for an extra. It only ever sees the
  feature's primary failure, and that invariant stays.
- An extra failure never changes the outcome, because the feature is already in
  Plex. `JobOutcome` and `JobFailure` are not widened, since they are wire
  format (#0060 decides that). Log a summary line such as
  `✓ Extras: 3 of 4 → <clips folder>`.

**Job marker**

- Before the loop, set the marker back to `.encoding`.
- The feature has already moved, and anything left over is re-derivable. The
  `.encoding` sweep rule, delete when stale, fits that.
- Leaving it at `.encoded` would make the sweep report `encodedNeverMoved`
  forever if the app died mid-extra.

**Selection state**

- The feature selection and the extras selection are two separate properties.
  Extras default to empty.
- The extras multi-select UI with its running duration total is #0026's fourth
  mode. This ticket only supplies `ExtrasPlan`.
- `JobController.Runner` still carries `MovieMetadata`. #0027 changes it to
  `RipRequest`, and Step B reads `extraTitleIndices` from there.

### Explicitly out of scope

- **Whether extras should be encoded or archived** (#0120 decides). Step B
  encodes with the feature's `Config` settings, because HandBrake is the only
  engine on the path. The format lives only in the encoded file's extension, so
  a later "faster preset" or "MKV" decision changes `EncodeController`
  arguments, not the destination logic.
- Identifying what an extra is (featurette, deleted scene), naming extras from
  disc metadata, or Plex local-extras conventions (`-featurette`).
- Audio and subtitle selection for extras (#0029). Extras get today's default
  `--aencoder`.
- A MakeMKV fallback for extras.
- Per-extra `JobOutcome` cases.
- Scaling Preflight's 2 GB free-space floor by extras (there's no size data).
- A TV Shows destination.
- Cancel.

### Decisions (user, 2026-09-15)

- **Extras encoder settings:** same as the feature (x265 slow, RF 23); keep the format swappable.
- **Plex libraries on joe** point at `Movies` and `TV Shows`, not the media root, so `<root>/Clips` is invisible to Plex.
- Deleting an extra whose move failed is acceptable (the disc remains the source) — orchestrator default, not separately asked.
