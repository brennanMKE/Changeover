# 0059 — Output files are dominated by copied AC3 audio, and the encoder settings have never been measured

| | |
|---|---|
| **Status** | open |
| **Phase** | 3 — Unattended multi-disc |
| **Module** | Config / EncodeController |
| **Platform** | macOS |
| **First seen** | 2026-09-16 |

## Description

The user reported the ripped files feel very large. Measured on the two films ripped on joe on 2026-09-16:

| | Oppenheimer (3:00:22) | Hornet's Nest (2:27:02) |
|---|---|---|
| File | 1.82 GB | 1.67 GB |
| Video (x265, RF 23, preset slow) | ~314 kbps → 0.42 GB | ~611 kbps → 0.68 GB |
| Audio (AC3 copied from the disc) | 1,024 kbps → **1.39 GB (76%)** | 896 kbps → **0.99 GB (59%)** |

The video encode is already frugal. **Audio is the majority of both files**, because every selected track is copied at the disc's own bitrate (448 kbps for 5.1), and #0027's preselection keeps every matching track — two 448 kbps tracks on an untagged disc, three tracks on Oppenheimer.

Separately, `Config`'s encoder settings (x265, RF 23, preset slow) have never been measured against quality on this project's own material. RF 23 at DVD resolution is conservative; nobody has data either way.

## Expected behavior

Defaults chosen from measurement: a quality target and an audio policy that a person picked after seeing size against a quality metric on real DVD material, with the numbers written down.

## Plan

**Experiment (joe).** `/Volumes/Media/test-fixtures/dragon-tattoo` is a full `VIDEO_TS` copy on local disk, so this needs no disc and no drive time.

1. Encode the same chapter range at RF 23, 24 and 25 (x265, preset slow, audio disabled) plus a near-transparent RF 10 reference.
2. Score each against the reference with `ffmpeg -lavfi libvmaf` (joe's ffmpeg has libvmaf). Note the caveat: the reference is itself an encode, so the scores measure quantization loss relative to a near-transparent copy, not absolute fidelity — fine for choosing between RF values.
3. Tabulate size and VMAF (mean and 1% low) per RF.
4. Compute audio sizes for the candidate policies: copy AC3 448k; AAC 5.1 at 256k; AAC stereo at 160k; AC3 5.1 plus AAC stereo; one track versus all tracks.

**Decisions to take from it.**

- The default RF, with its measured cost in size and VMAF.
- Whether a second matching-language track is kept by default (Hornet's Nest's two untagged 448k tracks are probably the same audio in two mixes).
- Whether 5.1 is transcoded to AAC or passed through — passthru is lossless and Apple TV plays it; AAC 5.1 at 256k saves ~43% per track.
- Whether the audio policy belongs in Settings rather than `Config` — [#0112](0112.md) already covers exposing encoder settings, and this is the evidence that issue needs.

**Out of scope here:** the missing AAC compatibility track is [#0058](0058.md); fix that first or the audio arms measure a layout that isn't shipping.

## Decision (user, 2026-09-16) — settings confirmed on a real conversion

Measured, then confirmed by watching the result. **These are the settings to use for conversions.**

| Setting | Value | Evidence |
|---|---|---|
| Video encoder | x265, preset `slow` | unchanged |
| Quality | **RF 23** | RF 24 saves 12% and RF 25 saves 23% of the *video* bitrate, which is only ~100 MB on a feature, while costing VMAF (95.07 → 94.60 → 94.05 mean, 90.11 → 87.97 at the 1% low). Not worth it: video was never the problem. |
| Deinterlace | `--comb-detect --decomb` | a 1985 telecined transfer came out correct at 23.976 fps; see #0016 for driving this from the scan rather than always-on |
| Audio | **one AAC stereo track at 160 kbps** (`--aencoder av_aac --mixdown stereo --ab 160`) | matches the user's three known-good library files (161–165 kbps AAC stereo, 0.47–0.74 GB per film); replaces copying every selected AC3 track at 448 kbps |
| Extra tracks | not kept by default | copying every matching track is what made the two new rips 59–76% audio |

**The conversion that settled it.** `Weird Science (1985)` was a raw MakeMKV rip (MPEG-2 + AC3 5.1 + DTS 5.1, 8.42 Mbps, 5.51 GB). Re-encoded with the settings above: **0.59 GB, 897 kbps total (video 726 kbps, audio 164 kbps), full 1:33:38** — a 9.3x reduction. The user watched it and approved; the original `.mkv` has been deleted.

For comparison, the library files this was tuned against: The Fifth Element 815 kbps / 0.72 GB, Tombstone 816 kbps / 0.74 GB, Massive Talent 627 kbps / 0.47 GB — all HandBrake 1.10.2, H.264 ~640 kbps video, one AAC stereo ~165 kbps.

### What this means for the app

- `Config`'s encoder constants keep `x265` / `slow` / RF 23.
- `EncodeController`'s audio arguments change from "copy every selected track" to "encode the primary selection as AAC stereo at 160 kbps". This supersedes the earlier orchestrator decision that the first track gets an AAC copy *alongside* AC3 passthru (#0027, #0029), and it subsumes #0058 — there is no `copy:aac` entry left to fall back to AC3.
- AC3 5.1 passthru becomes an opt-in, not the default. Whether that lives in Settings is #0112's question; this issue is the evidence for it.
- #0027's preselection should follow: pick one track, not every match. The untagged-disc rule (keep both when nothing is tagged) needs re-examining against this — two 448 kbps untagged tracks became two copies on Hornet's Nest.
