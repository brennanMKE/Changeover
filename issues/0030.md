## Description

Every TMDB search requires clicking `Search` or pressing Return
(`Changeover/MetadataEntryView.swift:34-38`), and results come back in whatever order
the API returned them (`Changeover/TMDB/MovieSearchViewModel.swift:28`) — so an exact
title match can sit below a remake or a documentary about it. `Plan.md` 11.1 and 11.7
cover both, and `Roadmap.md` line 309 folds them into Phase 2.

## Long Description

This is the one Phase 2 ticket that is not about discs. It is here because
`Roadmap.md`'s cross-cutting notes (lines 308–309) put it here:

> Debounced type-to-search and result sorting (`Plan.md` 11.1, 11.7). Polish; fold
> into Phase 2 where the search UI is already being touched.

Note that `Roadmap.md` carries this under "Things deliberately not in this roadmap"
(line 309) rather than in the Phase 2 work list (lines 108–120), so there is no
corresponding bullet up there — it is filed here so the fold-in is tracked rather
than implied.

That reasoning holds — [#0026](0026.md) and [#0027](0027.md) are both restructuring
`MetadataEntryView`, so touching the search half in the same phase avoids a second
pass over the same file. It is genuinely lower priority than the rest of the block
and contributes nothing to the phase demo; if Phase 2 runs long, this is the ticket
to drop.

Half the debounce machinery is already in place: `runSearch()` cancels the previous
task before starting a new one (`Changeover/MetadataEntryView.swift:137-140`), and
`searchTask` is held as `@State` (`:9`). What is missing is a trigger on query
change and a delay before the request goes out.

## Steps to reproduce

1. Insert a disc (or open the metadata window from the menu bar).
2. Type a movie title. Nothing happens until Return or a click on `Search`.
3. Search for a title with a well-known remake — the exact-year match is not reliably
   first.

## Expected behavior

Typing searches on its own after a short pause, and results are ordered so the
obvious answer is at the top: exact title matches first, then by release year
descending.

## Actual behavior

Search only fires on `onSubmit` or the button (`:34`, `:36`). Results are displayed
in the order TMDB returned them, assigned straight through at
`Changeover/TMDB/MovieSearchViewModel.swift:28`.

## Notes

Fully unit-testable and needs no disc, no network and no CLI tools — the sort is a
pure function over `[TMDBMovie]`, and `MovieSearchViewModel`'s initializer already
takes an injectable `TMDBClient` (`Changeover/TMDB/MovieSearchViewModel.swift:15-17`),
so the debounce behaviour can be exercised against a stub client that records call
counts.

Test at least: exact case- and diacritic-insensitive title match sorts above a prefix
match; ties break by year descending; a movie with no `releaseDate` (`yearText`
returns `"—"`, `Changeover/TMDB/TMDBModels.swift:33-36`) sorts last rather than
crashing or sorting first; and that three keystrokes within the debounce window
produce one network call.

## Plan

### Debounce (`Plan.md` 11.1)

In `Changeover/MetadataEntryView.swift`, add to the body's modifiers alongside the
existing `.onChange(of: selectedID)` (`:23-25`):

```swift
.onChange(of: vm.query) { _, _ in
    searchTask?.cancel()
    searchTask = Task {
        try? await Task.sleep(for: .milliseconds(350))
        guard !Task.isCancelled else { return }
        await vm.search(apiKey: settings.tmdbAPIKey)
    }
}
```

Reuse the existing `searchTask` `@State` (`:9`) rather than adding a second one, so
the explicit `Search` button and the debounce cancel each other correctly. Keep the
button and `onSubmit` working — `runSearch()` (`:137-140`) stays as it is and simply
becomes the zero-delay path.

Guard the empty query: `vm.search` sets `errorMessage` from
`TMDBError.emptyQuery` on a blank string, and firing that on every backspace to empty
would flash an error. Return early when the trimmed query is empty and clear
`vm.results` instead, matching the disabled condition the button already uses (`:37`).

Everything here runs on the main actor by default
(`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`,
`Changeover.xcodeproj/project.pbxproj:416,445`) and `MovieSearchViewModel` is
explicitly `@MainActor @Observable`
(`Changeover/TMDB/MovieSearchViewModel.swift:4-6`), so no isolation annotations are
needed. `vm` is owned with `@State` (`Changeover/MetadataEntryView.swift:5`) per
`Plan.md`'s convention; do not change that to `@StateObject`.

One detail worth getting right: `vm.search` sets `selectedMovie = nil` on every call
(`MovieSearchViewModel.swift:23`). With debounce firing automatically, a stray
keystroke after the user has picked a poster would now silently clear the selection
and disable `Start Ripping` (`MetadataEntryView.swift:129`). Either skip the
auto-search once a movie is selected, or preserve the selection when the new results
still contain it.

### Sorting (`Plan.md` 11.7)

In `MovieSearchViewModel`, sort in `search(apiKey:)` before assigning `results`
(`:28`). Extract a `nonisolated static func sorted(_:for:) -> [TMDBMovie]` so it is
testable without the actor and without the client:

1. Exact title match against the trimmed query — case- and diacritic-insensitive,
   via `compare(_:options:[.caseInsensitive, .diacriticInsensitive])` — first.
2. Then prefix matches.
3. Then everything else.
4. Within each group, `yearText` descending, with `"—"` (no release date) sorting
   last.

Use a stable sort key so equal-ranked results keep TMDB's own relevance ordering
rather than being reshuffled arbitrarily — TMDB's default order is popularity-based
and is a reasonable tiebreaker, not noise to discard.
