# 0054 — A TV disc whose MainFeature is an episode, not the Play All title, is offered as a movie

| | |
|---|---|
| **Status** | open |
| **Phase** | 3 — Unattended multi-disc |
| **Module** | DiscSelection |
| **Platform** | macOS |
| **First seen** | 2026-09-16 |

## Description

`DiscTitleHeuristic.classify` takes HandBrake's `MainFeature` as the answer and then runs the Play All guard **only on that one candidate**. On the TV season disc scanned on joe on 2026-09-16, HandBrake named the Play All title (14, 2:53:33) and the guard fired correctly — see #0025's "Real-disc confirmation" and `ChangeoverTests/Fixtures/handbrake-scan/tv-season-playall-title0-min1.json`.

Nothing guarantees that. On a TV disc with no Play All title, or one where HandBrake names an episode instead, `classify` returns `.single` on a 22-minute episode. The app then presents it as the main feature, the user searches TMDB for the show, picks something, and a single episode is filed in the Plex **Movies** library under a movie's name. That is the same silent wrong-library failure the Play All guard exists to prevent, reached by a different route.

The 45-minute threshold that used to catch this was deleted in #0025's Re-triage, deliberately, because `MainFeature` replaced it. Nothing took over the "is this plausibly a feature at all?" question.

## Triage notes (2026-09-25)

**Stays open — but the dangerous half is closed, and the ticket's own Description
is now out of date.** Checked against `HEAD` = 97a226f.

**What was fixed, and it is the silent-wrong-library failure.** The Description's
premise — "`DiscTitleHeuristic.classify` takes HandBrake's `MainFeature` as the
answer" — is no longer true. `classify` now checks the scanner's answer against
the same 45-minute floor the length fallback uses:

```swift
if let mainFeatureIndex, mainFeatureIndex > 0,
   let candidate = disc.titles.first(where: { $0.index == mainFeatureIndex }),
   candidate.durationSeconds >= featureMinimumSeconds {
    return outcome(for: candidate, source: .scanner, among: disc.titles)
}
return classifyByLength(disc)
```

(`Changeover/DiscTitleHeuristic.swift:152`, `featureMinimumSeconds = 45 * 60` at
`:70`, commit **69779f7** "Stop believing the scanner when it names a trailer as
the feature".) So a 22-minute episode named as `MainFeature` can no longer return
`.single`; it falls through to `classifyByLength`, which finds zero titles clearing
the floor and returns `.none`, which shows the picker. This ticket's "22-minute
episode filed in Plex Movies under a movie's name" cannot now happen through this
route. Note the fix arrived for a different disc — The Bourne Identity's
two-minute-26 trailer named as the main feature — which is why this ticket was
never updated.

Also worth recording: the Description's last paragraph says "Nothing took over the
'is this plausibly a feature at all?' question." Something now has. That sentence
should be read as historical.

**What is still owed — the Plan's actual item.** There is still no
cluster-*membership* guard. `playAllEpisodes(for:among:)`
(`DiscTitleHeuristic.swift`) builds the ≥3-title, 15%-similarity cluster exactly as
the Plan describes, but its final test is `abs(clusterTotal - candidate.durationSeconds)`
— "is the candidate the **sum** of a cluster?". Nothing asks "does the candidate
**sit inside** a cluster?", which is the one line of the Plan that has not been
written.

**And so there is still no TV-disc outcome.** `Outcome` has `.single`, `.playAll`,
`.noTitles` and `.none` — no TV case. On the disc this ticket describes the app
reports `.none`, whose wording is
`DiscTitleFormatting.noFeatureWording`: *"This disc did not identify itself — no
title looks like a feature. That can happen on a TV disc with no Play All title, or
a feature under 45 minutes."* That is a generic hint covering two causes, not the
ticket's "this looks like a TV disc: 8 titles of about 22 minutes". The app knows
enough to say the specific thing and does not say it. `MenuTVSignal.evaluate`
(`Changeover/MenuDerived.swift:125`) *does* detect TV discs from the menus, but its
own doc comment states it "is never an input to the proposal" — warning only.

**Net effect on severity.** This has gone from "a wrong file is silently filed in
Plex" to "the user is asked to choose and is told less than the app knows". That is
a downgrade from correctness to UX, and it is a reasonable candidate for the user to
re-scope or park rather than implement — but it is not resolved, and closing it
would lose the cluster-membership guard that the Play All path still needs as its
mirror image.

**Fixture note for whoever picks this up.** The Plan's unit-test list is still the
right one and the fixtures still exist
(`ChangeoverTests/Fixtures/handbrake-scan/tv-season-playall-title0-min1.json`).
`#0020`'s exit audit records the same gap from the other side and calls it "the
demo's biggest unknown"; that entry is now partly stale for the reason above.

## Expected behavior

A disc whose chosen title looks like one episode among several siblings is not offered as a movie. It says what it looks like — "this looks like a TV disc: 8 titles of about 22 minutes" — and leaves the picker available, exactly as the Play All case does.

## Plan

- Extend the guard so it also runs when the candidate is **a member of** an episode-like cluster, not only when it is the sum of one:
  - Build the cluster over all titles ≥ 5 minutes, as today.
  - If the candidate itself sits inside a cluster of ≥ 3 similar-length titles (within the existing 15% similarity), and the candidate is short enough to be an episode rather than a feature, report the TV-disc outcome instead of `.single`.
  - "Short enough" needs a number. The old 45-minute feature threshold is the obvious one and its evidence is already written down in #0025 (the longest non-feature title in the corpus was 39:46). Reuse it as a named constant with that evidence in the comment; do not invent a second rule.
- Keep the existing Play All path untouched — both routes end in the same outcome.
- A feature-length title that happens to have two similar-length siblings must NOT trip this (a double feature, or a film plus a long documentary). The ≥ 45-minute candidate is never treated as an episode.
- Unit-test against the real fixtures: the TV capture (both the Play All title and, synthetically, each episode as `MainFeature`), Dragon Tattoo and Oppenheimer (must stay `.single`), and the committed makemkvcon corpus.
