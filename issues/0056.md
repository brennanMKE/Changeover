## Description

Captured from a real disc on joe (2026-09-16): *The Girl Who Kicked The Hornets' Nest* scans as `MainFeature: -1` — HandBrake identifies **no** main feature. The disc is not ambiguous in any human sense: title 11 runs 2:26:53 with 16 chapters, titles 1–3 run 8–10 minutes, and everything else is under two minutes.

`DiscTitleHeuristic.classify` takes `MainFeature` as the answer and returns `.none` when it is absent, zero or not in the title list. A negative index falls into that last case. So the app says "This disc did not identify itself — no title looks like a feature" and makes the user pick title 11 by hand, on a disc where one title is fifteen times longer than any other.

#0025's Re-triage deleted the 45-minute threshold heuristic on the evidence that `MainFeature` had answered correctly on the one disc measured at the time (Fargo). This disc is the counter-example. The threshold's own evidence is still recorded in #0025: across nine captured discs, exactly one title per disc ran ≥ 45 minutes, and the longest non-feature title in the corpus was 39:46.

The capture is committed as `ChangeoverTests/Fixtures/discs/hornets-nest/` (#0055).

## Root cause

`DiscTitleHeuristic.classify` treated `MainFeature` as the only possible source of an answer: absent, zero, or an index the title list doesn't contain all went straight to `.none` (`guard let mainFeatureIndex, mainFeatureIndex != 0 else { return .none }`, followed by a failed lookup for an unknown index). A negative index — HandBrake's actual signal for "no main feature at all" on the Hornets' Nest disc — fell into the same unknown-index case, since no title has a negative `index`. #0025's Re-triage had deleted the 45-minute threshold that would have caught this, on the evidence that `MainFeature` answered correctly on the one disc measured at the time (Fargo). The Hornets' Nest capture is the counter-example the Re-triage didn't have: a disc where the scanner gives up but a human (and a simple duration comparison) would not.

## Fix

Followed the Plan as written, with the design already anticipating the FeatureSource requirement:

- `classify` now has one guard for "the scanner gave no answer" (`mainFeatureIndex` absent, `<= 0`, or not present in the title list — `if let mainFeatureIndex, mainFeatureIndex > 0, let candidate = disc.titles.first(where: …)`) instead of the old two-step short-circuit. Falling through calls a new private `classifyByLength(_:)`.
- `classifyByLength` filters titles to those `>= featureMinimumSeconds` (a new named constant, `45 * 60`, with #0025's evidence — the corpus's longest non-feature title, 39:46 — in its doc comment) and promotes only when **exactly one** clears the bar; zero or two-or-more both stay `.none`, matching the existing scanner-answer path's philosophy that ties and double features need a person.
- Both paths (scanner-provided and length-fallback) now share a private `outcome(for:source:among:)` helper that runs `playAllEpisodes(for:among:)` on the candidate before returning `.single` or `.playAll` — the guard runs identically regardless of which path found its candidate, per the Plan's explicit requirement.
- Added `DiscTitleHeuristic.FeatureSource` (`.scanner` / `.length`) and added it as an associated value on `Outcome.single(index:source:)`. This is a source-breaking change to every caller that pattern-matches `.single` — updated `DiscTitleListView.scannedView`/`confirmationRow`, `JobController.applyScanOutcome`, and `applyingSuggestedRoles` (all now bind `_` or `let source` as needed) — kept as a plain enum on the outcome exactly as the Plan asked, rather than a side channel, so #0054's future wiring has one place to read it from.
- `DiscTitleFormatting.featureSourceCaption(_:)` is the new pure/testable seam for the confirmation row's addendum: `nil` for `.scanner` (the ordinary case, no extra line), or a one-sentence caption for `.length`. `DiscTitleListView.confirmationRow` renders it under the existing "Main feature — …" line when non-nil.
- Updated the top-of-file doc comment and the `Outcome.none` doc comment, both of which described the pre-#0025.5 design and were now stale.

**Test updates beyond what the Plan listed**, all driven by the behavior actually changing:

- `absentZeroAndUnknownMainFeatureAllAskTheUser` (old name) exercised a disc whose only title was 6,000 s — *already* at or above the new 45-minute threshold, so under the fix it would now classify as `.single` by length instead of `.none`. Rewrote it (renamed `absentZeroNegativeAndUnknownMainFeatureAllAskTheUserWhenLengthFallsThroughToo`) against a disc whose one title is well under 45 minutes, so it still tests "no answer, and the fallback also finds nothing" — and added an explicit `-1` case, since that's the real disc's shape.
- `mainFeatureZeroNeverMarksAFeature` asserted that `MainFeature: 0` never marks anything the feature, using a disc with one 9,478 s title — which, under the fix, *is* the fallback's exactly-one-candidate case and correctly gets promoted. Split it into two tests: `mainFeatureZeroWithNoTitleClearingTheThresholdNeverMarksAFeature` (same assertion, disc changed so nothing clears the bar) and `mainFeatureZeroStillFallsBackToLengthWhenExactlyOneTitleClearsTheThreshold` (pins the new, deliberate behavior change on the original disc shape).
- Every other pre-existing `.single(index:)` callsite (both in `DiscTitleHeuristicTests` and `DiscCorpusTests`' `assertOutcome`) needed `source:` added or a `_` binding — mechanical, no behavior change, since those discs all have a real scanner-provided `MainFeature`.

## Gotchas

- **A pre-existing test (`mainFeatureZeroNeverMarksAFeature`) was pinning behavior this ticket deliberately changes**, and the first targeted run on gordon caught it as a real failure before this ticket's own new tests were even in scope: its disc had a single 9,478 s title, which is exactly the fallback's promote-by-length case once `MainFeature: 0` is folded into "no answer". This wasn't a mistake in the old test when it was written — it's #0025's Re-triage-era assumption (a scan-problem zero can never lead to a feature) that #0056 explicitly overturns. Split into two tests rather than just updating the one, so both the "still refuses when nothing clears the bar" and "does promote when the fallback finds exactly one" behaviors are pinned separately (see `## Fix`).
- **`swiftc`-compiling the five pure files standalone** (the same technique #0055 used) was the fastest way to independently re-derive the hornets-nest disc.json's `audioTrackCount`/`subtitleGroupCount` without trusting the same Swift code path the app and the test both exercise — worth reaching for again on future fixture manifests.

## Expected behavior

When the scan reports no main feature, fall back to the threshold rule rather than giving up:

- Exactly one title ≥ 45 minutes, and the Play All guard does not fire → treat it as the feature, the same as a `MainFeature` answer would be, and say in the UI that the app chose it by length rather than from the scan's own answer.
- Zero such titles, or two or more → `.none` as today, with the picker.
- The Play All guard runs on the fallback candidate exactly as it does on a `MainFeature` candidate.

## Plan

- Treat `MainFeature <= 0`, absent, or not present in the title list as "the scanner gave no answer", one code path rather than three.
- On no answer, apply the threshold rule (`featureMinimumSeconds = 45 * 60`, a named constant carrying #0025's evidence in its comment): count titles at or above it, and promote only when there is exactly one.
- Run `playAllEpisodes(for:among:)` on the promoted candidate before returning `.single`. A TV disc with no Play All title and no `MainFeature` must not become a movie by threshold.
- The `Outcome` should record *how* the feature was chosen (scanner answer vs length fallback) so #0026's confirmation row can say so, and so #0054's work has a single place to hook into. Keep it a plain value.
- Tests: the hornets-nest capture must produce `.single(11)`; Oppenheimer and Dragon Tattoo must be unchanged (they have real `MainFeature` answers); the TV capture must stay `.playAll`; and a synthetic disc with two ≥ 45-minute titles and no `MainFeature` must stay `.none`.
