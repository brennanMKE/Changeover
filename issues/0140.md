## Resolution notes

> 🟢 Resolved 2026-09-16 — `Start Ripping` and its #0053 reason are pinned below a single window-body `ScrollView` whose minimum height is nil, so no amount of disc content can push the window past the screen again, and the subtitle list collapses behind a one-line summary (4ee8a81, review fix 5173b50).

**Review (2026-09-16, claude-opus-5).** 4ee8a81 is in scope and its
structure is right, for a reason the drafted `## Root cause` only half
states. The window grew because `AppDelegate.showMetadataEntry()` installs
the view as an `NSHostingView` **content view**, and a hosting content view
publishes its root view's *minimum* size as the window's `contentMinSize`.
The old flat `VStack`'s minimum height was the sum of every section's, so 21
subtitle rows arriving after the scan forced the window taller than the
screen and `window.minSize = 560x560` was irrelevant. A `ScrollView` has no
minimum height in its scroll axis, so the whole window's minimum is now just
`actionBar`'s — that, not the presence of a scrollbar, is what makes the bug
unrepeatable. It also means the fix holds for content the issue never
mentioned (a long failure banner, a big result set) and for any future
section added inside the scroll region.

Two details in 4ee8a81 worked against the user, and 5173b50 fixes both:

1. **The audio list was put inside a nested `ScrollView` capped at 160
   points** — the one control on this screen the user *must* operate. The
   filing disc has 7 audio tracks, which do not fit in 160 points, so
   ticking the last one meant scrolling a box inside a box. Worse, on macOS
   an inner scroller captures the wheel/trackpad gesture while the pointer
   is over it, so stacking inner scrollers inside the new outer one risks
   handing the user a window they cannot scroll — the same class of
   dead-end this issue is about. The rows now lay out at natural height
   inside the single outer scroll region, which is safe *because* that
   region has no minimum height: however many audio tracks a disc has, the
   section can no longer grow the window. The nested scrollers left are the
   ones that cannot be anything else — `resultsList` and `titleTable` are
   `List`s, and the log pane is #0043's fixed 130-point auto-scrolling view
   — each with an explicit height, and with the audio rows, folder preview,
   verdict row and section headings giving a wide band of the window where
   a gesture reaches the outer scroll view instead.
2. **The #0053 Start reason could be truncated rather than wrapped.** The
   caption now shares a pinned, fixed-width row with the button, and
   #0049's partial-eject sentence ("The disc was unmounted but could not be
   ejected — retry Eject or remove the disc before starting.") is 103
   characters, wider than that row at the 560-point minimum window width. A
   `Text` squeezed inside an `HStack` truncates instead of wrapping, and
   #0053 made that sentence the only on-screen explanation of a greyed-out
   Start. It now carries `.fixedSize(horizontal: false, vertical: true)` and
   trailing alignment, so it takes a second line rather than being clipped.

## Description

On *The Girl in the Spider's Web* (2026-09-16, joe) the metadata window became unusable: the feature title carries **7 audio tracks and 21 subtitle tracks**, every subtitle is listed as its own row ("English · bitmap — cannot become an MP4 track", 21 times), and the window grew past the screen. The user could not reach `Start Ripping` at all.

Every section in the window lays itself out at full natural height — the search results, the title table, the audio list, the subtitle list and the log — so a disc with a lot of tracks pushes the action bar off the bottom. The subtitle list is the worst offender and is **purely informational**: Phase 2 output carries no subtitles (#0036), so 21 rows of "cannot become an MP4 track" are spending the user's screen on nothing.

## Expected behavior

The action bar is always reachable, on any disc, at any window size. Long lists scroll or collapse inside the window rather than growing it.

## Plan

- Give the window a layout that pins `Start Ripping` (and the Start decision caption from #0053) to the bottom, always visible, and lets the middle scroll.
- Collapse the subtitle list behind a disclosure summarising it ("21 subtitle tracks, none carried into the output"), collapsed by default. It is reference-only until #0036.
- Cap the sections that can grow without bound — search results, the title table, the audio list — with their own scroll areas and sensible maximum heights, rather than one outer scroll view that makes the whole window a long strip.
- Keep the log pane's existing behaviour (#0043's `displayLines`); it is already bounded.
- Check the window's minimum size still shows: the confirmation row, the Start button and its reason, and some log.
- Test the pure parts: a summary-line helper for the collapsed subtitle disclosure belongs in `DiscTitleFormatting` with unit tests. The layout itself is manually verified on joe — no UI tests (CLAUDE.md).

## Root cause

`MetadataEntryView.body` was one flat `VStack(spacing: 0)` holding every
section — search bar, results list, folder preview, the disc title section
(`DiscTitleListView` + `TrackSelectionView`), the failure banner, the log,
and `actionBar` — each laid out at its natural height with nothing to cap
the total. `TrackSelectionView`'s subtitle section was the worst offender:
one `Text` row per `SubtitleGrouping` group with no collapse, so a disc
with 21 logical subtitle tracks (*The Girl in the Spider's Web*,
2026-09-16, joe) rendered 21 rows of "English · bitmap — cannot become an
MP4 track" inline, before `actionBar` ever got laid out. Because the whole
`VStack` had no scroll container, the window (resizable, `minSize`
560x560, but otherwise free to grow with its `NSHostingView`'s intrinsic
content size) grew past the screen with `Start Ripping` unreachable and no
scrollbar to reach it.

## Fix

- **`MetadataEntryView`**: wrapped everything except `actionBar` in a
  `ScrollView`, with `actionBar` pinned below it (separated by a
  `Divider`) in the outer `VStack`. `Start Ripping` and its #0053 reason
  caption are now always laid out last, outside the scrolling region, so
  they're reachable at any window size regardless of how much the disc's
  content would otherwise have grown the middle. `resultsList` (the TMDB
  search results `List`) got a `maxHeight: 220` added alongside its
  existing `minHeight: 220`, turning it into a fixed-height cap instead of
  an unbounded-growth risk for a large result set.
- **`TrackSelectionView`**: the subtitle section is now a `DisclosureGroup`
  (`@State private var subtitlesExpanded = false` — collapsed by default),
  whose label is a new pure function, `DiscTitleFormatting
  .subtitleSummary(count:)`, e.g. "21 subtitle tracks, none carried into
  the output". It replaces the old always-visible "Subtitles" headline +
  "Not carried into the output yet — shown for reference." caption + one
  row per group; the rows themselves only render once expanded. *(As
  implemented, the audio list was also wrapped in a nested `ScrollView`
  capped at `maxHeight: 160`; the review removed that — see Resolution
  notes — because 7 tracks do not fit in 160 points and an inner scroller
  steals the gesture that scrolls the window. The rows lay out at natural
  height and the outer scroll view carries them.)*
- **`DiscTitleFormatting.subtitleSummary(count:)`**: a pure, unit-tested
  function — `"\(count) subtitle track\(count == 1 ? "" : "s"), none
  carried into the output"`. The trailing clause is a constant statement
  about the *output* (#0036's decision — Phase 2 carries no subtitles at
  all), not a per-track fact, so it's correct for any `count` including 1.
- **`AppDelegate.showMetadataEntry()`**: left the window's default
  (620x760) and minimum (560x560) sizes unchanged — updated only the
  comment. Since `Start Ripping` is now pinned outside the scrolling
  region, it's reachable at `minSize` (or smaller, via the middle
  scrolling) regardless of disc content, so the numeric sizes didn't need
  to change to fix this bug.

**Decisions made (not spelled out in the Plan):**

- ~~The audio list uses a **nested `ScrollView`**, not a `List`, to stay
  consistent with its existing `Toggle`-row content (not a selectable
  table) and because the log pane (`logArea`) already nests a `ScrollView`
  inside the same view tree for #0043 — this isn't a new pattern here.~~
  **Reversed in review (5173b50)**: the log pane's nesting is a fixed-height
  read-only view, the audio list is the control the user must operate;
  nesting it made the last of 7 tracks reachable only by scrolling an
  inner box, and each added inner scroller shrinks the area where a
  gesture can scroll the window at all.
- The subtitle disclosure's label **is** the summary sentence (no separate
  "Subtitles" headline above it) — the summary already states what section
  it is and why, so a second heading would repeat that.
- `subtitleSummary(count:)` was written to also read correctly for
  `count == 0`, even though `TrackSelectionView` only shows the section
  when `subtitleGroups` is non-empty — cheap to get right and it's tested.
- Did not touch `EncodeController.swift`/`Config.swift` (a separate agent
  is changing audio encoding there) and did not touch `DiscTitleListView
  .swift`'s `titleTable`, which already had a sensible `minHeight`/
  `maxHeight` cap from #0026/#0038.

## Gotchas

- The window nests scroll regions at runtime: after the review fix, the
  outer body scroll plus the log pane (fixed 130), the `resultsList` `List`
  (fixed 220) and, when shown, the `titleTable` `List` (160–260). Each has
  an explicit height. The audio list was un-nested in review precisely
  because every added inner scroller shrinks the area of the window where a
  trackpad gesture reaches the outer scroll view — the scroll-gesture
  handling between the remaining three is the part that is manually
  unverified above.
- `subtitlesExpanded` is per-`TrackSelectionView` `@State`; since that view
  is recreated whenever the selected title index changes (`MetadataEntryView
  .trackSelectionSection`'s `if let index = jobs.selectedTitleIndex,
  let title = ...`), switching titles resets the disclosure back to
  collapsed, which matches "collapsed by default" for whatever title ends
  up selected.
