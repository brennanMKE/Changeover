|---|---|

## Description

The window has "Don't import this one" (#0167). The CLI had no equivalent, so an
agent could leave a film out only by **never naming it** — which is how The
Jackal stayed out of a WILLIS triple feature.

That works until it doesn't, in three ways:

1. **`select` is additive.** Once a feature is named there is nothing that
   un-names or skips it.
2. **Asking changes the answer.** The app's automatic "already in Plex" skip only
   considers films that have been named, so an agent wanting the app to confirm
   a film is held has to name it — and naming it puts it in the plan.
3. **A guess cannot be dropped.** A film the app itself picked, or carried over,
   cannot be removed at all.

## Fix

`select --skip <title>` and `--unskip <title>`, routed through
`RipFlowController.setFeatureSkipped` — the same method the window's link calls,
so the plan, the gate and the extras attachment cannot disagree about which
films are running. A second path here would be a second chance to get it wrong.

Applied **after** the film choices, so `--movie` and `--skip` in one call mean
what they read as: name these, leave that one out.

A title that is not a feature on this disc is **refused**, not ignored. Silently
accepting it would report success for a skip that never happened and the film
would import anyway.

`isEmpty` had to learn about it too: a request carrying only a skip is a real
request, and without that change `select --skip 6` alone would have been refused
as "a selection that asks for nothing" — which is how an additive verb quietly
loses a new kind of instruction.

## #0242's default, caught before it bit

`setFeatureSkipped` forwards to `applyActiveFeature`, which forwards to
`select`, whose `origin` defaults to `.user`. Threading `origin` through the
skip path was necessary for the same reason #0242 needed it on the selection
path — and #0242's own ticket says this parameter "will be inherited again by
the next internal path that forwards to `select` without thinking about it".

This is that next path. It is the **third**. The ticket predicted it and the
prediction was right, which is an argument for removing the default rather than
continuing to thread it, and that remains open.

## Notes

Requested by the user through the agent session driving joe, 2026-10-10, after
The Jackal had to be left out of a WILLIS triple feature by omission.

One test here was wrong before it was right, and the reason is worth keeping:
asserting the chooser after skipping the **named** film is meaningless, because
skipping it unselects it and there is no choice left to attribute. The test now
names one film and skips another, which is both the real case and the only one
where the question has an answer.
