## Description

The numeric attribute ids inside `TINFO` and `SINFO` lines — the fields that carry
duration, chapter count, size, language and codec — are not documented in MakeMKV's
published `usage.txt`. They come from `apdefs.h` in the MakeMKV SDK and circulate
only as forum folklore. Until they are confirmed against output captured from real
discs, every parser written on top of them is a guess.

## Long Description

`RemoteControl.md` (lines 266–270) already flags this, and the roadmap repeats it
(`Roadmap.md` lines 111–113), but it is not a footnote — it gates
[#0023](0023.md), [#0024](0024.md) and [#0025](0025.md). A wrong attribute id does
not produce a crash or a compile error; it produces a title list where "duration"
is silently the codec name, the longest-title heuristic picks a trailer, and the
rip looks like it worked.

There is a second, subtler correction to make while capturing. The design sketch in
`RemoteControl.md` lines 235–241 writes the line shapes as:

```
TINFO:id,code,value
SINFO:id,code,value
```

That is missing fields. `usage.txt` gives four and five respectively:

```
CINFO:id,code,value                 ← disc attribute
TINFO:title,id,code,value           ← per-title attribute
SINFO:title,stream,id,code,value    ← per-stream attribute
```

So `TINFO` leads with the title index and `SINFO` leads with title index *and*
stream index. A parser written from the sketch rather than from real output would
read the title index as the attribute id on every single line. Capturing real output
is what makes that impossible to get wrong.

Third correction: within those lines, `id` is the attribute id (the `apdefs.h`
value being researched) and `code` is a *message* code used to look up a localized
display name for the attribute. The roadmap's phrasing "verify the `TINFO`/`SINFO`
numeric attribute codes" reads as though `code` is the interesting field. It is
`id`.

## Steps to reproduce

1. On the Mac mini with the optical drive and MakeMKV installed, run:
   `makemkvcon -r --cache=1 info disc:0`
2. Look at any `TINFO` line, e.g. `TINFO:0,9,0,"1:47:21"`.
3. Try to find, in <https://www.makemkv.com/developers/usage.txt>, what `9` means.

## Expected behavior

A checked-in reference table mapping each attribute id used by Changeover to its
meaning, value format and an example, plus captured robot-mode output from real
discs that the parser's tests can run against without a drive.

## Actual behavior

`usage.txt` documents only that the field exists. The ids are unknown, unverified
and undocumented anywhere in this repository, and there is no captured output — so
a parser cannot be tested without physically inserting a disc.

## Plan

### 1. Capture fixtures

On the mini, capture raw robot-mode output to files. Three discs minimum, chosen to
be structurally different:

- A plain single-feature DVD (few titles).
- A disc with substantial bonus features — the actual Phase 2 demo disc.
- A disc with alternate angles or a seamless-branching / playlist structure, which
  is where `SegmentsMap` and near-identical duplicate durations show up.

```bash
makemkvcon -r --cache=1 --noscan info disc:0 > 0021/scan-<slug>.txt 2>&1
```

Capture a second run of at least one disc with an explicit `--minlength=0` to see
titles MakeMKV hides by default (the default minimum title length is not zero, so
`info` does not list every title unless asked — this directly affects whether the
app's own "ignore below N seconds" threshold in [#0025](0025.md) is even reachable).

Store the captures in `issues/0021/` as attachments, and copy them into
`ChangeoverTests/Fixtures/` as the test corpus for [#0023](0023.md). Scrub nothing
except the drive serial in the `DRV` line if one appears.

Attribute **27 (OutputFileName)** is the highest-value row in the table: it is what
lets [#0028](0028.md) delete `largestMKV(in:)`
(`Changeover/RipController.swift:66-77`) and name the ripped file in advance instead
of discovering it by size. Confirm it first, and confirm it is present on *every*
title, not just the first.

Attribute **1 (Type)** and **4 (LangName)** are localized display strings. Note in
the table which attributes are locale-dependent, because the parser must not branch
on them — [#0023](0023.md) will classify streams from attribute 5 (CodecId), whose
values are stable identifiers.

Record the confirmed table in the ticket's `## Verification` and, on resolution,
promote it into a doc comment at the top of the parser file so it lives next to the
code that depends on it.

### 3. Nail the lexical details

These are what actually break parsers, and the captures answer all of them:

- **Quoting.** String values are quoted. Confirm how an embedded `"` is escaped
  (doubled `""` versus backslash) — a disc whose volume name contains a quote is the
  test case, but the DVD volume names in the captures may settle it.
- **Commas inside quoted values.** A disc named `Rocky, The Complete Saga` proves
  that naive `split(separator: ",")` is wrong and a quote-aware field splitter is
  required. Note this explicitly in the table's preamble.
- **Line termination and chunking.** Confirm whether progress output uses `\r`
  rather than `\n`. This matters for [#0024](0024.md): the existing
  `readabilityHandler` in `Changeover/RipController.swift:31-41` splits each
  `availableData` chunk on newlines with no carry-over buffer, so a line straddling
  two reads is silently corrupted. Cosmetic for a log; fatal for a parser.
- **`MSG` lines.** Record the `MSG:code,flags,count,message,format,params…` lines
  emitted for the failure cases [#0024](0024.md) must classify: an expired or
  missing MakeMKV key, no disc in the drive, and a scratched/unreadable disc.
  Capture at least the key-expiry case if one can be provoked, since
  `RemoteControl.md` line 459 calls it out as a recurring real-world failure. Record
  the process exit status for each too — an expired key may well exit non-zero,
  but it may also exit 0 with `TCOUT:0`, and the difference determines whether
  [#0024](0024.md) can rely on exit status at all.
- **`TCOUT` versus title count.** Confirm `TCOUT:n` matches the number of distinct
  title indices appearing in `TINFO` lines. If it does not, the parser trusts the
  `TINFO` lines and logs the discrepancy.

### 4. What not to do

Do not add a MakeMKV SDK dependency or vendor `apdefs.h` into the repo to shortcut
this. The SDK carries its own licensing, the app shells out to the CLI by design
(`Changeover/RipController.swift:17-24`), and a confirmed table plus fixtures is a
smaller and more durable artifact than a header file the build would have to track.

No Swift source changes land in this ticket — it produces fixtures, a table, and the
notes the next three tickets are written from.
