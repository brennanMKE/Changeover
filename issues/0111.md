# 0111 — TMDB API key should be entered in-app with first-run onboarding, not carried in the build config

| | |
|---|---|
| **Status** | open |
| **Phase** | 6 — Ship to other people |
| **Module** | AppSettings / SettingsView / Build config |
| **Platform** | macOS |
| **First seen** | 2026-07-01 |

## Description

The TMDB API key should be entirely a user-provided value entered in the app's Settings, with a first-run onboarding prompt that explains how to get a key and lets the user paste it in — never a value baked into the build. The runtime half of this already exists (`AppSettings.tmdbAPIKey` is read from `UserDefaults`, and `SettingsView` has a `SecureField` for it), but two gaps remain:

1. **No first-run onboarding.** A new user isn't told they need a TMDB key or how to obtain one. On first launch the app opens Settings when unconfigured, but there's no guidance beyond the caption text — no explanation of *why* a key is needed or a clear path to `themoviedb.org` to create one.
2. **The build still depends on the key living in `Secrets.xcconfig`.** `Secrets.xcconfig` is wired as the `baseConfigurationReference` for both Debug and Release configs (`Changeover.xcodeproj/project.pbxproj`), and `Secrets.xcconfig.example` still defines `TMDB_API_KEY`. The value is no longer read at runtime, but the file must still exist or the build fails to start (this bit us during release — `error: Unable to open base configuration reference file`). The key, and ideally the whole build-time dependency on this file, should be removed.

## Expected behavior

- On first use, the app presents clear onboarding: what a TMDB API key is, why it's needed (movie metadata + poster art), a link/button to create one at themoviedb.org, and a field to enter it. Once saved, the app is usable.
- The key is stored securely (see Notes — Keychain preferred over `UserDefaults`).
- Building the project requires **no** TMDB key anywhere in the build config. A fresh clone builds without creating or editing `Secrets.xcconfig`.

## Actual behavior

- First launch opens Settings with only a one-line caption; no real onboarding or "get your key" guidance.
- The build requires `Changeover/Secrets.xcconfig` to exist (it's the project's base configuration), even though its `TMDB_API_KEY` value is unused at runtime. A fresh clone without that file fails to build.
- The key is persisted in `UserDefaults` as plaintext (`~/Library/Preferences/co.sstools.Changeover.plist`).

## Scope

- Add a first-run onboarding prompt/screen with instructions and a link to obtain a TMDB API key, then store the entered key.
- Remove `TMDB_API_KEY` from `Secrets.xcconfig.example` and remove the `Secrets.xcconfig` `baseConfigurationReference` dependency from the project so the build no longer needs that file. Update `README.md` (its "Building → TMDB API Key" section) and `CLAUDE.md` accordingly, since both currently instruct putting the key in `Secrets.xcconfig`.
- Consider migrating storage from `UserDefaults` to the Keychain (`SecItem*`), keeping `settings.tmdbAPIKey` as the accessor so `SettingsView` and `TMDBClient` are unaffected.

## Notes

- Relevant code: `Changeover/AppSettings.swift` (`tmdbAPIKey`, `isConfigured`, `persist()`), `Changeover/SettingsView.swift` (the "Movie Database (TMDB)" GroupBox), `Changeover/TMDB/TMDBClient.swift` (`searchMovies(query:apiKey:)` throws `TMDBError.missingAPIKey` when empty), and `Changeover/AppDelegate.swift` (opens Settings on first launch when `!settings.isConfigured`).
- `AppDelegate` already opens Settings when unconfigured; onboarding can build on that entry point rather than adding a separate window.
- The TMDB key is low-sensitivity (read-only public data), so Keychain here is good hygiene rather than high-stakes — but it establishes the right pattern for any future secret.
- Docs to update once the build no longer needs the file: `README.md` and `CLAUDE.md` both reference the `Secrets.xcconfig` key flow.
