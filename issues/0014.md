# 0014 — Remove the rip stage: EncodeController encodes straight from VIDEO_TS and RipController is deleted

| | |
|---|---|
| **Status** | open |
| **Phase** | 1 — Trustworthy single-disc rip |
| **Module** | EncodeController / RipController / DVDPipeline / AppSettings |
| **Platform** | macOS |
| **First seen** | 2026-09-11 |

## Description

The pipeline rips a disc to an intermediate `.mkv` with `makemkvcon` and then encodes that file with HandBrakeCLI. HandBrake reads DVDs directly, so the rip stage is unnecessary: `EncodeController.encode` should take a `VIDEO_TS` path plus a title number and invoke HandBrakeCLI once. `RipController` is deleted. **This is the commit point of the MakeMKV replacement** — after it lands, no disc touches `makemkvcon` on the happy path, and 5–8 GB of write-then-read per disc disappears.

## Long Description

This is step 4 of `MakeMKVReplacement-Path.md` §3, and it was proven end to end on hardware before being filed. From `MakeMKVReplacement-Results.md` §1, run on `joe` (M1 mini, macOS 26.6.2, 8 GB) on 2026-09-11 against the *Fargo* Special Edition disc:

```
HandBrakeCLI -i /Volumes/FARGO_SE__16X9 -t 1 --format av_mp4 --quality 21 \
  --aencoder "copy:aac,copy:ac3" --subtitle scan --markers -o /tmp/fargo-direct.mp4
```

`work result = 0`. 1,128,135,218 bytes (1.13 GB). h264 712×472, AAC stereo + AC3 5.1, **36 chapters preserved**, duration 1:38:08, 21m44s wall clock for a 98-minute feature. No MakeMKV, no intermediate MKV, no expiring key.

The title number comes from the scan, which was also verified (`-Results.md` §2):

```
HandBrakeCLI -i /Volumes/FARGO_SE__16X9 --scan --title 0 --min-duration 1 --json
→ MainFeature: 1   titles: 8
```

**`--title 0` is mandatory.** Without it HandBrake scans only title 1, returns valid JSON, and is silently incomplete — the symptom is a scan returning exactly one title on a disc that should have several. That single detail is called out as the most important invocation fact in the entire results document.

### What this closes by construction

Three open tickets stop describing anything real the moment there is no intermediate file:

- **[#0003](0003.md)** — `RipController` picks the largest `.mkv` in a shared folder, so a stale file can be encoded as the current movie. There is no shared rip folder and no `.mkv` to pick, correctly or otherwise. The selection code (`RipController.swift:66-77`, `largestMKV(in:)`) is deleted along with the file.
- **[#0004](0004.md)** — working folders are never cleaned, so every rip strands its intermediate `.mkv`. There is no intermediate to strand. The encode's own output still needs a home and still gets moved, but the multi-gigabyte per-disc residue is gone.
- **[#0028](0028.md)** — `RipController` rips every title on the disc and then guesses the movie by file size. There is no full-disc rip and no size-based guess; HandBrake is pointed at one title index and encodes that.

"By construction" is the load-bearing phrase. These are not fixed by better code — the code they describe ceases to exist. Each of those three should still be read before this lands, because each documents a constraint worth keeping (per-job isolation, cleanup on success only, verifying by duration rather than size).

### The `--subtitle scan` decision

`--subtitle scan` is currently passed unconditionally (`EncodeController.swift:31`). Decide it deliberately here rather than inheriting it. From `-Results.md` §6: it runs **a complete extra pass over the full title before encoding begins** — the `task 1 of 2` visible in the progress output — and accounted for **roughly half of Fargo's 21m44s**. Phase 3 ([#0040](0040.md)) wants unattended multi-disc throughput, so doubling wall clock per disc for a forced-subtitle scan is a real cost.

It is also the source of the `bin_data` VOBSUB stream that [#0017](0017.md) is about. Two reasons to revisit it, one performance and one correctness, and they point the same way.

Related, non-fatal, observed on the same run: `ERROR: unable to decode subtitle with 2019 bytes.` during the subtitle scan. The encode continued and completed.

## Steps to reproduce

Not a defect report — this is the architectural change the three documents in the `MakeMKVReplacement*` series conclude with. The behavior it replaces is reproducible as [#0003](0003.md)'s steps.

## Expected behavior

`DVDPipeline.run()` is **scan → encode → move**. The encode reads the `VIDEO_TS` path the monitor supplied and the title index the scan chose, and writes the final `.mp4` directly. `RipController.swift` no longer exists. `makemkvcon` is not invoked on any disc that HandBrake can handle.

## Actual behavior

`DVDPipeline.run()` is rip → encode → move. `makemkvcon mkv disc:0 all <dir>` (`RipController.swift:24-29`) writes every title on the disc to `<plexMediaRoot>/Working/ripping`, the largest `.mkv` is selected, and HandBrakeCLI reads that file back (`EncodeController.swift:25-33`). Every disc pays a full write-then-read of 5–8 GB and depends on a beta key with a two-month clock on it.

### 1. `EncodeController` — the new signature

```swift
enum EncodeController {

    /// Which title HandBrake encodes.
    ///
    /// nonisolated + Sendable because it is constructed on MainActor in
    /// `DVDPipeline.run()` and passed into a nonisolated function; the module
    /// default isolation is MainActor (`CLAUDE.md`).
    nonisolated enum TitleSelection: Equatable, Sendable {
        /// `--main-feature` — HandBrake scans the whole disc and picks.
        /// The Phase 1 answer to G1.
        case mainFeature
        /// `--title <n>` — an explicit index. Phase 2's scanner
        /// ([#0023](0023.md)/[#0025](0025.md)) produces this, and
        /// [#0015](0015.md)'s MakeMKV fallback uses `.index(1)` for a
        /// single-title `.mkv`.
        case index(Int)
    }

    nonisolated static func encode(
        source:        String,           // disc volume root, or a file
        title:         TitleSelection,
        output:        String,
        handbrakePath: String,
        log:           @escaping @MainActor (String) -> Void
    ) async -> Result<URL, JobFailure>
}
```

Everything structural about the current implementation is kept verbatim:
`nonisolated static`, `withCheckedContinuation`, the `LogTailBuffer`, the
`Result<URL, JobFailure>` return from [#0007](0007.md), and the
`Task { @MainActor in log(line) }` discipline inside `readabilityHandler`
(`EncodeController.swift:40-51`) and `terminationHandler`
(`EncodeController.swift:56-69`). Exactly one `continuation.resume` per path;
do not restructure it — [#0004](0004.md)'s plan depends on the child process
being gone before the continuation resumes.

**Correction 1 — the parameter is `source`, not `videoTS`, and the value is the
volume root.** The verified invocation is `-i /Volumes/FARGO_SE__16X9`
(`-Results.md` §1) — the **mount point**, not `/Volumes/FARGO_SE__16X9/VIDEO_TS`.
HandBrake accepts both, but only the volume root has evidence behind it, and it
is exactly what `DVDMonitor` already hands over (`DVDMonitor.swift:17-29` uses
`VIDEO_TS` only as the *predicate*, and passes `url`, the volume). Naming the
parameter `videoTS` invites an implementer to append `VIDEO_TS` and silently
leave the verified path. `source` is also honest about the second caller:
[#0015](0015.md) passes a ripped `.mkv` file path through the same function.

### 3. G1 — title selection: `--main-feature`, and what it means

**Decision: Phase 1 ships `.mainFeature`.** `DVDPipeline.run()` passes
`.mainFeature` and nothing else chooses. Hardcoding `-t 1` is wrong on real
discs — *The IT Crowd*'s title 1 is the 2h24 Play All
(`MakeMKVReplacement.md` §R9) and any disc that opens with trailers puts the
feature elsewhere. `--main-feature` is the cheapest correct answer that needs no
scan parser (`MakeMKVReplacement-Findings.md` §3.1, "Other relevant flags").

**How `--main-feature` interacts with `-t`.** They are two ways of answering the
same question and HandBrakeCLI resolves the conflict in its own favour: passing
`--main-feature` makes the CLI scan *all* titles (the same reason `--title 0` is
mandatory for a scan, `-Results.md` §2) and then select the feature itself,
which overrides whatever `-t` said. **Never pass both.** The enum guarantees
that, so the interaction is designed out rather than documented around. **This
behaviour is asserted from HandBrake's documented flag semantics, not measured
on this project's hardware — confirming it is the first item on the joe list in
§9.**

**`--main-feature` is not covered by the verified invocation.** `-Results.md`
§1 ran `-t 1`. Substituting `--main-feature` is a deliberate step off the one
proven command line. Two consequences: joe must re-run the *exact shipped
vector* (§9), and if `--main-feature` turns out to select differently from the
JSON `MainFeature: 1` field, the fallback is `.index(1)` — a one-expression
change at a single call site in `DVDPipeline.run()`. Keep that call site a
single named `let` so the policy is visible and swappable.

**When it picks wrong.** Nothing in Phase 1 can detect it before the encode:
there is no scan (that is [#0023](0023.md)) and no duration cross-check (that is
[#0032](0032.md)). The cost of a wrong pick is a 20–40 minute encode of the
wrong title with no way to stop it ([#0001](0001.md) G7 — there is deliberately
no `cancel()`, `JobController.swift:18-23`), and then a wrong file in Plex.
Phase 1's entire mitigation is **visibility**:

- Log which title HandBrake chose, as the review requires. Add a tiny defensive
  helper — `nonisolated static func selectedTitle(fromLogLine:) -> Int?` — fed
  from the existing `readabilityHandler` line loop, which emits
  `"▶ HandBrake selected title N"` on the first match and nothing after.
- **Write that helper against a captured log, not against a guess.** Nobody has
  a `--main-feature` transcript yet. Capture one on joe from
  `/Volumes/Media/test-fixtures/dragon-tattoo`, check the relevant lines into
  `ChangeoverTests/Fixtures/handbrake/`, and write the parser and its test
  against that text. If the capture is not available when the code is written,
  ship the encode without the parser and log
  `"▶ Title: HandBrake main feature"` — a failure to parse must never fail a
  job, and a guessed regex in place of evidence is worse than no line at all.

Phase 2 replaces `.mainFeature` with `.index(n)` from the scan. That is the
whole migration: one case swap at one call site.

### 4. G2 — who creates the working directory, and when

**Decision: `EncodeController.encode` creates the parent directory of `output`,
immediately before `process.run()`, and fails with
`JobFailure(stage: .encode, reason: .destinationUnwritable(path:))` if it
cannot.**

```
try FileManager.default.createDirectory(atPath: (output as NSString).deletingLastPathComponent,
                                        withIntermediateDirectories: true)
```

Rationale, and why not elsewhere:

- **"Create at the moment of use"** is [#0003](0003.md)'s conclusion (O4 in the
  review keeps only the probe from [#0008](0008.md) once #0003 closes), and the
  controller is the only code that knows it is about to write there.
- It covers every caller for free, including [#0015](0015.md)'s fallback encode
  of a ripped `.mkv`.
- It keeps `DVDPipeline.run()` a pure orchestration function with no filesystem
  work of its own.
- `PlexOrganizer` already creates its own destination folder
  (`PlexOrganizer.swift:29-30`). After this ticket **every path the app writes
  to is created at the moment of use**, and a fresh install no longer fails at
  the first job with a bare exit status. That closes the orphaned half of G2.

**Ordering is load-bearing and is what makes it testable**: create the directory
*first*, launch *second*. A test that points `handbrakePath` at a nonexistent
binary and `output` at `<temp>/does/not/exist/yet/x.mp4` must observe
`.toolMissing` **and** find the directory created — that asserts the ordering
with no HandBrake at all. See §8.

**What this does not do, and must not be mistaken for:** cleanup after a
successful job, the encode output left behind by a *failed* job, and the
launch-time sweep. Those are [#0004](0004.md)'s residual scope. The review's
recommendation is that **#0004 is re-scoped, not closed** — this ticket does not
touch #0004's file and does not earn its closure. Say so in `## Fix`.

**Per-job subdirectories were considered and deliberately rejected here.** The
encode output path is *computed* (`workingEncodePath` + `metadata.fileName`), not
*discovered* by scanning a folder, so [#0003](0003.md)'s "largest file wins"
defect cannot recur regardless of what else is in the folder — a stale file with
the same name is simply overwritten by HandBrake. Per-job isolation
(`JobController.currentJobID`, `JobController.swift:41-43`) buys nothing until
something enumerates that directory, which is #0004's re-scoped cleanup. Leave
the flat path; do not thread `currentJobID` into the pipeline.

**The working folder stays.** The encode writes to `workingEncodePath`
(`AppSettings.swift:30`) and `PlexOrganizer` still moves it. Do not "simplify"
by encoding straight into the Plex Movies folder: [#0012](0012.md)'s
stage-then-swap exists precisely so a partial or failed file is never visible to
a Plex scan, and after this ticket the encoded file is the job's *only* artefact.

### 5. `--subtitle scan` — drop it

**Decision: `--subtitle scan` is removed and no subtitle flag replaces it. The
Phase 1 output carries no subtitle track.**

Reasoning, in order of weight:

1. **It costs roughly half the wall clock.** `-Results.md` §6: it runs a
   complete extra pass over the full title before encoding begins — the
   `task 1 of 2` in the progress output — and was about half of *Fargo*'s
   21m44s. [#0040](0040.md)'s unattended multi-disc throughput is the phase this
   feeds; doubling per-disc time for a track nobody asked for is the wrong
   default to inherit.
2. **It is the sole source of the `bin_data` VOBSUB stream.** That stream is the
   entire subject of [#0017](0017.md), and VOBSUB in MP4 is poorly supported.
   #0017's residual worry is precisely Plex direct play vs a silent transcode;
   removing the track removes the question.
3. **As passed today it is not even doing the useful job.** `--subtitle scan`
   performs HandBrake's Foreign Audio Search pass; burning in forced subtitles
   needs `--subtitle-forced` / `--subtitle-burned` alongside it, which the
   current vector does not pass (`EncodeController.swift:31`). So the app pays a
   full extra pass to attach one bitmap track it never selected on purpose.
4. It also produced the non-fatal
   `ERROR: unable to decode subtitle with 2019 bytes.` noise (`-Results.md` §5).

**The cost, recorded honestly:** a disc whose feature has foreign-language
dialogue subtitled by a forced track will encode without those subtitles. That
is a real regression against the current behaviour for such a disc, and Phase 2
owns the fix — [#0029](0029.md) and [#0027](0027.md) replace the inherited flag
with explicit selection, and #0017's `Pairs with` line already anticipates it.
Phase 1's position is: no subtitles is a defensible, fast, predictable default;
one accidental bitmap track is not.

**Correction 2 — the shipped vector now differs from the verified one in two
places** (`--main-feature` instead of `-t 1`; no `--subtitle scan`), before the
encoder-settings experiment adds a third. The evidence base for the exact
command the app will run is therefore *zero discs*, not one. That is acceptable
— both deltas are removals or substitutions of a title/subtitle flag, not of the
video or audio path — but it makes the joe re-run in §9 mandatory rather than
nice to have, and it is the single most important line in this plan for whoever
signs off the phase demo.

### 11. Risks

- **The shipped command line has no disc behind it** (Correction 2). Mitigated
  only by the joe run in §9. Do not demo the phase without it.
- **`--main-feature` may not mean what this plan says.** It is the plan's one
  claim taken from documentation rather than measurement. If it selects by
  longest-title heuristic rather than the disc's own feature flag, a disc with a
  long Play All title (*The IT Crowd*, 2h24) gets it wrong. The escape hatch is
  `.index(1)` at one call site; the real answer is Phase 2's scan.
- **A wrong title costs 20–40 minutes and cannot be interrupted** (G7 — no
  `cancel()`, by design, `JobController.swift:18-23`). Deliberately deferred to
  Phase 3's queue.
- **HandBrake now holds the disc for the entire job.** There is no rip stage to
  eject after, so eject-on-completion is the only option — the review §1 records
  this as a correction to [#0040](0040.md)'s premise. Worth a line in the commit
  message so [#0005](0005.md) is not implemented against the old assumption.
- **A disc unmounted mid-encode** (a user popping the tray) is uncharacterized;
  HandBrake will fail with read errors and the job fails at `.encode`. Not
  handled here; [#0013](0013.md) territory.
- **One-disc evidence base**, **libdvdcss on a fallback path** (`-Results.md`
  §5) and **uncharacterized bad-sector behaviour** (`-Results.md` §11) all stand
  as written at filing time. The mitigation is #0015's fallback plus logging
  every fallback, not delaying this — and spot-checking playback rather than
  exit codes.
- **Deleting a file plus widening a typealias touches eight test stubs.** If the
  build breaks in `JobControllerTests.swift`, it is arity, not logic. Do not
  "fix" it by reverting the seam.
