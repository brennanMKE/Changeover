# 0243 — The first job of a double feature never reports that it finished

| | |
|---|---|
| **Status** | resolved |
| **Phase** | 4 — Agentic control |
| **Module** | BridgeStatusDiff / BridgeStatusReader / BridgeStatus |
| **Platform** | macOS |
| **First seen** | 2026-10-09 |
| **Closed** | 2026-10-09 |

## Description

Measured on WILLIS, 2026-10-08. `job-20261008-232502-8F8B` went
`starting → encoding → organizing` at 07:01:40.568 and 55 ms later
`job-20261009-000140-AC20` started. **8F8B never got a `job.finished`**, although
`report` listed it as succeeded.

## Why it is a hang and not a cosmetic gap

`import`'s own help tells an agent:

> Wait for it with `wait --for job-done --job <id> --timeout 7200`.

On a double feature the id `import` returns is the first job's — and that is
precisely the id whose event never arrives. An agent following the documented
pattern waits until its timeout on a job that finished successfully minutes
earlier.

## Root cause

The event feed is a diff of two snapshots, and `jobDrafts` only ever looked at
`new.job`. When one job replaces another between two snapshots, the first job's
terminal state is never observed — there is no snapshot in which it appears
finished.

The same shape as #0239: the feed can only report what the diff is taught to
look at.

## Fix

`BridgeStatus.lastFinished` carries the most recently finished job **when it is
not the reported one**, and `BridgeStatusDiff.finishedJobDrafts` emits
`job.finished` for it.

`nil` whenever the finished job is still `status.job`, which is the single-film
case — so the ordinary phase transition keeps reporting that one and nothing is
announced twice. Pinned by `asingleFilmDiscStillReportsExactlyOnce` and
`thesameFinishedJobIsNotReportedTwice`.

Split into its own function rather than folded into the existing one, because
the two answer different questions — "did the reported job change state" and
"did a job end without ever being reported as ended" — and the second has to
fire even when nothing else in the snapshot moved.

## Still open

`import` returns only the **first** job's id on a multi-film disc. The second
job's id appears only in the feed and in `report`, so an agent cannot wait on it
by id at all. That belongs with #0241, which is about the same blindness to the
second film, and is not fixed here.

## Gotchas

`lastFinished.film.chosenBy` is read from the live identification story, which on
a double feature has already moved to the second film by the time this fires —
so on that disc it describes the disc's chooser rather than this job's. Left as
is deliberately: #0242 is open on that field having no way to say "not
recorded", and inventing a value here would be another instance of the same
family rather than a fix.
