# 0071 — There is no client that can discover the host and mirror its state

| | |
|---|---|
| **Status** | open |
| **Phase** | 4 — Remote control from a Mac |
| **Module** | RemoteClient |
| **Platform** | All |
| **First seen** | 2026-09-11 |

## Description

Nothing on the laptop side can find the mini, connect to it, or turn the resulting `RemoteEvent` stream into something SwiftUI can render. `RemoteClient` needs to browse for `_changeover._tcp`, authenticate with the paired key, run the `subscribe` handshake, and mirror the host's state into an `@Observable` session object that views bind to exactly the way they bind to local state today.

## Long Description

This is the counterpart to [#0068](0068.md) and the piece [#0073](0073.md) builds a
UI on. It is deliberately separated from the app target: `RemoteClient` should be
platform-free and live in the package alongside the transport, because
[#0080](0080.md) needs the identical type on iOS and iPadOS. "Restructure the remote
client as a multiplatform target" is a Phase 5 work item that becomes almost free if
the client core never depended on AppKit in the first place.

The design property that makes this small: **the client holds no authority.** It
never computes job state, never decides whether a command is allowed, never merges.
It applies whatever the host sends. `RemoteSession` is a projection of
`JobController`, and every divergence between them is a bug by definition. That rule
is what keeps the client from growing a second, subtly different state machine —
which is the standard way this kind of feature rots.

Discovery is also not as simple as "take the first endpoint". `RemoteControl.md`'s
sketch does `.run { endpoints in .finish(endpoints.first!) }`, which is fine for a
snippet and wrong for a product: there can be zero hosts, several (a second Mac
running Changeover, a stale advertisement `mDNSResponder` has not yet expired), or
one the user is not paired with. And Bonjour instance names are not stable identities
— `mDNSResponder` silently renames conflicts to `Changeover (2)`.

## Steps to reproduce

1. Launch a remote client on the MacBook Air on the same Wi-Fi as the mini.
2. Expect it to find the host and show what the host is doing.

## Expected behavior

The client browses, presents the discovered hosts if there is more than one,
connects to the paired host, completes the handshake, and exposes an `@Observable`
`RemoteSession` carrying connection state, the job queue, disc info and the log — so
a SwiftUI view binds to it the way `MetadataEntryView` binds to local state today.

## Actual behavior

No client exists in any form.

## Plan

**Where it lives.** A `RemoteClient` target in the `ChangeoverProtocol` package. It
imports the protocol types and the transport protocols from [#0062](0062.md), and
nothing platform-specific. No AppKit, no SwiftUI.

**Shape.**

```swift
@Observable
public final class RemoteSession {
    public private(set) var connection: ConnectionState   // .idle .browsing .connecting
                                                          // .handshaking .connected
                                                          // .reconnecting(attempt:)
                                                          // .failed(RemoteClientError)
    public private(set) var jobs: [JobState]
    public private(set) var discInfo: DiscInfo?
    public private(set) var log: [String]
    public private(set) var capability: Capability?
    public private(set) var hosts: [DiscoveredPeer]

    public func start()
    public func send(_ command: RemoteCommand) async
    public func stop()
}
```

**Isolation — read this before writing it.** The package does not inherit the app's
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` (`project.pbxproj:416`, `:445`), so
`RemoteSession` must be annotated `@MainActor` explicitly. It must be MainActor:
`@Observable` drives SwiftUI, and mutating observable state off the main actor is
how "Modifying state during view update" and torn reads appear. The event-receiving
loop runs off-main inside the transport actor and hops in, following the pattern the
codebase already uses at `Changeover/RipController.swift:38` and `:51`
(`Task { @MainActor in log(line) }`) and `Changeover/DVDMonitor.swift:24`. Use
`@Observable` from `Observation` — never `ObservableObject`/`@Published`; `Plan.md`
is binding and this is a new file with no excuse.

**Discovery.** Take a `TransportDiscoverer` ([#0062](0062.md)) by injection.

- Surface **all** discovered endpoints in `hosts`, not `first!`.
- Identify hosts by a stable app-controlled ID — from the TXT record if
  [#0063](0063.md) finds TXT records reachable, otherwise from the handshake after
  connecting. Never by Bonjour instance name.
- Auto-connect when exactly one discovered host matches a peer record the client
  holds. Otherwise present a picker. Remember the last-used host ID in
  `UserDefaults` — that is fine for a host ID; it is emphatically not fine for key
  material, which goes in the Keychain per [#0067](0067.md).
- Handle zero hosts as a real state with actionable copy: same Wi-Fi, host running,
  host awake, Local Network permission granted on this device ([#0074](0074.md)) —
  not a spinner.

**Applying events.** A single `apply(_ event: RemoteEvent)` on the MainActor:

- `.state` replaces `jobs` wholesale. **Never merge.** Merging is how a reconnected
  client keeps displaying a job that finished while the laptop was asleep.
- `.discInfo` replaces `discInfo`; a `.state` of `.idle` clears it.
- `.logReplay` replaces `log`; `.log` appends. Cap the client's array at the same
  2000 lines the host ring uses ([#0069](0069.md)) so a long session cannot grow
  unboundedly on a laptop.
- `.rejected` surfaces the reason to the UI — do not swallow it. A rejected
  `startRip` that produces no visible change is the bug that makes people press
  Start twice.
- `.unsupported` (unknown `kind`, from [#0061](0061.md)) is ignored, but increments a
  counter the UI can use to say "this client is older than the host".

**Sending.** `send(_:)` mirrors the host's validation from [#0070](0070.md) using the
shared `validated()` and `Capability.permits(_:)` before hitting the wire, purely so
buttons can be disabled and errors shown inline. Host-side enforcement stays
authoritative; the client copy is UX.

**Pairing.** The client holds its own peer identity (a `UUID` generated once, stored
in the Keychain) and its link key. Mode A adoption ([#0065](0065.md)) and PIN
pairing ([#0066](0066.md)) both write into that store. If no key exists, `start()`
must land in a state the UI renders as "not paired yet" with a route to pairing —
not in `.failed`.

**Deliberately not here:** reconnect and backoff, which is [#0072](0072.md), and all
UI, which is [#0073](0073.md). Keep `start()`/`stop()` simple enough that
[#0072](0072.md) can wrap them without restructuring.

### Plan refresh (2026-09-15)

**What is stale**

- **The mirrored shape is outdated.**
  - `jobs: [JobState]` / `discInfo` becomes a wholesale-replaced `HostState`
    ([#0061](0061.md)).
  - `log: [String]` becomes per-source `[LogLine]` stores.
  - `capability` comes from `RemoteEvent.session(SessionInfo)`.
- **Isolation-pattern references are stale.** `RipController.swift:38/:51` was
  deleted in #0014. `DVDMonitor.swift:24` is now a DiskArbitration callback that
  hops with `Task { @MainActor in … }`; still a valid pattern, different line.
- **Client identity is not "a UUID stored in the Keychain".** It is the client's
  TLS identity ([#0064](0064.md)), plus a list of pinned hosts
  `PairedHost{hostID, name, fingerprint}`. Fingerprints are integrity-sensitive, so
  they go in the Keychain; the last-used `hostID` may go in `UserDefaults`.
- **Start and retry have concrete host contracts now** ([#0070](0070.md)):
  - `start` must carry `metadata.selectionDisc = hostState.disc`, or
    `JobController.start`'s #0034 guard refuses.
  - A runtime-mismatch refusal is answered by re-sending with
    `MismatchAcknowledgement`.
  - `retry` sends only the `JobID` (#0048 handoff).
- **Pure predicates already exist and should be reused rather than re-derived:**
  `JobPresentation` (renders `JobSnapshot`, including `discRemovedDuringJob`),
  `StartGate`, `CancelPolicy`, `EjectPolicy`, `RuntimeCrossCheck`,
  `LogDisplayRow`/`JobLog.mergedForDisplay`.
  - Move them to `ChangeoverProtocol` (or a `ChangeoverCore` target) when this
    ticket needs them.
  - Before moving, check each one's imports: `FailurePresenter` (used by
    `JobPresentation`), and `AudioTrackOptions`' use of `AppSettings`. A type that
    needs `AppSettings` gets its settings-dependent piece passed in as a value
    instead.

**Replacement plan** (target `ChangeoverRemoteClient`, MainActor)

```swift
public nonisolated struct SessionModel: Equatable, Sendable {      // pure reducer state
    public var connection: ConnectionState          // .idle .browsing .connecting .handshaking .live .reconnecting(attempt:) .notPaired .terminal(RefusalCode)
    public var session: SessionInfo?
    public var host: HostState?
    public var logs: [LogSource: RemoteLogBuffer]   // capped at JobLog.defaultCapacity (2000), dedupes by LogLine.id, epoch-aware
    public var pending: [UUID: RemoteCommand]
    public var lastRefusal: (requestID: UUID, refusal: Refusal)?
    public var unsupportedCount: Int
    public static func reduce(_ state: inout SessionModel, _ event: RemoteEvent)   // nonisolated, pure
}
@MainActor @Observable public final class RemoteSession {
    public private(set) var model: SessionModel
    public private(set) var hosts: [DiscoveredHost]
    public init(browser: any TransportBrowser, pairedHosts: any PairedHostStore, clock: any Clock<Duration>)
    public func start(); public func stop()
    @discardableResult public func send(_ command: RemoteCommand) async -> UUID
}
```

- **Applying events:**
  - `hostState` replaces `host` wholesale; never merge.
  - `logReplay` with a new source or epoch replaces that store; `logAppend`
    appends only ids past the last one.
  - `commandResult` clears `pending[requestID]` and surfaces a refusal.
  - `unsupported` increments a counter and never disconnects.
- **Discovery.** Show all hosts. Auto-connect only when exactly one discovered
  host's TXT `id` matches a `PairedHost`. The TLS pin is the authority; TXT is only
  a hint. Zero hosts is a real state with actionable copy.
- **Client-side gating** is UX only:
  - `Capability.permits`
  - `StartGate.decide`, fed by the client's own `MovieSearchViewModel.runtimeLookup`
  - `CancelPolicy` / `JobPresentation.retryDecision` from `HostState`

  The host re-checks everything.
- **Missing credentials.** With no client identity or no paired host, `start()`
  lands in `.notPaired`, never `.failed`.
- **Isolation.** The reducer is pure and nonisolated. `RemoteSession` is
  `@MainActor`, via explicit annotation or the target's
  `.defaultIsolation(MainActor.self)`. The transport read loop runs off-main and
  hops in. No `ObservableObject`.

**Tests** (in `ChangeoverTests` via `./run-remote-tests.sh gordon`,
`InMemoryTransport`/`InMemoryBrowser`, injected clock; no network):

- `SessionModel.reduce` on a scripted handshake.
- Wholesale replacement: a two-snapshot state followed by a one-snapshot state
  leaves one snapshot.
- Replay then append order, duplicate ids ignored, cap enforced, epoch reset.
- A refusal surfaces with its `requestID`.
- `unsupported` doesn't disconnect.
- Zero, one or several hosts: auto-connect only on a single matching paired host.
- Observe capability disables control commands client-side.
- `start` fills `selectionDisc` from `HostState.disc`.
- A mismatch refusal followed by an acknowledged re-send.
- `retry` sends only the `JobID`.

**Needs two real Macs:** real Bonjour discovery over Wi-Fi, and whether the log
reads as live from across the room.

## Notes

**Fully unit-testable against the `InMemoryTransport` from [#0062](0062.md):**

- Feed a scripted handshake; assert `jobs`, `discInfo`, `log` and `capability` match.
- Assert `.state` replaces rather than merges: apply a two-job state, then a one-job
  state, assert `jobs.count == 1`.
- Assert `logReplay` then `log` produces the right order and the client cap holds.
- Assert an observe-only capability disables control commands client-side.
- Assert zero / one / several discovered hosts each produce the right
  `ConnectionState` and that auto-connect only fires for exactly one matching paired
  host.
- Assert `.unsupported` does not throw and does not disconnect.

**Requires two real machines:** actual Bonjour discovery over Wi-Fi, and the latency
feel of the log stream — whether it reads as live from across the room, which is
what the demo hangs on.

**A note on `@Observable` and large arrays:** appending to `log` on every line during
a rip invalidates views observing it. Keep the log view's observation narrow — a
dedicated child view reading `log` only — so a progress update does not re-render the
poster list. Worth watching in Instruments once real log volume is flowing; it is
much easier to see than to reason about.
