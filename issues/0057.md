# 0057 — capture-disc.sh writes unescaped values into disc.json and ignores a failed scan

## Description

Recorded by the #0055 review, deliberately not fixed there. `Tools/capture-disc.sh` is a human-run capture tool, so none of these is urgent, but each will bite eventually:

- The volume name, drive model and lsdvd's stderr are interpolated into `disc.json` **unescaped**, so a disc whose volume name contains a quote or a backslash produces invalid JSON, and the corpus test then fails on a disc that was captured correctly.
- An explicit `slug` argument isn't sanitized, so `Tools/capture-disc.sh ../../etc` would write outside the fixtures directory.
- A non-zero HandBrakeCLI exit doesn't abort the capture: a failed scan is written out as if it were a disc with no titles.
- `handbrakeVersion` is formatted two different ways across the existing manifests.
- The script leaves `~/changeover-fixtures/` behind on the rip host after every run.

## Expected behavior

The capture tool produces valid JSON for any disc, refuses a slug that isn't a plain kebab-case name, aborts loudly when the scan fails, records the version consistently, and cleans up after itself on the host.

## Plan

- Build `disc.json` with a JSON encoder (a small `python3 -c` or `plutil` step) rather than string interpolation, and normalize `handbrakeVersion` to HandBrake's own `Version:` block.
- Validate the slug against `^[a-z0-9]+(-[a-z0-9]+)*$` and refuse anything else.
- Abort when the scan exits non-zero, printing the last stderr lines; keep the partial capture only if explicitly asked.
- Remove the host-side scratch directory on exit (`trap`), the way the local `mktemp -d` already is.
- Re-derive the existing four manifests afterwards and confirm `DiscCorpusTests` still passes.
