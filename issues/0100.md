## Description

Umbrella for **Roadmap Phase 6 — Ship to other people** (`Roadmap.md:227`). Today the only way to get Changeover onto a Mac is to clone the repo, hand-create a gitignored `Secrets.xcconfig`, build in Xcode, copy the app to `/Applications`, and run `xattr -cr` to defeat Gatekeeper — then guess your way through an unexplained Settings window. Phase 6 replaces all of that with a signed, notarized DMG and a first-run flow that walks a stranger from download to first rip.

## Long Description

Two independent problems are bundled under one phase because neither alone gets
a second person running the app:

1. **Distribution.** The app has never been signed with a Developer ID, never
   notarized, and has no DMG. `ENABLE_APP_SANDBOX = NO`
   (`Changeover.xcodeproj/project.pbxproj:402`, `:431`) is required for the
   `makemkvcon` / `HandBrakeCLI` shell-outs, which permanently rules out the Mac
   App Store — direct Developer ID distribution is the *only* path, so it has to
   be done properly. The `mac-release` skill
   (`/Users/brennan/.claude/skills/mac-release/SKILL.md`) covers this end to end
   with editable script templates; Phase 6 adopts that pipeline rather than
   inventing one.

2. **Onboarding.** `AppDelegate.applicationDidFinishLaunching`
   (`Changeover/AppDelegate.swift:23-25`) opens the Settings window when
   `!settings.isConfigured` and stops there. `isConfigured`
   (`Changeover/AppSettings.swift:33`) checks only that a Plex root and a TMDB
   key are non-empty — it does not check that `makemkvcon` or `HandBrakeCLI`
   actually exist at the configured paths, and it does not check that the TMDB
   key works. A user can see a green "Idle — insert a DVD to begin" dot
   (`Changeover/StatusMenuView.swift:16-18`) and still fail ten minutes into a
   rip.

`RemoteControl.md:86` states the design constraint that makes this phase matter:
**"Not a single-user app."** Nothing in the current setup path may assume the
author's Apple ID, Homebrew prefix, or `/Volumes/MediaSSD` layout.

## Steps to reproduce

1. On a Mac that has never run Changeover, follow `README.md` from the top.
2. Reach `README.md:59` ("Building") and try to supply a TMDB key as documented.
3. Build, copy to `/Applications`, launch.

## Expected behavior

A downloaded DMG opens, the app is dragged to Applications, and it launches with
no Gatekeeper warning and no Terminal step. The app then walks through each
prerequisite — `makemkvcon`, `HandBrakeCLI`, TMDB key, Plex media root, Local
Network access — showing the state of each, and a disc can be ripped.

## Actual behavior

There is no DMG. Building from source requires creating a `Secrets.xcconfig`
that no longer feeds anything (the TMDB key moved to `UserDefaults` in commit
`1c1e3d9`), the built app must be de-quarantined with `xattr -cr`
(`README.md:79`, `Plan.md:306`), and first launch is a bare Settings window with
four fields and no explanation of where the values come from.

## Plan

This ticket carries no implementation of its own. It is closed when every child
is closed and the exit criteria below hold.

Sequencing risk worth stating once, here: **0101 must land before 0102.** The
`mac-release` preflight (`templates/preflight.sh`) hard-fails on any
`MARKETING_VERSION =` or `CURRENT_PROJECT_VERSION =` line in `project.pbxproj`
(`references/versioning.md`, "One source of truth: the xcconfig"), and the
project currently has four of each (`project.pbxproj:401`, `:411`, `:430`,
`:440`). Running the release script against the project as it stands today will
fail at the first gate.

Second sequencing risk: the project-level `baseConfigurationReference` is already
occupied by `Secrets.xcconfig` (`project.pbxproj:276` Debug, `:340` Release), and
a config can only have one. Introducing `App.xcconfig` / `Build.xcconfig` means
deciding what happens to `Secrets.xcconfig` — that decision is 0101's, and
0108's README rewrite depends on it.

## Phase exit criteria

Taken from `Roadmap.md:250-256`:

- A clean-Mac install from the DMG with **no `xattr -cr` step and no Gatekeeper
  prompt** — proven on a Mac (or VM) that has never run Changeover, per
  [#0103](0103.md).
- **Every prerequisite is either auto-detected or explained in the UI** — no
  prerequisite can first surface as a pipeline failure, per [#0104](0104.md),
  [#0105](0105.md), [#0106](0106.md).
- **A person who has not seen the app before can rip a disc without being told
  anything** — tested against a real person or, failing that, a fresh macOS user
  account with no Homebrew, no TMDB key, and no prior `UserDefaults`.

## Notes

**Verification for this umbrella is the demo above, run by someone else.** Every
child ticket has a narrower, mechanically checkable verification step; this one
does not, and should not be closed on the strength of the children's green
checkmarks alone. The honest test needs a second Mac or a fresh macOS VM — see
`issues/Issues.md`, "Build / verify command for this project", which warns that a
green `xcodebuild` is not verification for anything in the rip path.

**Local Network access is listed in the roadmap demo but has nothing to grant
yet.** Changeover does not open a listener or browse Bonjour until the Phase 4
`RemoteServer` lands ([#0060](0060.md)); `NSLocalNetworkUsageDescription` and
`NSBonjourServices` are Phase 4 deliverables (`RemoteControl.md:435-438`,
`:504`). [#0104](0104.md) carries a placeholder row for it so the checklist has
somewhere to put it, but the permission prompt itself cannot be demonstrated in
Phase 6. See the scoping note in that ticket.
