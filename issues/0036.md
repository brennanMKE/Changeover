# 0036 — Phase 2 output carries no subtitles, so forced subtitles and closed captions on the disc are lost

## Description

By decision (recorded on #0027, 2026-09-15), Phase 2 encodes carry no subtitle streams. That keeps the #0017-verified MP4 layout that direct-plays on Apple TV, but it drops two things a viewer can need: **forced subtitles** (for example, translated foreign-language dialogue in an English film) and **CC608 closed captions**. #0033 found CC608 on the feature title of only 2 of 7 scanned discs. #0029's Plan refresh required this follow-on to be filed before it resolved.

## Expected behavior

The user can keep forced subtitles and/or closed captions for the feature, in a form Plex and Apple TV play directly, without breaking the verified audio/video layout.

## Notes

Options to evaluate, not decided:

- CC608 text passthrough into MP4 as `tx3g` (HandBrake converts CC608 to text for MP4).
- Forced subtitles burned in (`--subtitle-burned`) versus kept as a soft forced track. Burn-in is universally compatible but permanent; a soft track depends on client support for the forced flag.
- A sidecar `.srt` next to the MP4 in the Plex folder (Plex naming: `Title (Year).eng.forced.srt`). This needs OCR for bitmap VOBSUB, so it's probably out of scope.
- Selection UI builds on #0033's `SubtitleGrouping` (`selectedTrackNumber` is HandBrake's track number; log the chosen variant).

Anything that changes the output layout must be re-verified on the Apple TV the way #0017 was. Needs joe, discs and `ffprobe`.
