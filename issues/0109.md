# 0109 — MacApp.md is a stale pre-rename spec that still describes an app called PlexDVD

| | |
|---|---|

## Description

`MacApp.md` is a 21 KB "Build & Deployment Guide" for an app named **PlexDVD** (`MacApp.md:1`), written before the project was renamed to Changeover. It names 17 things that no longer exist — `PlexDVDApp.swift`, `PlexDVD.entitlements`, `/Applications/PlexDVD.app` — and its deployment section teaches the same `xattr -cr` workaround (`MacApp.md:615`) Phase 6 is removing. `Plan.md:6` still lists it as a reference doc, so it reads as current guidance.

## Long Description

The file's problem is not that it is old — it is that it is *plausible*. It has a
correct-looking architecture, a correct-looking file layout
(`MacApp.md:122-123`), and correct-looking build steps (`:596-635`), all
describing an app with a different name, a different structure, and a different
distribution story. Specific divergences:

- **The name.** `PlexDVD` throughout: product name (`:74`), entitlements file
  (`:105`), app entry point (`:170-176`), status item accessibility label
  (`:203`), the project file (`:596`), the installed bundle (`:608`, `:615`,
  `:621`), Login Items (`:632-635`), and the troubleshooting table (`:695-696`).
- **The workflow.** `:12-14` describes the user typing "Movie Title, Year, TMDB
  ID (optional)" by hand. The shipped app searches TMDB and populates all three
  from the selected result — `Plan.md`'s UX Flow section is explicit that there
  is "no manual entry of year or TMDB ID", and `MovieMetadata.init(from:)`
  (`Changeover/MovieMetadata.swift`) takes a `TMDBMovie`.
- **The platform baseline.** `:28-29` says Xcode 15, macOS 14, deployment target
  macOS 13. The project is Xcode 26.2 with `MACOSX_DEPLOYMENT_TARGET = 26.2`
  (`Changeover.xcodeproj/project.pbxproj:328`, `:386`).
- **An entitlements file** (`:105`) that does not exist — the project uses
  `ENABLE_APP_SANDBOX = NO` build settings (`project.pbxproj:402`, `:431`) and a
  synthesized Info.plist (`GENERATE_INFOPLIST_FILE = YES`, `:404`).
- **The deployment section** (`:596-635`, `:695`) — manual export, copy to
  `/Applications`, `xattr -cr`, check Login Items by hand. Superseded by
  [#0102](0102.md) and [#0107](0107.md).

Three other historical docs sit alongside it —
`Automated_DVD_to_Plex_Workflow.md`, `mac_plex_dvd_workflow.md`,
`tmdb_swift_mac_app_guide.md` — all listed as references at `Plan.md:6`. They are
research notes rather than specs and are less dangerous, but the same question
applies to them and it is cheaper to answer once.

This is in Phase 6 because Phase 6 is when someone other than the author reads
this repository. Right now the first thing a new contributor finds when looking
for build and deployment instructions is a detailed, confident, wrong document.

## Steps to reproduce

1. Clone the repo and look for build or deployment documentation.
2. Open `MacApp.md` — titled "Build & Deployment Guide", referenced from
   `Plan.md:6` as a current reference.
3. Follow section 1.1 (`:28-29`) or the deployment steps at `:596-635`.

## Expected behavior

Either the file describes Changeover accurately, or it is unmistakably marked as
a superseded historical document, or it is gone. In all three cases the reader
knows within one line which it is.

## Actual behavior

It describes a different app under a different name with a different workflow, a
different macOS baseline and a distribution process Phase 6 replaces — with no
indication that any of it is obsolete.

## Plan

This ticket is **a decision plus a small edit**. The decision is the work; make
it explicitly and record it, because "we should clean up the docs sometime" is
how the file survived the rename.

Three options, in order of recommendation:

**Option A — Archive it (recommended).** Move it to `docs/history/MacApp.md` and
prepend a blockquote at the very top:

> **Superseded.** This is the original pre-implementation spec, written when the
> app was called PlexDVD. It does not describe the current app: the name, file
> layout, metadata workflow, macOS baseline and deployment process have all
> changed. Kept for provenance. See `README.md` for current instructions and
> `Plan.md` for the implementation record.

Cheap, reversible, preserves the design reasoning (the TMDB and MakeMKV notes in
it are still interesting), and removes the trap. Do the same for
`Automated_DVD_to_Plex_Workflow.md`, `mac_plex_dvd_workflow.md` and
`tmdb_swift_mac_app_guide.md` in the same move. Then update `Plan.md:6`'s
reference line to point at the new paths and mark them historical.

**Option B — Delete it.** `git log` and `git show` keep it; nothing is lost that
matters. Faster and leaves the cleanest tree. Choose this if nobody will ever
read it again — but note that `Plan.md:6` and several `Plan.md` phase notes cite
these files, so the citations have to go too, and a dangling reference is its own
small trap.

**Option C — Rewrite it as the real build-and-deploy guide.** Rejected:
[#0102](0102.md) produces `RELEASE.md` from the `mac-release` templates, and
[#0108](0108.md) rewrites `README.md`. A third document covering the same ground
would be the fourth stale file in this repo within a year. Only take this option
if `MacApp.md` is meant to become something the other two are not.

**Mechanics, whichever option wins:**

1. Grep for inbound references before moving or deleting anything:
   `grep -rn 'MacApp.md\|mac_plex_dvd_workflow\|Automated_DVD_to_Plex\|tmdb_swift_mac_app_guide' . --include='*.md' --include='*.swift'`
   — `Plan.md:6` is the known one; check `Roadmap.md`, `RemoteControl.md`,
   `Montages.md` and `issues/` for others.
2. Use `git mv` so history follows the file.
3. Fix every reference found in step 1 in the same change.

**Risks.** (a) Deleting a file someone is using as a reference for Phase 2's
MakeMKV work — `MacApp.md` contains `makemkvcon` invocation detail that may be
the only written record of it. Check before choosing Option B; Option A avoids
the question entirely. (b) Moving files is noisy in a diff — do it as its own
commit, separate from [#0108](0108.md)'s README rewrite.

The last one overlaps with [#0108](0108.md) — between the two tickets, `xattr
-cr` should not appear anywhere outside an explicitly-archived document. That is
a concrete, checkable proxy for Phase 6's headline exit criterion
(`Roadmap.md:252`).

No build verification applies; this ticket touches no code. Say so plainly in the
resolution rather than pasting an unrelated green `xcodebuild` —
`issues/Issues.md` is clear that compilation is not verification, and here it is
not even relevant.
