# 0238 — A job that stalls on bad sectors looks alive for minutes

| | |
|---|---|
| **Status** | open |
| **Phase** | 4 — Agentic control |
| **Module** | ChangeoverBridge / BridgeEventFeed / BridgeStatusDiff |
| **Platform** | macOS |
| **First seen** | 2026-10-08 |

## Description

Both Lady in the Water runs went silent for five to eight minutes between the
last `job.progress` event and `job.finished`:

| run | last progress | failed | silence |
|---|---|---|---|
| `job-20261008-123159-0D74` | 19:59:10, 67 % | 20:07:19 | 8 min |
| `job-20261008-144208-CDE6` | 22:06:57, 67 %, 71.8 fps, eta 724 s | 22:12:23 | 5 min |

Presumably HandBrake grinding retries on the bad sectors. Nothing says so. A
watcher sees a job that was healthy a moment ago — the second run was at full
speed with a twelve-minute ETA right up to the stall — and then nothing at all,
with no way to distinguish "working hard" from "wedged" until it finally fails.

## Why it matters

An agent waiting on `wait --for job-done` has no signal to act on, and a person
watching has no idea whether to leave it. The stall is also the earliest
observable sign of the real fault: it begins the moment the damaged area is
reached, minutes before the failure says so.

## Suggested fix

A `job.stalled` event after some period with no progress report, and the
matching fact in `status` (seconds since the last progress). The threshold needs
a number that does not fire on normal work: the `organizing` phase legitimately
reports nothing for a while, and `remux` has no percentage at all
(`JobProgress`), so it should key on "no progress event" rather than "percentage
unchanged", and probably only during `encoding`.

Pairs with #0236, which gives the position; the stall says *when* trouble
started, the position says *where*.

## Relation

Blocked on nothing, but see the `disc.mounted` gap in #0236: the feed is diffed
from snapshots by `BridgeStatusDiff.drafts(from:to:)`, so any new watchable fact
has to be in the snapshot and in the diff. A stall is a function of elapsed time
rather than of a changed field, so it may not fit that shape without a clock —
worth checking before assuming it is a one-line addition.

## Notes

Observed by the agent session driving joe (`changeover-d1`), 2026-10-08, across
two runs of the same damaged disc.
