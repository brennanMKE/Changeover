# 0061 — There is no shared package defining the remote wire protocol

| | |
|---|---|
| **Status** | open |
| **Phase** | 4 — Remote control from a Mac |
| **Module** | ChangeoverProtocol |
| **Platform** | All |
| **First seen** | 2026-09-11 |

## Description

Every model the remote needs to exchange — `MovieMetadata`, `DiscInfo`, job state, the commands and events themselves — either lives inside the app target or does not exist. Phase 4 needs a `ChangeoverProtocol` Swift package that the host and every client compile against, with a versioned, decode-hardened `Codable` wire format.

## Long Description

`MovieMetadata` (`Changeover/MovieMetadata.swift:5-25`) is a plain `struct` that is
not even `Codable` today, and its only initializer takes a `TMDBMovie`
(`Changeover/MovieMetadata.swift:10-14`), so it cannot be reconstructed on the host
from a decoded payload. `TMDBMovie` (`Changeover/TMDB/TMDBModels.swift:20-37`) is
`Codable` but is a TMDB API response shape, not a wire type — it should not be what
crosses the connection.

The protocol must be a **separate Swift package**, not a folder in the app target,
for one hard reason: Phase 5 ([#0080](0080.md)) builds iOS and iPadOS clients, and
the current app target is macOS-only, unsandboxed, `LSUIElement`, and links AppKit.
A package with no platform-specific dependencies is the only thing all four
destinations can share.

Because the host is **unsandboxed** (`ENABLE_APP_SANDBOX = NO`,
`Changeover.xcodeproj/project.pbxproj:402` and `:431`) and shells out to
`makemkvcon` and `HandBrakeCLI`, the decoder on the host side is a genuine attack
surface. Decode hardening belongs in this ticket, not bolted on later.

## Steps to reproduce

1. Try to send a chosen TMDB result from a hypothetical client to the host.
2. Look for a type that can represent it on the wire.

## Expected behavior

A `ChangeoverProtocol` package exports `RemoteCommand`, `RemoteEvent`, `JobState`,
`RipRequest`, `MovieMetadata`, `DiscInfo`, `DiscTitle` and `DiscStream` as
platform-free `Codable`, `Sendable` value types with a declared wire version, and
both the host app and the remote client depend on it.

## Actual behavior

No package exists. `MovieMetadata` is not `Codable`, has no memberwise
initializer, and is only constructible from a `TMDBMovie`.

## Plan

**Create the package.** Add a local Swift package at `Packages/ChangeoverProtocol`
with `Package.swift` declaring `platforms: [.macOS(.v26), .iOS(.v26)]` to match
`MACOSX_DEPLOYMENT_TARGET = 26.2` (`project.pbxproj:328`, `:386`). Add it to
`Changeover.xcodeproj` as a local package reference and link it to the `Changeover`
target. Note that the app target uses `PBXFileSystemSynchronizedRootGroup`, so a
package under `Packages/` stays outside the synchronized `Changeover/` folder and
will not be swept into the app target by accident.

**Isolation.** The package does *not* inherit the app's
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` (`project.pbxproj:416`, `:445`) — a
package has its own build settings. Wire types must therefore be explicitly
`Sendable` value types with no actor isolation at all; do **not** set MainActor
default isolation on the package, because the codec runs off the main actor inside
`Network` connection handlers. This is the one place in the project where the
"everything is MainActor" rule does not apply by default, and it should be called
out in the package's own README so the convention mismatch is not surprising.

**Types to define.**

- `MovieMetadata` — move the type out of `Changeover/MovieMetadata.swift` into the
  package. Keep `folderName` and `fileName` (`MovieMetadata.swift:17-24`) as the
  single definition of the Plex naming convention so host and client agree on the
  preview string. Add a memberwise `init(title:year:tmdbID:)` and make it
  `Codable`. Keep the `init(from: TMDBMovie)` convenience **in the app/UI layer**,
  not the package — the package must not know about TMDB response shapes. Add a
  `validated()` throwing accessor here or in [#0070](0070.md); see the cross-link.
- `DiscInfo` / `DiscTitle` / `DiscStream` — these are authored in Phase 2
  ([#0020](0020.md)). The `RemoteControl.md` sketch types `DiscTitle.duration` as
  `Duration`; `Duration` is `Codable` but encodes as a two-field container of
  seconds and attoseconds, which is awkward across versions. Prefer a plain
  `durationSeconds: Int` on the wire with a computed `Duration` accessor. Coordinate
  with [#0020](0020.md) so the models are authored in the package from the start
  rather than moved later.
- `JobState` — mirrors the `JobController` state enum from [#0001](0001.md):
  `.idle`, `.discInserted(DiscInfo)`, `.scanning`, `.ripping(progress)`,
  `.encoding(progress)`, `.organizing`, `.done(folderName)`, `.failed(reason)`.
  Add the job ID from [#0040](0040.md) so a queue of jobs can be represented, not
  just one current job — retrofitting IDs into the protocol later is exactly the
  cost `RemoteControl.md` open question 1 warns about.
- `RipRequest` — `metadata`, `titleIndices: [Int]`, `audioLanguages: [String]`,
  `subtitleLanguages: [String]`.
- `RemoteCommand` — `.subscribe`, `.rescanDisc`, `.startRip(RipRequest)`,
  `.cancel(jobID)`, `.eject`, `.ping`.
- `RemoteEvent` — `.state([JobState])`, `.discInfo(DiscInfo)`, `.log(jobID, String)`,
  `.logReplay(jobID, [String])`, `.finished(jobID, folderName: String)`,
  `.rejected(RejectionReason)`, `.pong`.

**Versioning.** Add `public enum WireVersion { public static let current = 1 }` and
carry it in the handshake ([#0069](0069.md)), not in every message. Give
`RemoteCommand` and `RemoteEvent` explicit `CodingKeys` and a `kind` discriminator
string rather than relying on Swift's synthesized enum encoding, whose layout is an
implementation detail that has changed between toolchains. Decoding an unknown
`kind` must produce a typed `.unsupported` case, never a thrown error that tears
down the connection — a newer client must be able to talk to an older host well
enough to report a version mismatch.

**Decode hardening.** The host decoder runs unsandboxed. In the package add:

- A `ProtocolLimits` enum with a maximum frame size (start at 256 KiB — a log
  replay of a few thousand lines fits comfortably), a maximum `titleIndices`
  count, and a maximum string length for `metadata.title`.
- A `decode(_:from:)` entry point that enforces those limits before handing the
  data to `JSONDecoder`, and rejects oversize frames with a typed error.
- No `AnyCodable`, no dictionary-of-`Any`, no nested unbounded recursion.

**Codec.** Expose a `ProtocolCoder` type that wraps the `Coder(_:using: .json)`
message framing from the structured-concurrency `Network` API so the transport
layer ([#0062](0062.md)) never touches `JSONEncoder` directly. Keeping the codec
in the package means the round-trip tests test the real code path. If JSON proves
too fat for log streaming, swapping to a binary coder becomes a one-file change —
but start with JSON; it is debuggable with `nc` and the volumes here are tiny.

**Ordering.** This ticket is first in the phase and blocks [#0062](0062.md),
[#0068](0068.md), [#0069](0069.md), [#0070](0070.md) and [#0071](0071.md). It can
start as soon as [#0001](0001.md) has settled the `JobController` state enum; the
disc models can be stubbed and filled in when [#0020](0020.md) lands.

### Plan refresh (2026-09-15)

**What is stale**

- **"`MovieMetadata` is not `Codable`" is no longer true.**
  - It is `nonisolated struct MovieMetadata: Codable, Hashable, Sendable`
    (`MovieMetadata.swift:16`), with a memberwise
    `init(title:year:tmdbID:selectionDisc:)` and a `selectionDisc: DiscInsertion?`
    that `JobController.start` requires (#0034).
  - The title is path-sanitized by `pathSafe` (`:89`, #0010).
  - `year` and `tmdbID` are **not** sanitized; see [#0070](0070.md).
- **The disc models exist** in `Changeover/DiscInfo.swift` (#0022):
  - `nonisolated` at the type level.
  - `durationSeconds: Int`, so the `Duration` concern is resolved.
  - Lenient decoding of `Role`/`Kind` and of optional fields.
- **The `JobState` in this plan is not what shipped.** Today it is:
  - `JobState`: a struct of `phase`/`progress`/`outcome` that re-validates on
    decode (`Jobs/JobState.swift`).
  - `JobPhase`: `starting/encoding/fallback/organizing/extras/succeeded/failed/cancelled`.
  - `JobSnapshot`: the per-job wire projection (`Jobs/Job.swift:160`).
  - "Scanning" and "disc inserted" are **not** job states. They live in `ScanState`
    (`JobController.swift:13`) and `JobController.insertedDisc`. Neither
    `ScanState` nor `DiscScanner.Result`/`Failure` is `Codable`.
- **`RipRequest` is `{metadata, featureTitleIndex, extraTitleIndices, audioTrackNumbers}`**
  (`RipRequest.swift`, #0027). There are no `titleIndices`, no language strings
  and no subtitle field.
- **`JobID` is a validated string wrapper** (`Jobs/JobID.swift`) whose validity
  check lives in the app target: `WorkingFiles.isJobID` (`WorkingFiles.swift:25-33`).
- **Logs are `LogLine` values** (`Jobs/JobLog.swift:13`), not strings (#0043
  handoff: ship `[LogLine]` with a `JobID`).
- **D1 is one job at a time.** "The full queue" is `JobController.snapshots`
  (history then current, oldest first).
- **`ProtocolCoder` wrapping `Coder(_:using: .json)` is superseded.**
  - The SDK's `Coder<Sending, Receiving, NetworkJSONCoder>` exposes no message-size
    cap (only `WebSocket` has `maximumMessageSize`), so the frame limit can't be
    enforced before decoding.
  - Framing moves to a length-prefixed `FrameCodec` in [#0062](0062.md). This
    package owns `ProtocolCodec`: `Data` ⇄ message, with limits enforced.
- **These references remain valid:** `project.pbxproj` `:328`/`:386` (26.2),
  `:402`/`:431` (no sandbox), `:416`/`:445` (MainActor default). Also relevant are
  `SWIFT_VERSION = 5.0` (`:419`), `SWIFT_APPROACHABLE_CONCURRENCY = YES` (`:415`)
  and `SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY = YES` (`:418`).

**Replacement plan**

*Step A — package skeleton and a mechanical move, as its own commit with no
behaviour change.*

- Create `Packages/ChangeoverProtocol/Package.swift`:
  - `swift-tools-version: 6.2`, `platforms: [.macOS(.v26), .iOS(.v26)]`.
  - Library product `ChangeoverProtocol`.
  - Swift 6 language mode plus `.enableUpcomingFeature("NonisolatedNonsendingByDefault")`
    and `.enableUpcomingFeature("InferIsolatedConformances")`.
  - **No** default isolation.
- Add it as a local package reference and link the product to the **`Changeover`
  app target only**. `packageProductDependencies` is empty today.
- Move into the package, adding `public` and explicit `public init`s (synthesized
  memberwise initializers are internal, and tests call them):
  - `DiscInfo`, `DiscTitle`, `DiscStream`.
  - `RipRequest`.
  - `MovieMetadata`. Its `init(from: TMDBMovie, selectionDisc:)` stays in the app
    as an extension, e.g. `Changeover/TMDB/MovieMetadata+TMDB.swift`.
  - The `DiscInsertion` struct only. `DiscMountDecision` and the classifier stay.
  - `JobID`. Move `jobIDPattern`/`isJobID` in as `JobID.isValidRawValue(_:)`, and
    have `WorkingFiles.isJobID` forward to it so the deletion guards keep one
    definition.
  - `JobPhase`, `JobState`.
  - The wire types in `JobOutcome.swift`: `JobStage`, `FailureReason`,
    `FallbackAttempt`, `JobFailure`, `JobOutcome`.
  - `JobSnapshot`, `LogLine`, `MismatchAcknowledgement`.
- Add `import ChangeoverProtocol` to every app and test file that uses them.
  MemberImportVisibility makes this mandatory.
- **Stop condition:** `./run-remote-tests.sh gordon` passes with the *same* test
  count as before the move, and `RipRequestTests`, `JobStateTests`, `JobIDTests`
  and `MovieMetadataSanitizationTests` are named in the output. Only then continue.
- **Rejected alternative:** separate wire DTOs mapped from host types. That means
  two shapes to keep in sync, and these types were designed to move.

*Step B — additive wire surface, all in `ChangeoverProtocol`.*

- `JobSnapshot.discRemovedDuringJob: Bool`: custom `init(from:)` with
  `decodeIfPresent ?? false`, filled by `Job.snapshot` (#0052 handoff).
  `JobPresentation.make(for:)` may keep its parameter but should default it from
  the snapshot.
- Fix the doc comment on `DiscReliabilityLog.Record.decision`
  (`DiscReliabilityLog.swift:44-45`, app target) to list `"cancelled"` and
  `"discRemoved"`. The handoff noted it, and it's a one-line doc-only change folded
  in here.
- `ScanStatus`: `idle | scanning | scanned(disc: DiscInfo, mainFeatureIndex: Int?,
  warnings: [String]) | failed(message: String, cancelled: Bool)`. It is mapped from
  `ScanState` host-side, so `DiscScanner.Failure` never becomes wire format.
- `HostState`:
  - `wireVersion`
  - `hostID: UUID`
  - `snapshots: [JobSnapshot]`
  - `currentJobID: JobID?`
  - `cancellingJobID: JobID?`
  - `disc: DiscInsertion?`
  - `isEjecting`
  - `discUnavailable`
  - `scan: ScanStatus`
- `SessionInfo`: `{wireVersion, hostID, hostName, capability}`, sent first in the
  handshake ([#0069](0069.md)).
- `CommandEnvelope`: `{requestID: UUID, command: RemoteCommand}`. `RemoteCommand`
  cases:
  - `subscribe(ClientHello{wireVersion, appVersion})`
  - `ping(UInt64)`
  - `rescanDisc`
  - `cancelScan`
  - `start(RipRequest, acknowledgement: MismatchAcknowledgement?)`
  - `cancel(JobID)`
  - `retry(JobID)` (handoff: never a rebuilt request)
  - `eject`
  - `fetchLog(JobID)` (for history rows, via `JobController.retainedLog(forJobID:)`)
  - `unsupported(kind: String)`

  Pairing messages are a separate family owned by [#0066](0066.md).
- `RemoteEvent` cases:
  - `session(SessionInfo)`
  - `hostState(HostState)`
  - `logReplay(LogChunk{source: LogSource, lines: [LogLine], droppedCount: Int,
    latestProgress: LogLine?, isLast: Bool})`
  - `logAppend(source, [LogLine])`
  - `progress(source, LogLine)`
  - `commandResult(requestID, CommandResult)`
  - `pong(UInt64)`
  - `goodbye(GoodbyeReason)`
  - `unsupported(kind)`

  `LogSource` is `.job(JobID) | .controller(epoch: Int)`; see [#0069](0069.md) for
  why an epoch is needed.
- `CommandResult` is `.accepted | .refused(Refusal)`, where `Refusal` is
  `{code: RefusalCode, message: String}`.
  - `message` carries the existing policy strings (`CancelPolicy`, `EjectPolicy`,
    `JobPresentation.retryDecision`, the start refusals).
  - `RefusalCode` decodes leniently, with an unknown code becoming `.other`.
  - Codes: `notPaired`, `revoked`, `notPermitted`,
    `wireVersionMismatch(host: Int)`, `busy`, `noDisc`, `ejecting`,
    `discUnavailable`, `scanNotReady`, `differentDisc`, `invalidRequest(field:)`,
    `runtimeMismatchNeedsConfirmation(titleIndex:movieID:deltaSeconds:)`,
    `unknownJob`, `cannotCancel`, `cannotRetry`, `rateLimited`, `other`.
- Hand-written `kind`-discriminated `Codable` for both enums. An unknown `kind`
  decodes to `.unsupported(kind)` and never throws. `WireVersion.current = 1`.
- `ProtocolCodec.encode(_:)` / `decode(_:from:) throws(ProtocolError)`:
  - Checks `data.count <= ProtocolLimits.maxFrameBytes` before `JSONDecoder`.
  - Pins `JSONEncoder` settings (sorted keys; date strategy fixed and recorded in
    the golden fixtures).
- `ProtocolLimits`:
  - `maxFrameBytes = 256 KiB`
  - `maxLogLinesPerChunk = 200`
  - `maxLogLineBytes = 4 KiB` (longer lines are truncated host-side)
  - `maxTitleCharacters = 200`
  - `maxExtraTitles = 64`
  - `maxAudioTracks = 32`
- Paths cross the wire: `JobOutcome.succeeded(destination: URL)` and
  `DiscInsertion.mountURL`. That's acceptable for control peers. Redaction for
  observe peers is [#0067](0067.md)'s call.

**Concurrency.** Everything here is plain `Sendable` value types with no actor
isolation. Nothing in this target imports Network, Observation, SwiftUI or AppKit.

**Tests** (in `ChangeoverTests`, importing `ChangeoverProtocol`, run with
`./run-remote-tests.sh gordon`; no network):

- `ProtocolCodecTests`:
  - Round-trip every `RemoteCommand`/`RemoteEvent` case.
  - Golden JSON fixtures under `ChangeoverTests/Fixtures/Protocol/`.
  - Unknown `kind` → `.unsupported`.
  - Frame at exactly `maxFrameBytes` accepted; one byte over rejected.
- `JobSnapshotWireTests`:
  - A legacy payload without `discRemovedDuringJob` decodes as `false`.
  - A new payload round-trips.
- `RefusalCode` lenient decode.
- The existing `JobStateTests` (invariant decode) and `JobIDTests` (invalid wire
  string rejected) keep passing after the move. That is part of the proof the move
  was mechanical.

A package-local `Tests/` target is optional and is **not** the verification of
record, because the script doesn't run it. Nothing in this ticket needs a second Mac.

## Notes

**Fully unit-testable, no hardware, no second machine.** This is the single most
testable ticket in Phase 4 and the tests are cheap:

- Round-trip every `RemoteCommand` and `RemoteEvent` case through
  `ProtocolCoder` and assert equality.
- Assert that a payload with an unknown `kind` decodes to `.unsupported` rather
  than throwing.
- Assert that a frame one byte over `ProtocolLimits.maxFrameSize` is rejected,
  and one byte under is accepted.
- Assert `MovieMetadata.folderName` still produces `Blade Runner (1982) {tmdb-78}`
  and `fileName` produces `Blade Runner (1982).mp4`, matching the table in
  `Plan.md` — this is a behavioural regression guard on moving the type.
- Freeze a golden JSON fixture per message type in the test bundle so a future
  refactor that silently changes the wire shape fails loudly.

Add these to `ChangeoverTests/` (or a package test target, which is better — it
runs without building the app). Whichever target they land in, the run must be
observed passing, not merely compiled.
