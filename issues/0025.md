# 0025 — Nothing decides which title is the main feature

| | |
|---|---|
| **Status** | open |
| **Module** | DiscSelection |
| **Platform** | macOS |
| **First seen** | 2026-09-11 |

## Description

A scanned disc yields a flat list of titles with no opinion about which one is the
movie. Without a default, the Phase 2 demo is "pick one of fourteen rows" instead of
"the right one is already selected". The heuristic that `mac_plex_dvd_workflow.md`
§3.3 describes for a human — take the largest title, ignore the short ones — needs
to be a function.

## Long Description

The current app has a heuristic, just a much worse one and in the wrong place:
`largestMKV(in:)` (`Changeover/RipController.swift:66-77`) picks the biggest file in
the working directory *after* ripping everything. Moving the decision before the rip
is what converts the guess into a choice — and it is measured in duration and
chapter count, not in bytes on disk that a previous disc may have left behind.

Scoping this as its own ticket is worth it because it is pure, cheap and entirely
testable, while the UI ([#0026](0026.md)) and the rip change ([#0028](0028.md))
around it are not. It also has genuinely tricky cases that deserve to be written
down rather than discovered:

- **Playlist / seamless-branching discs** present several titles with near-identical
  durations, because the same feature is exposed through multiple playlists. Picking
  "the longest" between two titles that differ by three seconds is a coin flip that
  lands differently on re-scan.
- **Alternate angles** produce titles that are as long as the feature.
  `mac_plex_dvd_workflow.md` §3.3 explicitly lists them as something to uncheck.
- **Episodic discs** — a TV disc or a double feature — have several legitimate long
  titles. Out of scope for Phase 2 (`Roadmap.md` line 307 defers TV support), but
  the heuristic should not confidently pick one and hide the rest.

## Expected behavior

Given a parsed `DiscInfo`, exactly one title is marked `.mainFeature` — the longest
— titles below a configurable threshold are marked `.ignore`, and everything else is
`.extra`. The result is deterministic: re-running on the same input gives the same
answer.

## Actual behavior

No such function exists. The closest thing is `largestMKV(in:)`
(`Changeover/RipController.swift:66-77`), which compares file sizes in the shared
working directory after a full-disc rip and can select a leftover `.mkv` from a
previous disc — the defect `Roadmap.md` lines 35–38 records.

## Notes

Pure function, no disc, no `Process`, no UI. This is the easiest ticket in the phase
to verify properly, so it should have the most thorough tests: build `DiscInfo`
values in-test (not only from fixtures) and assert the role assignment for a plain
single-feature disc, a disc with bonus features, a disc with two titles three
seconds apart, a disc where every title is below threshold, a disc with exactly one
title, and an empty disc.

Also assert the tie-break is stable by shuffling the input title array and checking
the same index wins.

## Plan

### Files

New: `Changeover/DiscTitleHeuristic.swift`.
New: `ChangeoverTests/DiscTitleHeuristicTests.swift`.
Changed: `Changeover/AppSettings.swift` — two threshold settings.

### Shape

```swift
nonisolated enum DiscTitleHeuristic {
    struct Thresholds {
        var ignoreBelowSeconds: Int      // default 300
        var nearDuplicateSeconds: Int    // default 5
    }

    /// Returns a copy of `disc` with `suggestedRole` assigned on every title.
    static func applyingSuggestedRoles(
        to disc: DiscInfo,
        thresholds: Thresholds = .init()
    ) -> DiscInfo
}
```

`nonisolated` because [#0024](0024.md) applies this immediately after parsing,
inside a `nonisolated static` scan — under
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`
(`Changeover.xcodeproj/project.pbxproj:416,445`) the default would be `@MainActor`
and unreachable from there.

Returning a new `DiscInfo` rather than mutating in place keeps this a pure function
and makes the tests trivial. `DiscTitle.suggestedRole` is a `var`
([#0022](0022.md)), so the copy is cheap and local.

### Algorithm

1. Drop titles with `durationSeconds < ignoreBelowSeconds` into `.ignore`. The
   300-second default comes from `RemoteControl.md` line 263 ("everything under ~5
   minutes ignored"). Anything at or above the threshold is a candidate.
2. If there are no candidates, mark every title `.extra` and return — do **not**
   promote a 40-second title to `.mainFeature` just because it is the longest thing
   present. A disc where nothing clears the bar is a disc the user has to look at,
   and [#0026](0026.md) should say so rather than preselect a trailer.
3. Among candidates, the maximum `durationSeconds` wins. Resolve ties — and
   near-ties within `nearDuplicateSeconds` — deterministically, in this order:
   greater `chapterCount`, then greater `sizeBytes`, then **lowest `index`**. The
   near-tie window is what handles playlist discs; without it, two titles three
   seconds apart make the selection depend on array ordering.
4. All remaining candidates become `.extra`.

Keep the comparison in seconds and integers throughout. Do not compare `Duration`
values or convert through `Double` — the whole function should be exactly
reproducible.

### Settings

Add to `Changeover/AppSettings.swift` alongside the existing stored properties
(`:13-16`), with `Keys` entries (`:58-63`), loads in `init()` (`:38-43`) and writes
in `persist()` (`:48-54`):

```swift
var ignoreTitlesBelowSeconds: Int = 300
```

`AppSettings` is `@Observable` (`:8-9`) and owned by `AppDelegate` (`:8` of
`AppDelegate.swift`), injected with `.environment(settings)`
(`AppDelegate.swift:43,87`) — so the threshold becomes editable in
`SettingsView` later with no plumbing. Note the existing `init()` guards every load
with `!v.isEmpty`; an `Int` needs a different guard, since `UserDefaults.integer`
returns 0 for a missing key and 0 would silently disable the threshold. Use
`object(forKey:) as? Int` and keep the default when absent.

Keep `nearDuplicateSeconds` as a code constant, not a setting. It is a correctness
detail, not a preference, and exposing it invites someone to set it to zero.

### Explicitly out of scope

Do not try to identify *which* extras are alternate angles or which long titles are
episodes. Attribute 15 (`AngleInfo`) and attribute 25 (`SegmentsCount`) from
[#0021](0021.md) are suggestive and worth surfacing in the UI
([#0026](0026.md)) as columns, but branching the default on them without real discs
to test against is how a heuristic becomes superstition. Duration plus chapter count
is enough for the exit criterion, and the user can see the rest and override.
