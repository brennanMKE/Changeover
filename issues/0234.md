## Description

On REPO_MEN an agent selected the film and then could not import it. The
Unrated cut runs 119m against TMDB's 111m, so the Start gate returned
`runtimeMismatchUnconfirmed`, and there was no flag to offer. The window clears
that refusal with a "Rip anyway" button; the CLI had nothing, and the sequence
dead-ended with the disc selected and waiting.

From the user: *"The CLI is supposed to be able to get the app to import no
matter what."*

## Root cause

Every confirm-button refusal is cleared by an acknowledgement recorded on
`JobController` or `RipFlowController` — `acknowledgeMismatch`,
`acknowledgeReplace`. All of them were reachable only from a button. The CLI's
`import` read the gate and reported whatever it said.

## Fix

`import --confirm`, as **one** flag covering every refusal of that kind rather
than one flag per gate. A flag per gate means the next confirm button added to
the window silently blocks the CLI again until somebody notices; the question
asked is "is this the kind of refusal a person clears with a button", and an
agent that asked to import has already answered it.

`AgentConfirmation` is the pure seam: `clearable` is the set, `canConfirm` the
question, and `acknowledgementDescription` the sentence echoed back. The
acknowledgement is applied through the very methods the buttons call, which are
no-ops unless the thing being acknowledged is really there — that guard is why
an agent cannot confirm its way into a state the window would not have offered
to confirm either.

What it deliberately does not cover: environment facts (no disc, scan running,
HandBrake missing) and incomplete selections (no movie, no title, no audio
track). Confirming those would turn a clear refusal into a silent no-op, so
they still refuse — and say that `--confirm` did not apply, so an agent does not
simply pass it again.

Whatever was acknowledged is echoed in `detail`. The window asks because the app
believes something may be wrong, and an agent overriding that belief should
leave a record of which one.

## Notes

`AgentConfirmationTests` pins the non-clearable cases one by one, so a new
confirm-button refusal added to `StartDecision` has to be decided either way
rather than silently left out — the failure mode guarded against is a gate being
added and the CLI quietly losing the ability to import again.
