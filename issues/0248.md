| | |
|---|---|

## Description

On a WILLIS collection the app named **Sunset Boulevard** (1950) for a title
that is **Sunset** (1988), and was one auto-start away from filing it into the
wrong Plex folder.

| | runtime | error against 1:46:56 |
|---|---|---|
| Sunset (1988), tmdb-38560 | 107 m | **0.07 min** |
| Sunset Boulevard (1950), tmdb-599 | 110 m | 3.1 min |

## Root cause

`RipFlowController.candidate(for:)` took `.first` of the TMDB search results —
**one** candidate per term. That quietly changed the matcher's question from
*"which of these films is this title"* to *"is TMDB's top hit close enough"*.
Sunset (1988) was never offered to the matcher at all.

The flat three-minute window used to hide it by rejecting Sunset Boulevard too.
#0246 widened the window so the matcher agrees with the Start gate, and
uncovered the fault underneath. **The widening did not cause this; it revealed
it.** Reverting it would re-hide this and re-break Alpha Dog.

## Fix

`candidates(for:)` returns up to `maximumCandidatesPerTerm` (4) films per term,
and the matcher chooses:

- `bestSplit` now walks every combination of one candidate per term, keeping the
  assignment with the lowest total error. Bounded: 4 candidates to the power of
  the feature count, times the permutations `assign` already walked — four
  features is 256 combinations of 24 orderings, which is arithmetic.
- `bestFit(for:among:)` does the same for the single-title interrogate path,
  which had the identical `.first` fault.

Four is enough for the right film to be present — Sunset (1988) is the second
hit for "Sunset" — without turning one disc into a hundred detail lookups.

## Pinned

The test the agent asked for, in its words: **"SUNSET" on a 106:56 title
resolves to 38560, never 599** — in either TMDB result order, through `bestFit`
and through `bestSplit`, and as part of the whole three-film disc solved
one-to-one. All three fail against the old first-hit behaviour.

Also pinned: a term whose candidates all miss yields **nothing**, rather than the
least-bad of several wrong answers.

## Still open, from the same report

- **(C) No cast or label signal.** Every film on all three WILLIS discs stars
  Bruce Willis, and the volume label is his surname. The app treats the label
  only as something to split into titles and then drops it. Cast agreement
  would have rejected Sunset Boulevard outright, and is the strongest available
  signal on a collection disc.
- **(D) Titles across more than two lines.** `The- | Whole | Nine Yards` needs a
  three-line join plus hyphen continuation; #0246 joins adjacent pairs only.
- **(E) `interrogate` and `feature match` disagreed** about the same disc in the
  same second — "unconfirmed by the disc's runtimes" was logged for all three
  names. One of those paths is not using the corrected rule. Worth finding
  before building anything else, because it is the same class of fault as this
  one.
