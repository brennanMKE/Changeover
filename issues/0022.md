## Root cause

The app's only model was `MovieMetadata` — the movie, not the media. Every
Phase 2 ticket (parser, scanner, role heuristic, title picker, language
selection) needs `DiscInfo`/`DiscTitle`/`DiscStream` to exist first, and the
shape had to be settled before any of them could be built because it becomes
Phase 4's wire format.

## Fix

`5007d37` — one new file, `Changeover/DiscInfo.swift`, holding all four types
so the Phase 4 package move is a single drag:

- `nonisolated` at the **type level** (SE-0449), confirmed compiling under
  this target's `SWIFT_VERSION = 5.0` + `SWIFT_APPROACHABLE_CONCURRENCY` —
  no member-by-member annotations needed, so the types keep their meaning
  when the `SWIFT_DEFAULT_ACTOR_ISOLATION` setting is absent in the Phase 4
  package.
- `index` stored (not `id`), with `id` derived, keeping `Identifiable` for
  SwiftUI without colliding with the TMDB-id meaning of `id`.
- `sizeBytes: Int64` explicit; `var` throughout (#0025 mutates
  `suggestedRole`); no selection state; no UI imports.
- `Role`/`Kind` decode **leniently** (custom `init(from:)`, unknown raw →
  `.extra`/`.unknown`), and `DiscTitle`/`DiscStream` decode leniently too
  (`decodeIfPresent` + defaults), so payloads from older hosts and hosts from
  older clients both survive — additive optional fields only, forever.
- `flags` stored raw with `isForced`/`isCommentary` computed exactly as the
  Plan specifies (`isCommentary` = "some flag other than forced", so an
  unrecognized flag like 8 surfaces rather than masquerading as ordinary
  audio).
- `languageCode`/`languageName` genuinely optional; `nil` = untagged.

**Additions beyond the Plan's sketch, both required by the Re-triage:**
`DiscTitle.frameRate: Double?` and `.interlaceDetected: Bool?` — the two
fields #0016's deinterlace decision consumes, `nil` meaning "scan did not
report" (matching `decide`'s treatment of missing data); and
`DiscStream.variant: String?` — the variant axis distinct from language
(HandBrake's "English (Wide Screen)" parenthetical, #0033's dedup), never
folded into the language strings. Both optional, so older payloads decode.

**Deviation:** none of substance. The Plan's `isTextSubtitle` prefix check,
the `sourceFileName`-always-nil-on-DVD rule, and the keep-selection-out rule
are all as written.

## Gotchas

- `Duration.seconds(_)` takes a `Double` — `.seconds(Double(durationSeconds))`,
  not `.seconds(durationSeconds)`.
- The `flags` table's `4097` row is a trap for test authors: forced wins, so
  `isCommentary` is false for a stream that is both forced and
  commentary-flagged. The Plan's formula (`flags != 0 && !isForced`) is the
  definition; don't "fix" the code to match an intuition that commentary
  should also be true there.
- Type-level `nonisolated` works on this toolchain (Xcode 26.6 / Swift 6.3.3
  in Swift-5 language mode) — no member annotations needed, which is what
  keeps the Phase 4 package move a no-op.

## Description

Changeover has no type representing a disc, a title on that disc, or a stream inside
that title. `MovieMetadata` (`Changeover/MovieMetadata.swift:5-26`) is the only model
in the app and it describes the movie, not the media. Every other Phase 2 ticket
needs `DiscInfo` / `DiscTitle` / `DiscStream` to exist first.

## Long Description

These three types are the most consequential design decision in Phase 2, because
they do not stay here. `RemoteControl.md` lines 297–300 puts them in the
`ChangeoverProtocol` Swift package in Phase 4, shared verbatim between the host and
the macOS, iOS and iPadOS clients, and serialized across a network connection. Their
JSON representation becomes wire format. Getting the shape right now costs nothing;
changing it after Phase 4 ships means a protocol version.

Two project-specific constraints bite here and neither is obvious:

**MainActor default isolation does not travel.** This target sets
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`
(`Changeover.xcodeproj/project.pbxproj:416,445`), so a bare `struct DiscTitle` is
implicitly `@MainActor`. The parser ([#0023](0023.md)) and the scanner
([#0024](0024.md)) run `nonisolated` for the same reason `RipController` does
(`Changeover/RipController.swift:9`, `:66`) — they must not block the main actor
during a scan that takes tens of seconds. A `@MainActor` model type cannot be
constructed from there. `MovieMetadata` already hits this and works around it by
annotating individual members (`Changeover/MovieMetadata.swift:17,22`). And when
these types move into a Swift package in Phase 4, that package will not have the
build setting at all, so a model that depends on it will change meaning on the move.

**The fixtures added requirements this ticket was filed before.** `DiscSelection.md`
and [#0021](0021.md) turned three of these fields from guesses into constraints:

- **`flags: Int` on `DiscStream` is now required**, carrying attribute 22 verbatim.
  It is a bitfield with four observed values: `0` (723 occurrences), `1` (25), `2`
  (23) and `4096` (10). `4096` means forced subtitle; `1` and `2` mean commentary.
  Store the raw integer and derive the booleans — a `Bool` per meaning would need a
  new wire field and a protocol version every time another flag turns out to matter,
  and at least one more (visually-impaired audio) is known to exist upstream.
- **`languageCode: String?` must genuinely be optional, and `nil` must mean
  "untagged", not "English".** Every stream in
  `ChangeoverTests/Fixtures/makemkvcon/hornets-nest-min0.txt` lacks attribute 3 —
  the whole disc is untagged. Decoding that to `""` or defaulting to `"eng"` is what
  produces a silent MP4 downstream ([#0027](0027.md)). The same applies to
  `languageName` (attribute 4), which is absent on the same disc.
- **`sourceFileName` will always be `nil` on DVDs.** Attribute 16 does not appear on
  any title in any fixture. Keep the field for Blu-ray later, but do not design
  anything around it and do not let a test assert it is populated.

**`Swift.Duration` is a poor wire type.** `RemoteControl.md` line 250 sketches
`let duration: Duration`. `Duration`'s encoded form is a pair of internal integer
components, which is opaque to anything that is not Swift and awkward to read in a
log or a fixture. Since Phase 4 sends this over JSON, store integer seconds and
expose `Duration` as a computed accessor.

## Expected behavior

`DiscInfo`, `DiscTitle`, `DiscStream` and their supporting enums exist as plain
value types that a `nonisolated` parser can build, that round-trip through JSON
unchanged, and that can be moved into a Swift package in Phase 4 by dragging the
file with no edits.

## Actual behavior

No such types exist. The app's only model is `MovieMetadata`
(`Changeover/MovieMetadata.swift`), which holds a title, a year and a TMDB id.

## Plan

### Files

One new file, `Changeover/DiscInfo.swift`. The target uses
`PBXFileSystemSynchronizedRootGroup`, so a new file under `Changeover/` is compiled
automatically with no `project.pbxproj` edit. Keep all four types in the single file
so the Phase 4 move is one drag.

### Shape

```swift
import Foundation

nonisolated struct DiscInfo: Codable, Hashable, Sendable {
    var volumeName: String
    var driveName: String
    var titles: [DiscTitle]
}

nonisolated struct DiscTitle: Codable, Hashable, Sendable, Identifiable {
    /// Index passed to `makemkvcon mkv disc:0 <index>` — the leading field of TINFO.
    var index: Int
    var id: Int { index }

    var durationSeconds: Int
    var chapterCount: Int
    var sizeBytes: Int64
    /// From attribute 27 (OutputFileName), e.g. "B1_t00.mkv" or
    /// "Girl in the Spider's Web, The-B1_t00.mkv". NOT unique across scans of the
    /// same disc at different --minlength values — see #0028. A hint, not an id.
    var outputFileName: String
    var sourceFileName: String?
    var segmentCount: Int?
    var streams: [DiscStream]
    var suggestedRole: Role

    var duration: Duration { .seconds(durationSeconds) }
}

nonisolated struct DiscStream: Codable, Hashable, Sendable, Identifiable {
    var index: Int
    var id: Int { index }

    var kind: Kind                 // .video | .audio | .subtitle | .unknown
    var codecId: String            // "V_MPEG2", "A_AC3", "S_VOBSUB", "S_CC608/DVD"
    var codecShort: String?
    var languageCode: String?      // ISO 639-2; nil means UNTAGGED, not English
    var languageName: String?      // localized display string — never branch on this
    var displayName: String?       // attribute 30, for dedup and for the UI
    var bitrate: String?           // attribute 13, e.g. "448 Kb/s" — for dedup
    var channelCount: Int?
    var isDefault: Bool

    /// Attribute 22, stored raw. Known bits: 1 and 2 = commentary, 4096 = forced.
    var flags: Int

    var isForced: Bool { flags & 4096 != 0 }
    var isCommentary: Bool { flags != 0 && !isForced }
    /// MakeMKV converts this to text; MP4 can carry it. See #0029.
    var isTextSubtitle: Bool { codecId.hasPrefix("S_CC608") }
}
```

Plus `DiscTitle.Role` (`mainFeature`, `extra`, `ignore`) and `DiscStream.Kind`
(`video`, `audio`, `subtitle`, `unknown`), both `String`-backed `Codable` enums
nested inside their owners.

`isForced` becomes a **computed** property rather than a stored one, which is the
point of storing `flags`: it keeps the wire format stable while letting the
interpretation change. `isCommentary` is deliberately written as "some flag other
than forced" rather than `flags == 1 || flags == 2`, so an unknown flag is surfaced
rather than silently treated as ordinary audio — and it is honest about being
incomplete, since Super Troopers 2's commentary carries `flags == 0` and no
metadata identifies it ([#0027](0027.md)).

`displayName` and `bitrate` are new and are not cosmetic: [#0027](0027.md)
deduplicates tracks on `(languageCode, codecId, bitrate, displayName)`, and without
them on the model that has to be done in the parser or not at all.

### Decisions worth being deliberate about

- **`nonisolated` at the type level.** SE-0449 permits `nonisolated` on a type
  declaration; the project builds with `SWIFT_VERSION = 5.0` and
  `SWIFT_APPROACHABLE_CONCURRENCY = YES`
  (`Changeover.xcodeproj/project.pbxproj:415,419`), so confirm it compiles here. If
  it does not, fall back to annotating members the way
  `Changeover/MovieMetadata.swift:17,22` already does — but prefer the type-level
  form, because it is what makes the Phase 4 package move a no-op rather than a
  semantic change.
- **`index`, not `id`, as the stored name.** `RemoteControl.md` line 249 names it
  `id`, but the app already has an `id` that means something different —
  `TMDBMovie.id` (`Changeover/TMDB/TMDBModels.swift:21`) and the `{tmdb-ID}` tag in
  `MovieMetadata.folderName`. Storing `index` and deriving `id` keeps `Identifiable`
  working for SwiftUI `List` (used at `Changeover/MetadataEntryView.swift:63`)
  without inviting a mix-up in [#0028](0028.md), where the wrong integer means
  ripping the wrong title.
- **`sizeBytes: Int64`, not `Int`.** Explicit width, because this crosses a wire in
  Phase 4 and may reach a 32-bit client eventually.
- **`var`, not `let`.** [#0025](0025.md) mutates `suggestedRole` and
  [#0026](0026.md) needs a mutable selection. `RemoteControl.md` line 258 already
  makes `suggestedRole` a `var`; make the rest consistent rather than mixing.
- **Keep selection *out* of these types.** What the user picked is job state, not
  disc state. It belongs in the `RipRequest` shape defined by [#0027](0027.md)
  (`RemoteControl.md` lines 324–329), so that `DiscInfo` stays a faithful
  description of the physical disc and can be re-sent to a reconnecting client in
  Phase 4 without carrying another client's choices with it.
- **No `import AppKit`, no `import SwiftUI`, no `import Observation`.** These are
  value types; the `@Observable` object that holds them is `JobController` from
  [#0001](0001.md). A single UI import here is what would stop the Phase 4 move.
- **Unknown `Role` on decode.** Decide and write down: either a custom
  `init(from:)` that falls back to `.extra` for an unrecognized raw value, or strict
  decoding that fails. Prefer the lenient fallback — a Phase 5 iPhone client running
  an older build should not fail to decode a whole disc because the host added a
  role.

## Re-triage

**2026-09-11 — needs rewriting against HandBrake's scan JSON.** Per
`MakeMKVReplacement-Path.md` §4: *"Model shape should follow from HandBrake's
fields."* The ticket stays `open` and stays necessary — Phase 2 still needs
`DiscInfo` / `DiscTitle` / `DiscStream`, and they still end up in the
`ChangeoverProtocol` package in Phase 4. What changes is where the fields come
from.

The source of truth is now `HandBrakeCLI --scan --title 0 --min-duration 1 --json`.
Verified available on that output (`MakeMKVReplacement-Results.md` §3):

| Model need | HandBrake field |
|---|---|
| title list | `TitleList`, with `MainFeature` naming the index |
| duration | `Duration` |
| chapters | `ChapterList` |
| angles | `AngleCount` |
| geometry | `Geometry` |
| frame rate | `FrameRate` |
| interlace | `InterlaceDetected` |
| audio / subtitle streams | per-title stream lists with language, codec, layout |
| commentary flag | `Attributes.Commentary` — correctly flagged on Fargo's third AC3 track |

Three constraints on how that mapping is done, all from `-Path.md` §3 step 1:

- **Map HandBrake's fields onto the model; do not reshape the model around
  HandBrake's JSON.** A backend swap should stay cheap — that is the entire lesson
  of this exercise, and it is the same argument this ticket already makes about
  Phase 4's wire format.
- **`InterlaceDetected` and `FrameRate` must be on `DiscTitle`.** [#0016](0016.md)
  drives the deinterlace decision from exactly those two fields, and it cannot
  exist until they are carried.
- **`DiscStream` needs a variant axis distinct from language.** HandBrake reports
  `lang=English (Wide Screen)` and `lang=English (Letterbox)` as separate streams
  with distinct ids — see [#0033](0033.md). The parenthetical must not be folded
  into the language string, and the raw stream id (`0x20bd`) must survive, because
  it is what the encode selects by.

Everything in this ticket about **MainActor default isolation not travelling**
(`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, the models being constructed from
`nonisolated` code, and the setting not existing once these types move into a Swift
package) is unaffected and still governs. So is the lenient-decoding argument for
unknown enum cases.
