# 0239 — A disc mounting mid-job produces no event

## Description

During `job-20261008-123159-0D74` the disc went from unmounted to mounted — it
started on `/dev/rdisk4` with the screen locked (#0152's path) and the job's end
snapshot shows `isMounted=true`,
`mountPath=/Volumes/LADY_IN_THE_WATER`. No event was emitted for that
transition, so a watcher could only discover it by comparing two snapshots it
happened to have kept.

## Why it matters

Beyond this disc: the event feed is produced by diffing snapshots
(`BridgeStatusDiff.drafts(from:to:)`), so **a field that changes without
producing an event means the diff does not look at that field**. That is a
general gap, not a mount-specific one — anything added to `BridgeStatus` is
watchable only once the diff is taught about it, and the architecture note in
`CLAUDE.md` ("a field added to the snapshot becomes watchable for free") is
therefore not quite true.

Worth auditing which snapshot fields the diff covers rather than only adding
mount.

## Not the cause of the Lady in the Water failure

Recorded so nobody re-derives it. The retry (`job-20261008-144208-CDE6`) ran
with the disc mounted for its whole duration and failed at the same 67 %, so the
mid-run mount did not cause that failure. A fixed damaged area did.

That does not make the transition harmless: #0152 holds a disc unmounted
deliberately, and something mounting it mid-job is worth understanding on its
own terms. It is a separate question from why this disc fails.
