# 0035 — The MakeMKV fallback ignores a hand-picked title and rips the longest one instead

| | |
|---|---|
| **Status** | open |

| **Platform** | macOS |
| **First seen** | 2026-09-15 |

## Description

Since #0026 the user can choose which title to encode, and `JobController.start` passes HandBrake `.index(n)`. When the direct HandBrake encode fails and the #0015 MakeMKV fallback runs, `MakeMKVRipper.rip()` takes no title argument and still picks the longest title, then encodes the one-title `.mkv` with `.index(1)`. A title picked by hand (a Play All override, an unidentified disc, or "Not this one?") is silently replaced by the longest title, which gets filed under the chosen movie's name. On a TV-season disc, the longest title is exactly the Play All title that #0025 refuses to call a movie.

Found during the #0026 review, which added a comment at the call site. Nobody has reproduced it with a disc, because the fallback only runs after a HandBrake failure.

## Expected behavior

The fallback rips the title the user chose, or it refuses to run and says why. It never substitutes a different title.

## Plan

- Pass the chosen title into the fallback as a duration (seconds from the HandBrake scan), not an index. HandBrake and MakeMKV number titles differently and can't be mapped index to index.
- The fallback picks the makemkvcon title whose duration matches within a small tolerance (for example ±2 s, or 1%), using the robot-mode parser/model already present. Put that match in a pure, unit-tested function. If there is no unique match, refuse the fallback with a clear `JobFailure`, never guess.
- Keep today's behaviour when the job used the heuristic's `.single` answer and durations agree.
- Unit-test the matcher and the refusal. A real fallback run needs a disc and an induced HandBrake failure, so that stays manually unverified.
