# 0062 — Transport must be abstracted behind listener and browser providers, not written against Bonjour

| | |
|---|---|
| **Status** | open |
| **Phase** | 4 — Remote control from a Mac |
| **Module** | Transport |
| **Platform** | All |
| **First seen** | 2026-09-11 |

## Description

If `RemoteServer` and `RemoteClient` are written directly against Bonjour, adding Wi-Fi Aware later is a rewrite instead of a dependency swap. The transport layer must take its discovery mechanism as an injected `Network.ListenerProvider` / `Network.BrowserProvider` dependency, because `WAPublisherListener` and `WASubscriberBrowser` conform to those exact protocols.

## Long Description

`WiFiAware.framework` is a **public** framework that already ships on macOS — it is
present at `/System/Library/Frameworks/WiFiAware.framework` on macOS 26.4.1 and in
`MacOSX26.5.sdk` with a complete Swift module. Every public symbol in it carries
`@available(macOS, unavailable)` — 28 such annotations — and the gate is enforced by
the compiler, not cosmetic:

```
$ xcrun swiftc -target arm64-apple-macos26.0 -typecheck wa.swift
error: 'WACapabilities' is unavailable in macOS
```

Apple DTS confirmed the macOS gap and pointed at enhancement request FB17988268.
Because the framework is *shipped rather than missing*, enabling it on macOS is an
availability-annotation change on Apple's side, not new framework work — so it is
reasonably likely to arrive, and the Changeover host is always a Mac, so both
relevant topologies (MacBook ↔ mini, iPhone ↔ mini) unblock at once when it does.

The migration shape is already visible in the SDK: `WAPublisherListener` conforms to
`Network.ListenerProvider`, `WASubscriberBrowser` to `Network.BrowserProvider`, and
`WAEndpoint` to `Network.Connectable` — the *same* protocols the Bonjour listener and
browser use. Injecting the provider now is a small amount of indirection that buys
the entire migration.

This is cheap insurance, not speculative architecture: the indirection is one
protocol, one Bonjour conformance, and one `init` parameter.

## Steps to reproduce

1. Imagine Apple lifts the macOS availability gate on `WiFiAware` in a future release.
2. Try to add Wi-Fi Aware discovery to a `RemoteServer` that calls the Bonjour
   listener API directly and a `RemoteClient` that constructs
   `NetworkBrowser(for: .bonjour(type: "_changeover._tcp"))` inline.

## Expected behavior

Adding Wi-Fi Aware is a new type conforming to the project's existing transport
protocol plus a pairing UI. No change to `RemoteServer`, `RemoteClient`, the
protocol package, or any view.

## Actual behavior

There is no transport layer yet, and the sketch in `RemoteControl.md` constructs
the Bonjour listener and browser inline at the call site, which would harden the
concrete mechanism into both ends.

## Plan

**Where it lives.** A `Transport` target inside the `ChangeoverProtocol` package
(or a sibling `ChangeoverTransport` target in the same package). It must not live
in the app target — [#0080](0080.md) needs it on iOS too.

**The abstraction.** Define two thin protocols the project owns, rather than
exposing Apple's `Network.ListenerProvider` / `BrowserProvider` directly to callers:

```swift
public protocol TransportAdvertiser: Sendable {
    func run(_ handler: @Sendable @escaping (TransportConnection) async -> Void) async throws
}

public protocol TransportDiscoverer: Sendable {
    func endpoints() -> AsyncStream<[DiscoveredPeer]>
    func connect(to peer: DiscoveredPeer) async throws -> TransportConnection
}

public protocol TransportConnection: Sendable {
    var commands: AsyncThrowingStream<RemoteCommand, Error> { get }
    var events: AsyncThrowingStream<RemoteEvent, Error> { get }
    func send(_ event: RemoteEvent) async throws
    func send(_ command: RemoteCommand) async throws
    func close() async
}
```

Owning the protocol rather than re-exporting Apple's matters for two reasons:
`ListenerProvider` / `BrowserProvider` are Apple's conformance points for the
*provider*, not a good call-site API, and owning our own protocol lets the test
suite supply an in-memory pair with no networking at all.

**The Bonjour conformance.** `BonjourAdvertiser` and `BonjourDiscoverer` wrap the
structured-concurrency `Network` API (`NetworkListener`, `NetworkBrowser`,
`NetworkConnection`) and the `ProtocolCoder` from [#0061](0061.md). The service type
is `_changeover._tcp`. **The exact listener-side advertisement call is unverified —
see [#0063](0063.md); do not write it speculatively.** Structure `BonjourAdvertiser`
so the advertisement construction is a single private function, so whichever of the
two candidate APIs [#0063](0063.md) confirms, only that function changes.

**The Wi-Fi Aware placeholder.** Do **not** add a `WiFiAwareAdvertiser` stub. Every
symbol it would reference fails to compile on macOS today, so the file would have to
be excluded from the target, which defeats the point. Instead, add a short
`Docs/WiFiAware.md` in the package recording the conformance mapping
(`WAPublisherListener` → `TransportAdvertiser`, `WASubscriberBrowser` →
`TransportDiscoverer`, `WAEndpoint` → the connection), the hardware floor (iPhone 12
and later; iPad 10th gen, iPad Air 4th gen, iPad Pro 11" 3rd gen, iPad Pro 12.9"
5th gen, iPad mini 6th gen and later), the `com.apple.developer.wifi-aware`
entitlement, and ER FB17988268. That document is the actual deliverable of the
Wi-Fi Aware preparation; the code deliverable is only the injection point.

**Injection.** `RemoteServer` ([#0068](0068.md)) takes a `TransportAdvertiser` in its
initializer; `RemoteClient` ([#0071](0071.md)) takes a `TransportDiscoverer`. Neither
imports `Network`. Provide default arguments that construct the Bonjour pair so call
sites stay short.

**Isolation.** These types run off the main actor — connection handlers are invoked
from the `Network` framework's own executors. Since the package does not inherit the
app's `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` (`project.pbxproj:416`, `:445`),
mark everything `Sendable` explicitly and keep mutable connection state inside an
`actor`. This is one of the few places in this project where `actor` is the right
answer rather than the anti-pattern `Plan.md` warns about, because the state genuinely
must be reachable from a non-main executor. Say so in a comment, or someone applying
the convention table mechanically will "fix" it back to a struct.

**Ordering.** Depends on [#0061](0061.md) for the message types. Should land before
[#0068](0068.md) and [#0071](0071.md), but [#0063](0063.md) can run in parallel — the
spike's answer only affects one private function here.

### Plan refresh (2026-09-15)

**What is stale**

- **The listener API is no longer unverified.** `MacOSX26.5.sdk`
  (`Network.swiftmodule/arm64e-apple-macos.swiftinterface`) has:
  - `NetworkListener.init(for provider: (any ListenerProvider)? = nil, using:)`.
  - `BonjourListenerProvider(name:type:domain:txtRecord:)` / `.bonjour(...)`.
  - `onServiceRegistrationUpdate`, `newConnectionLimit`.
  - A browser-side `.bonjour(_:domain:includeTxtRecord:)`.
  - `NetworkConnection(to: any Connectable, using:)`.

  The listener takes the provider protocol as an existential, so a Wi-Fi Aware
  swap really is "pass a different provider". Only runtime proof remains, which is
  [#0063](0063.md)'s spike S1. There is no legacy `NWListener` bridge.
- **One `TransportConnection` carrying both `commands` and `events` is replaced**
  by a typed channel per direction. A server channel that exposes a `commands`
  stream it never receives is a trap.
- **Framing is not `Coder`.** The SDK's `Coder` has no size cap. The real transport
  frames bytes itself over the `TLS` stream using `receive(exactly:)`, which exists
  on `NetworkConnection` in the same interface.
- **The TLS options block now follows [#0064](0064.md)'s recommendation:** mutual
  TLS 1.3 with pinned self-signed identities. The authenticated peer's identity is
  a property of the channel.

**Replacement plan**

*Part A — pure code, implementable now, in target `ChangeoverTransport` (depends on
`ChangeoverProtocol`; no `import Network`).*

```swift
public struct CertificateFingerprint: Hashable, Codable, Sendable { public let sha256SPKI: Data }   // #0064
public struct PeerIdentity: Hashable, Sendable { public let fingerprint: CertificateFingerprint }

public protocol MessageChannel<Outgoing, Incoming>: Sendable {
    associatedtype Outgoing: Encodable & Sendable
    associatedtype Incoming: Decodable & Sendable
    var peer: PeerIdentity { get }                        // authenticated by the transport, never claimed in a message
    var incoming: AsyncThrowingStream<Incoming, any Error> { get }
    func send(_ message: Outgoing) async throws
    func close(_ reason: CloseReason) async
}
public typealias HostChannel   = any MessageChannel<RemoteEvent, CommandEnvelope>
public typealias ClientChannel = any MessageChannel<CommandEnvelope, RemoteEvent>

public protocol TransportListener: Sendable {
    func run(_ accept: @escaping @Sendable (HostChannel) async -> Void) async throws
}
public protocol TransportBrowser: Sendable {
    func hosts() -> AsyncStream<[DiscoveredHost]>        // DiscoveredHost carries the TXT hint (#0063): wire version, hostID
    func connect(to host: DiscoveredHost, pinning: CertificateFingerprint?) async throws -> ClientChannel
}
```

- **`FrameCodec`** (pure): a 4-byte big-endian length plus a `ProtocolCodec` body.
  - Rejects a length over `ProtocolLimits.maxFrameBytes` *from the header*, before
    reading the body.
  - Rejects zero-length frames.
  - An incremental `FrameDecoder` handles split and coalesced reads.
- **`OutboundQueue`** (pure value type) is the send policy for a slow peer:
  - A newer `hostState` replaces a pending one.
  - `commandResult`, `session`, `goodbye` and `pong` are never dropped.
  - `logAppend` batches are dropped from the middle past a cap, and a synthesized
    `logAppend` marker line ("… N lines dropped …") is inserted.
  - It is wrapped by `actor ChannelWriter`. That actor is the legitimate use
    `Plan.md` allows, because it is reached from transport executors, and needs a
    comment saying so.
- **`InMemoryTransport`:**
  - `makePair(peer:)` returns `(HostChannel, ClientChannel)`, and every message is
    **encoded and decoded through `ProtocolCodec`**, so limits and codec bugs show
    up in higher-level tests.
  - `InMemoryListener` (tests call `connect(peer:)`) and `InMemoryBrowser` (a
    scripted host list).
  - `simulateDrop()` for [#0072](0072.md) and `simulateStall()` for the slow-client
    test.
  - `close` must `finish()` both streams. `run-remote-tests.sh` reports
    continuation leaks.
- The Wi-Fi Aware doc deliverable is unchanged.

*Part B — blocked on S1/S2 and decision D-A. `NetworkTransport` in
`ChangeoverTransport` (`import Network, Security, CryptoKit`).*

- `BonjourTLSListener` wraps `NetworkListener(for: .bonjour(type: "_changeover._tcp",
  txtRecord: …))` with a `TLS` stack configured per [#0064](0064.md).
  - It reads the client leaf certificate in `certificateValidator`, computes the
    fingerprint, and builds the channel with that `peer`.
  - Frames are read with `receive(exactly:)`.
- `BonjourTLSBrowser` wraps `NetworkBrowser` with `includeTxtRecord: true`.
- The exact result-builder syntax is copied from the working S1/S2 spike code, not
  from this plan.
- `newConnectionLimit`: start at 8.

**Isolation.** Both targets are nonisolated and `Sendable`. The server and
`RemoteSession` hop to MainActor themselves.

**Tests** (in `ChangeoverTests` via `./run-remote-tests.sh gordon`; no sockets):

- `FrameCodecTests`: split reads, oversized header, zero length, two frames in one
  chunk.
- `OutboundQueueTests`: latest-wins `hostState`, never-drop classes, the drop marker.
- `InMemoryTransportTests`: ordering, close finishes streams, drop surfaces as an
  error on both ends, codec limit enforced.

Part B is **not** unit-tested. Its handshake is covered by S2 on loopback (one Mac)
and by two real Macs in [#0068](0068.md)/[#0071](0071.md).

## Notes

**Testable without hardware:** add an `InMemoryTransport` conforming to all three
protocols that hands messages between two halves of a pair with no sockets. Every
higher-level ticket in this phase — the handshake ([#0069](0069.md)), arbitration
([#0070](0070.md)), the session mirror ([#0071](0071.md)), reconnect backoff
([#0072](0072.md)) — can then be unit-tested end to end with no network, no second
machine and no disc. Building this fake is arguably the highest-leverage hour in the
whole phase and should not be deferred.

**Requires two real machines:** that `BonjourAdvertiser` and `BonjourDiscoverer`
actually find each other. That belongs to [#0063](0063.md) and [#0068](0068.md);
this ticket is verified by the in-memory pair plus a compile.

**Do not claim Wi-Fi Aware readiness as verified.** Nothing here can be tested
against Wi-Fi Aware until Apple lifts the gate. The honest claim is "the injection
point exists and the mapping is documented", not "Wi-Fi Aware is a drop-in".
