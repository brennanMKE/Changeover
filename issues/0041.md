# 0041 — Jobs have no identity and no state machine, so nothing can refer to a job or validate its progress

| | |
|---|---|
| **Status** | open |
| **Phase** | 3 — Unattended multi-disc |
| **Module** | JobQueue |
| **Platform** | macOS |
| **First seen** | 2026-09-11 |

## Description

There is no `Job` type at all — a job is an implicit thing that exists for the duration of one `DVDPipeline.run()` call and is described only by a boolean (`Changeover/MetadataEntryView.swift:7`). Before a queue can exist, a job needs a stable `JobID`, an explicit stage enum with validated transitions, and a `Codable` snapshot that Phase 4 can put on the wire.

## Long Description

This is the foundation ticket for Phase 3 and it deliberately ships no behaviour change. It adds types.

Two separate representations are needed and conflating them is the mistake to avoid:

- **`Job`** — an `@Observable final class`, host-only, reference semantics. It is what SwiftUI rows bind to, so that updating one job's progress invalidates one row rather than the whole list. Reference types are required here: an array of `@Observable` structs does not exist, and putting mutable job state in a value type inside `JobQueue.jobs` means every progress tick invalidates every view reading the array.
- **`JobSnapshot`** — a `Codable`, `Sendable`, `Hashable` struct projected from a `Job`. This is the protocol surface. It never gains an `@Observable` macro and never gains a closure or a `Task` handle, because those cannot cross the wire.

The stage enum is the part that earns unit tests. Right now "what stage is the job in" is inferable only from which line of `DVDPipeline.run()` is executing (`Changeover/DVDPipeline.swift:16-62`), and failure is a log line plus an early `return` (`:32-34`, `:47-50`) that leaves no residue anywhere.

## Steps to reproduce

1. Open `Changeover/DVDPipeline.swift` and try to answer "is this job ripping or encoding right now" from outside the pipeline.
2. Open `Changeover/MetadataEntryView.swift:142-155` and try to name the job that `startRipping()` just began.
3. Look for anywhere in the codebase that could reject an illegal transition such as encoding a job that already failed.

## Expected behavior

A job is a first-class value with a stable identity: `JobID` (a typed wrapper, `Codable` + `Hashable` + `Sendable`), a `JobStage` enum covering every stage the pipeline actually has, a `JobFailure` describing *why* a job is in `.failed`, and a `JobState` that bundles stage, progress and failure with an enforced invariant. Illegal transitions are rejected, not silently applied.

## Actual behavior

None of these types exist. The only observable job state in the app is `isProcessing: Bool` and an array of log strings, both `@State` inside a view, and both discarded when the window closes.

### Types

```swift
struct JobID: Hashable, Codable, Sendable, CustomStringConvertible {
    let rawValue: UUID
    init() { rawValue = UUID() }
    var description: String { String(rawValue.uuidString.prefix(8)) }
}
```

A typed wrapper, not a bare `UUID`. Phase 4 will carry several kinds of id (job, peer, disc) and a bare `UUID` in the protocol means nothing stops a peer id being passed where a job id belongs.

```swift
enum JobStage: String, Codable, Sendable, CaseIterable {
    case queued          // accepted, waiting for the drive lane
    case ripping         // makemkvcon running; the disc must stay in the drive
    case awaitingEncode  // rip done, disc ejected, waiting for the encode lane
    case encoding        // HandBrakeCLI running
    case organizing      // moving into the Plex folder structure
    case done
    case failed
    case cancelled
}
```

`awaitingEncode` is the stage that makes Phase 3 possible and it is exactly the stage the current code has no room for: `DVDPipeline.run()` goes from `RipController.rip` returning (`Changeover/DVDPipeline.swift:27-35`) straight into `EncodeController.encode` (`:41-46`) with no point at which the job could wait.

Legal transitions — this table is the specification the tests assert against:

| From | To |
|---|---|
| `queued` | `ripping`, `cancelled`, `failed` |
| `ripping` | `awaitingEncode`, `failed`, `cancelled` |
| `awaitingEncode` | `encoding`, `cancelled`, `failed` |
| `encoding` | `organizing`, `failed`, `cancelled` |
| `organizing` | `done`, `failed` |
| `done`, `failed`, `cancelled` | — terminal, no outgoing edges |

Note `organizing` cannot be cancelled: it is a `FileManager.moveItem` (`Changeover/PlexOrganizer.swift:27`) that is over in milliseconds, and cancelling halfway would leave a half-placed file in the Plex library.

```swift
enum JobFailure: Codable, Sendable, Hashable, Error {
    case makemkvKeyExpired
    case toolMissing(path: String)
    case destinationUnwritable(path: String)
    case diskFull
    case discRemoved
    case processExited(stage: JobStage, status: Int32)
    case cancelled
}
```

The first four come from Phase 1's "surface actionable failures distinctly" work (`Roadmap.md:82-83`); this ticket gives them a home on the job rather than in a log line. `discRemoved` is new in Phase 3 and is consumed by [#0045](0045.md). Each case owns a `localizedDescription` and a `recoverySuggestion` so [#0048](0048.md) has something to render without a switch in the view.

```swift
struct JobState: Codable, Sendable, Hashable {
    var stage: JobStage
    var progress: Double?      // 0…1 within the current stage; nil when unknown
    var failure: JobFailure?   // non-nil if and only if stage == .failed
}
```

The invariant `failure != nil ⇔ stage == .failed` is enforced in a private initialiser and asserted in tests. `progress` is `Optional` rather than `0` because `makemkvcon` and `HandBrakeCLI` both emit long stretches with no parseable percentage and a stuck `0%` bar reads as broken.

```swift
@Observable final class Job: Identifiable {
    let id: JobID
    let request: RipRequest          // from Phase 2 — metadata + titleIndices + languages
    let workingDirectory: URL        // per-job directory from Phase 1
    let createdAt: Date
    private(set) var state: JobState
    private(set) var startedAt: Date?
    private(set) var finishedAt: Date?

    @discardableResult
    func transition(to stage: JobStage, failure: JobFailure? = nil) -> Bool
}
```

`state` is `private(set)` and `transition(to:)` is the only mutator. It consults the table above, returns `false` and leaves state untouched on an illegal edge, and stamps `startedAt` on the first move out of `queued` and `finishedAt` on any move into a terminal stage. `Job` is `@MainActor` for free under the module default and must **not** be marked `nonisolated` or made an `actor` — `Plan.md` is explicit that the `actor` keyword is not used for types with no reason to leave the main actor.

```swift
struct JobSnapshot: Codable, Sendable, Hashable, Identifiable {
    let id: JobID
    let title: String            // metadata.folderName, for display
    let state: JobState
    let createdAt: Date
    let startedAt: Date?
    let finishedAt: Date?
}
```

`Job.snapshot` produces one. Phase 4 sends `JobSnapshot`, never `Job`.

### Risks

- **Transition validation must be total, not `default:`-driven.** A `switch` on `(from, to)` with a `default: return false` silently rejects a stage added later. Use `CaseIterable` plus an explicit `allowedTransitions: [JobStage: Set<JobStage>]` and a test that walks `JobStage.allCases` and fails if any case is missing a key.
- **`Codable` stability.** `JobStage` is a `String` raw-value enum precisely so a Phase 4 client on an older build decodes `"encoding"` rather than an integer whose meaning shifted when a case was inserted. Do not convert it to `Int` raw values.
- **Don't add the queue here.** The temptation is to give `Job` a `next` pointer or a position. Ordering belongs to [#0042](0042.md); a job that knows its own position cannot be reordered without mutating it.

### Plan refresh (2026-09-15)

**Stale:**

- **`JobStage` and `JobFailure` already exist** with other meanings (`JobOutcome.swift:16`, `:92`), and both are wire format (#0007):
  - `JobStage` is the stage a failure happened at;
  - `JobFailure` is a struct of stage, reason, `logTail` and `fallback`.

  New files with those names would not compile. The planned `JobFailure` enum is also redundant: `FailureReason` already covers:
  - a missing tool;
  - an unwritable destination;
  - a full disk;
  - an expired activation key;
  - an unreadable disc;
  - a cancel.

  Wording belongs to `FailurePresenter`. These types deliberately carry no user-facing strings or `LocalizedError` (`JobOutcome.swift:9-11`), so there is no `localizedDescription` or `recoverySuggestion` to add.
- **`ripping` and `awaitingEncode`** describe the deleted rip stage (#0014).
- **`Job.request: RipRequest`** can't be used yet, because `RipRequest` doesn't exist (#0027 is open). Nor can `workingDirectory` be set up front: `DVDPipeline.run()` creates that directory itself, part-way through the job.
- **A job has two unrelated ids today:**
  - `JobController.start` mints one (`JobController.swift:107`), used for the notification identifier;
  - `DVDPipeline.run()` mints another (`DVDPipeline.swift:82`), used for the working directory and the `▶ Job` log line.

  A UUID-based `JobID` would add a third.
- **Stale line references:** the `DVDPipeline.swift` ranges (16-62, 27-35, 32-34, 41-46, 47-50) and `PlexOrganizer.swift:27` describe pre-#0014 files.
- **The test notes are out of date.** `ChangeoverTests` holds 22 suites, not one stub, and tests run through `./run-remote-tests.sh gordon`.

**Replacement.**

- **New files** in `Changeover/Jobs/` (picked up automatically by the synchronized group):
  - `JobID.swift`, `JobPhase.swift`, `JobState.swift`, `Job.swift`, `JobSnapshot.swift`;
  - `ChangeoverTests/JobStateMachineTests.swift`.
- **Changed files**, all small:
  - `JobController.swift` — `makeJobID()` forwards to `JobID.make()`;
  - `DVDPipeline.swift` — takes `let jobID: JobID` instead of minting one at `:82`;
  - `JobNotifier.swift` — identifier becomes `jobID.rawValue`;
  - `JobController.Runner` — gains the id; coordinate its exact shape with #0042's `JobContext`.

```swift
nonisolated struct JobID: Hashable, Codable, Sendable, CustomStringConvertible {
    let rawValue: String                    // "job-20260915-143012-A1B2"
    init?(rawValue: String)                 // nil unless WorkingFiles.isJobID(rawValue)
    static func make(date: Date = Date()) -> JobID   // today's makeJobID body
    var description: String { rawValue }
}
```

**One id per job.** The same value names:

- the working directory;
- the `▶ Job` log line;
- the notification identifier;
- the history row;
- the Phase 4 wire id.

Keep it a `String` wrapper in the existing `job-yyyyMMdd-HHmmss-XXXX` shape, not a `UUID`. That way `WorkingFiles`' deletion guards (`jobIDPattern`, `isJobID`, `WorkingFiles.swift:25-34`) keep protecting every `removeItem` unchanged, and `WorkingFilesTests` T1 still round-trips through `makeJobID()`.

```swift
nonisolated enum JobPhase: String, Codable, Sendable, CaseIterable {
    case starting     // sweep + preflight, DVDPipeline.swift:228-268
    case encoding     // HandBrakeCLI reading the disc
    case fallback     // #0015: MakeMKV rip + second HandBrake pass
    case organizing   // PlexOrganizer.move + eject — not cancellable
    case succeeded, failed, cancelled
    var isTerminal: Bool { get }
}
```

| From | To |
|---|---|
| `starting` | `encoding`, `failed`, `cancelled` |
| `encoding` | `fallback`, `organizing`, `failed`, `cancelled` |
| `fallback` | `organizing`, `failed`, `cancelled` |
| `organizing` | `succeeded`, `failed` |
| terminal | — |

Under #0040's option B, add `.queued`, `.staging` and `.awaitingEncode`. Not before.

**A terminal state carries the existing `JobOutcome`; nothing is widened.**

```swift
nonisolated struct JobState: Codable, Sendable, Equatable {
    private(set) var phase: JobPhase
    private(set) var progress: Double?      // nil = unknown; no progress parser exists yet
    private(set) var outcome: JobOutcome?   // non-nil iff phase.isTerminal
    static let initial: JobState            // .starting
    func advancing(to phase: JobPhase) -> JobState?     // nil: illegal edge or terminal target
    func finishing(with outcome: JobOutcome) -> JobState?
}
```

**`finishing(with:)`** maps an outcome to a terminal phase:

- `.succeeded` is accepted only from `.organizing`;
- a failure whose reason is `.cancelled` goes to `.cancelled`;
- any other failure goes to `.failed`;
- it returns `nil` if the state is already terminal.

These are pure value functions, so the state machine needs no MainActor and no disc. `JobState` is `Equatable` rather than `Hashable`, because `JobOutcome` is only `Equatable`.

```swift
@Observable final class Job: Identifiable {        // MainActor by default; never an actor
    let id: JobID
    let metadata: MovieMetadata                     // becomes RipRequest when #0027 lands
    let disc: DiscInsertion
    let createdAt: Date
    private(set) var state: JobState = .initial
    private(set) var finishedAt: Date?
    @discardableResult func advance(to: JobPhase) -> Bool
    @discardableResult func finish(with: JobOutcome, at: Date = Date()) -> Bool
    var snapshot: JobSnapshot { get }
}

nonisolated struct JobSnapshot: Codable, Sendable, Equatable, Identifiable {
    let id: JobID
    let title: String        // metadata.folderName
    let volumeName: String   // disc.mountURL.lastPathComponent
    let state: JobState
    let createdAt: Date
    let finishedAt: Date?
}
```

`MovieMetadata` is a plain MainActor struct and not `Codable` (`MovieMetadata.swift:5`). So the snapshot carries only strings, and this ticket doesn't touch `MovieMetadata`; #0027 makes it `Codable`.

`startedAt` is dropped. Under option A a job is created at the moment it starts.

**Tests** — all pure, no disc, run through `./run-remote-tests.sh gordon`:

- **Edges:**
  - every legal edge succeeds;
  - an illegal edge returns `nil` and leaves the value unchanged;
  - a terminal state rejects everything, including itself;
  - a completeness test over `JobPhase.allCases`.
- **Outcome mapping:**
  - `.succeeded` from anywhere but `.organizing` is rejected;
  - a `.cancelled` reason lands in `.cancelled`;
  - `finishedAt` is set exactly once.
- **`JobID`:**
  - `init?(rawValue:)` rejects `../x`, a trailing newline and a UUID;
  - it accepts `JobID.make()` output.
- **Coding:** `JobSnapshot` round-trips through JSON, with the phase strings asserted literally.
- **Id unification:**
  - a stub `Runner` receives the same id `JobController` exposes;
  - `DVDPipeline`, driven with `Fixtures/stub-HandBrakeCLI.sh` the way `EncodeControllerTests` drives it, creates `Working/encoding/<that id>`.

No part of this ticket needs a physical disc.

## Notes

**Verification.** This ticket is pure model code with no disc, no subprocess and no UI, so it is fully unit-testable and the `Issues.md` manual-verification caveat does not apply to any part of it. `ChangeoverTests/JobStateMachineTests.swift` must cover:

- every legal edge in the table above succeeds and updates `state.stage`;
- a representative illegal edge from each stage returns `false` and leaves `state` byte-identical (including `finishedAt`);
- all three terminal stages reject every outgoing transition, including a transition to themselves;
- `startedAt` is set exactly once, on the first departure from `queued`, and is not overwritten by later transitions;
- `finishedAt` is set exactly once, on entry to a terminal stage;
- the `failure != nil ⇔ stage == .failed` invariant cannot be violated through the public API — a `.failed` transition with no failure, and a `.done` transition carrying a failure, are both rejected;
- a completeness test over `JobStage.allCases` proving the transition table has an entry for every case;
- `JobSnapshot` round-trips through `JSONEncoder`/`JSONDecoder` for every `JobStage` and every `JobFailure` case, with the encoded stage strings asserted literally so a rename breaks the test rather than the protocol.

Run with `xcodebuild -project Changeover.xcodeproj -scheme Changeover -destination 'platform=macOS' test` and confirm the new test names appear in the output — `ChangeoverTests` currently contains one empty stub, so the count going from 1 to N is the signal.
