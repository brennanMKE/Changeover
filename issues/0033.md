## Description

HandBrake's scan of *Fargo* lists **12 subtitle entries where there are 6 logical tracks**. Each track is present in a Wide Screen and a Letterbox variant, distinguished only by its stream id and a parenthetical in the language string. Phase 2's track-selection UI ([#0027](0027.md)) must collapse the pairs, or the user is asked to choose between twelve rows that read almost identically.

## Long Description

From `MakeMKVReplacement-Results.md` §6, "Subtitle count discrepancy resolved":

```
id=0x20bd, lang=English (Wide Screen) [VOBSUB]
id=0x26bd, lang=English (Letterbox) [VOBSUB]
```

The six logical tracks on the disc are **English, Français, español, English Forced, Français Forced, English Director's Commentary** — each appearing twice, once per aspect-ratio variant. That is where 12 comes from.

The same disc reports different counts through every tool that reads it, which is the useful part of this finding:

| Tool | Subtitle count | What it is counting |
|---|---|---|
| HandBrake `--scan --json` | **12** | every VOBSUB substream, both aspect variants |
| lsdvd `-x -Oj` | **6** | logical subtitle tracks |
| MakeMKV robot mode | **3** | a filtered subset |

None of them is wrong; they are answering different questions. But it means the count cannot be taken at face value from whichever tool happens to be the scanner, and the number the user sees must be derived deliberately rather than inherited.

This matters more under the HandBrake pipeline than it did before. [#0027](0027.md) was written against `makemkvcon`'s numbers, where the same disc presented 3 subtitle streams — a list short enough that presenting it raw was defensible. HandBrake presents 12. A UI designed around 3 rows and fed 12 is a different UI.

The variant distinction is also **not** meaningful to the user in the way the parenthetical suggests. Wide Screen and Letterbox VOBSUB streams differ in where the bitmap is positioned for the two framings of the disc's video; for an anamorphic widescreen encode there is a correct one and an irrelevant one. Presenting both as choices asks the user a question they cannot answer and that has a determinable right answer.

Note that the parenthetical is inside the language string, not a separate field — `lang=English (Wide Screen)`. Any code that keys a language on that string, dedupes on it, or displays it raw inherits the variant into the language. That is a parsing consequence, not only a UI one.

## Expected behavior

The scan model carries the variant as its own property, not baked into the language. The selection UI shows **six rows** for this disc — English, Français, español, English Forced, Français Forced, English Director's Commentary — with the appropriate variant chosen automatically for the output geometry, and the raw substream ids retained so the encode can request the right one.

## Actual behavior

Nothing collapses anything, because nothing parses a HandBrake scan yet ([#0023](0023.md)). If the scan output were surfaced as-is, this disc would present twelve rows differing only by a parenthetical, six of which are for a framing the encode is not producing.

## Notes

**Do not collapse by string-stripping the parenthetical and deduping.** The variant is real information the encode needs — it determines which substream id to select — so it must survive into the model even though it does not survive into the UI. Strip it for display, keep it for selection.

**Do not assume the pairing is always exactly two.** Six-into-twelve is one disc. A disc may carry only one variant, three, or an odd number where a track exists in one framing only. Group by (language, role) and handle a group of any size; do not index into a pair.

**Do not assume the parenthetical vocabulary is closed.** "Wide Screen" and "Letterbox" are what this disc emits. Treat an unrecognized parenthetical as a variant label to carry through rather than as a parse failure — an unknown variant is still a valid track.

Testable without a disc, and it should be: this is a pure function from a scanned subtitle list to a grouped one. Fargo's twelve entries are a documented fixture with known ids and known expected output (six groups, correct roles). Capture a real `--scan --json` run as a fixture in `ChangeoverTests/Fixtures/` alongside the existing `makemkvcon/` corpus, and assert the grouping against it. Include the Forced and Commentary tracks — those are roles, and they must not be collapsed into their plain-language counterparts.

The "English Forced" and "English Director's Commentary" entries are a reminder that role and language are separate axes. [#0027](0027.md) already deals with forced subtitles; this ticket adds a third axis (variant) and the three must not be conflated.

Whether any subtitle track is selected at all is a separate question — see [#0027](0027.md) for selection, and [#0014](0014.md), which dropped `--subtitle scan` because it cost roughly half the encode's wall clock. (This paragraph previously called the output's `bin_data` stream a VOBSUB track; it is the chapter text track — see [#0017](0017.md).)

## Plan

### Model

Add a variant to `DiscStream` ([#0022](0022.md)) — an optional label carried verbatim from the scan, plus whatever normalized enum is worth having once more than one disc has been seen. Keep the raw stream id (`0x20bd`, `0x26bd`) on the stream; that is what the encode selects by.

Parse the language as language-plus-parenthetical, not as an opaque string. Role (Forced, Director's Commentary) is a separate axis again — HandBrake puts all three in the same field on this disc and the parser has to separate them.

### Grouping

A pure `nonisolated` function from `[DiscStream]` to groups keyed by (language, role), each holding the variants. For display, one row per group. For selection, the group plus the chosen variant resolves to exactly one stream id.

### Choosing the variant

Prefer Wide Screen for an anamorphic widescreen encode. Fargo's scan gives the geometry to decide with — `Geometry` is in the same scan JSON. Where the rule is ambiguous, pick one deterministically and log the choice rather than asking the user.

### Risks

- **Six-into-twelve is one disc.** The rule must be written so an unexpected shape degrades to "show what is there" rather than dropping tracks. Silently hiding a subtitle track is worse than showing a duplicate.
- **Do not collapse audio the same way without evidence.** Fargo's three audio tracks were reported consistently, with `Attributes.Commentary` correctly flagged on the third (`-Results.md` §3). Audio has its own dedup problem in [#0027](0027.md); this ticket is about subtitles specifically.
- **The counts in [#0021](0021.md)'s fixtures are MakeMKV's counts.** Do not reconcile the two corpora by assuming one is authoritative — they count different things, which is the whole point of this ticket.

#### New evidence from the Dragon Tattoo fixture

Grouping by `(language, role)` and collapsing would merge Dragon Tattoo's three
English tracks into one row. They are three distinct tracks that the metadata can't
tell apart. That is the "silently hiding a subtitle track" risk above, now seen on
real data. **Collapse only across different variants, never within one variant.**

#### Types in `Changeover/SubtitleGrouping.swift` (pure, `nonisolated`)

```swift
nonisolated struct SubtitleGroup: Equatable, Sendable, Identifiable {
    var languageCode: String?     // LanguageCode.normalize (#0027); nil = untagged
    var languageName: String?     // parenthetical-free, from the parser
    var isForced: Bool
    var isCommentary: Bool
    var isText: Bool              // DiscStream.isTextSubtitle, once it also matches "CC608" (#0027)
    var members: [DiscStream]     // at most one per variant, TrackNumber order, never empty
    var selectedTrackNumber: Int  // the member an encode would take
    var id: Int { members[0].index }
}

nonisolated enum SubtitleGrouping {
    static let preferredVariant = "Wide Screen"
    static func groups(for title: DiscTitle) -> [SubtitleGroup]
}
```

#### Rule

1. Take the title's `.subtitle` streams in `TrackNumber` order.
2. Bucket them by `(normalized languageCode, languageName, isForced, isCommentary,
   codecId)`, keeping buckets in first-appearance order.
3. Within a bucket, split the streams by `variant`, with `nil` as its own variant.
   - **At least two variants, each with the same number of streams *n*:** pair the
     variants by position into *n* groups. Each group holds one stream per variant.
   - **One variant only, or unequal counts:** make one group per stream. An unexpected
     shape falls back to showing what is there.
4. `selectedTrackNumber` is the `Wide Screen` member when there is one, otherwise the
   lowest `TrackNumber`. An unknown variant label is kept as it is and never treated
   as a failure.
5. Log the choice only when a selection is actually encoded. That never happens in
   Phase 2 (see #0029's refresh), so there the groups are read-only subtitle rows in
   #0027's picker.

- **Synthetic Fargo** (name the test `syntheticFargo…`; build it from

  - 12 streams produce 6 groups.
  - Each group has a `Wide Screen` and a `Letterbox` member, and selects the Wide
    Screen one.
  - The Forced and Commentary groups are never merged into plain English.
- **Uneven counts.** Two Wide Screen streams and one Letterbox stream give 3 groups.
- **Single variant.** A lone `PanScan` stream gives 1 group that keeps its variant.
- **Unknown label.** An unknown variant `"Foo"` pairs by position with `Wide Screen`.
- **No variant.** A stream with a `nil` variant stays its own group.
- **No stream lost.** The groups never hold fewer streams than the input.
- **Fixture title 4.** Its CC608 stream is `isText`, with `languageCode == nil` after
  #0027's `und` normalization.
