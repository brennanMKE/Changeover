## Description

`mac_plex_dvd_workflow.md` §3.3 says to keep English and Spanish audio and drop the
rest. Changeover offers no way to express that — there is no track UI, no language
preference, and the HandBrake invocation is a fixed string
(`Changeover/EncodeController.swift:20-28`). The user gets whatever the defaults
produce.

## Root cause

Nothing built the picker or the request shape the #0026/#0029/#0033 plumbing was
already waiting for. `JobController.start(metadata:settings:)` took a bare
`MovieMetadata` and always encoded with `EncodeController.AudioSelection
.sourceDefault` (whatever HandBrake picks as its own default — the disc's first
audio track); there was no type describing "this title, these tracks", no picker
UI, and no per-user language preference on `AppSettings`.

## Fix

Implemented per the **2026-09-15 plan refresh** in this file (superseded the
original MakeMKV-robot-mode plan) and the orchestrator's decisions/handoff notes
recorded in it. Scope: the plumbing named in the #0029-review handoff, plus the
picker.

- **`Changeover/RipRequest.swift`** (new) — `RipRequest`: `metadata`,
  `featureTitleIndex`, `extraTitleIndices` (defaulted `[]`, #0031's field, unused
  here), `audioTrackNumbers`. `Codable, Hashable, Sendable` so it can cross the
  wire in Phase 4.
- **`Changeover/AudioTrackOptions.swift`** (new) — `AudioTrackOption` and
  `AudioTrackOptions.options(for:)`/`.isUntagged(_:)`/`.preselection(_:preferred
  :untagged:)`. Tagged streams dedupe on `(languageCode, codecId, bitrate,
  channelCount, flags, displayName)`, keeping the first occurrence and recording
  the rest as `duplicateTrackNumbers`; `flags` is part of the key so a commentary
  track never merges into a plain one. **Untagged streams are never merged**,
  even when two are byte-for-byte identical otherwise (Hornets' Nest's shape) —
  merging them is indistinguishable from silently dropping a second language
  track (a Swedish original plus an English dub). Preselection: on an untagged
  title, every non-commentary track; otherwise the non-commentary tracks matching
  `AppSettings.preferredAudioLanguages`, falling back to the first non-commentary
  track when nothing matches, and to the first track at all when every option is
  a commentary — never `[]` for a title that has audio.
- **`Changeover/EncodeSelection.swift`** (new) — `EncodeSelection` (`title`,
  `audio`, `fallbackAudio`, `filter`) and `.phase1` (today's byte-identical
  default). `EncodeSelection.make(request:disc:)` is the one place a `RipRequest`
  is resolved against a live scan: `nil` when `featureTitleIndex` isn't a title
  of `disc`, or any `audioTrackNumbers` entry isn't an audio stream on that
  title. `audio` is `.tracks(audioTrackNumbers)`. `filter` is
  `DeinterlaceDecision.decide(frameRate: interlaceDetected:)` from the resolved
  title's own scanned values. *Corrected in review (d28308a):* the draft set
  `fallbackAudio` to `.languages(...)` of the selected tracks' codes, or
  `.languages([])` when any was untagged. It is now always `.sourceDefault`,
  because `.languages` is unverified on real HandBrake and drops the AAC stereo
  copy. See `## Resolution notes`.
- **`Changeover/JobController.swift`** — `Runner` now takes `(RipRequest,
  EncodeSelection, AppSettings, URL, log)`. `start(request:settings:)` replaces
  `start(metadata:settings:)`: keeps every #0034 disc-identity guard (reading
  `request.metadata.selectionDisc`), then refuses when `scanState` isn't
  `.scanned` or `EncodeSelection.make(request:disc:)` returns `nil` — this is the
  enforcement the ticket asks for ("refuses a request whose indices or tracks
  don't match the held scan"), and it subsumes the old separate "no title
  selected"/"title not on this scan" checks. New `selectedAudioTrackNumbers:
  [Int]` state, recomputed via `AudioTrackOptions.preselection` every time
  `selectTitle(_:settings:)` runs or a scan's `.single` outcome preselects a
  title, and cleared on `removeDisc()`/a fresh `startScan`.
- **`Changeover/DVDPipeline.swift`** — `titleSelection: TitleSelection` replaced
  with `selection: EncodeSelection = .phase1` (same defaulting trick, so the
  ~25 existing construction sites in `EncodeControllerTests`/
  `MakeMKVFallbackTests`/`PreflightTests` don't change). The primary encode
  passes `audio: selection.audio`; the `runFallback` path threads
  `fallbackAudio: selection.fallbackAudio` through to its own
  `EncodeController.encode(...)` call. The deinterlace log line now just reports
  `selection.filter` (resolved upstream by `EncodeSelection.make`) instead of
  logging a hardcoded `nil`/`nil` "no scan yet" pair — #0022/#0023 landed since
  that comment was written.
- **`Changeover/AppSettings.swift`** — `preferredAudioLanguages: [String] =
  ["eng", "spa"]`, loaded with `stringArray(forKey:)` (not the existing
  `!v.isEmpty` string idiom) so an intentionally empty list survives a round
  trip, normalized via `LanguageCode.normalize` on both load and save. Gained
  `init(defaults: UserDefaults = .standard)` so tests use a throwaway suite.
- **`Changeover/TrackSelectionView.swift`** (new) — sits under
  `DiscTitleListView`'s verdict row (per the #0026 review handoff), shown once a
  title is selected. Audio: one toggle row per `AudioTrackOption`, bound directly
  to `jobs.selectedAudioTrackNumbers` with `@Bindable` (no `@State` copy),
  showing the duplicate count and a "Commentary" badge. Subtitles: `#0033`'s
  `SubtitleGrouping.groups(for:)` shown **read-only** — Phase 2's output still
  carries no subtitle track (#0014 §5), so there is nothing to select yet; #0036
  is the follow-on.
- **`Changeover/MetadataEntryView.swift`** — composes `TrackSelectionView` under
  `DiscTitleListView`; `startRipping()` builds a `RipRequest` from
  `vm.selectedMovie`, `jobs.selectedTitleIndex`, and
  `jobs.selectedAudioTrackNumbers`, and calls `jobs.start(request:settings:)`.
- **`Changeover/SettingsView.swift`** — a "Languages" group with one
  comma-separated field for `preferredAudioLanguages`, normalizing on edit.
- **`Changeover/MovieMetadata.swift`** — `Codable, Hashable, Sendable`, plus a
  plain memberwise `init(title:year:tmdbID:selectionDisc:)` alongside the
  existing `init(from: TMDBMovie, ...)` — needed so `RipRequest` (which embeds a
  `MovieMetadata`) can itself be `Codable`/`Hashable`.
- **`Changeover/DiscInsertion.swift`** — `Codable, Hashable`, for the same
  reason (`MovieMetadata.selectionDisc` carries one). See Gotchas for the
  `insertionID` fix this required.

**Divergences from the plan, decided here (user AFK, delegated):**

- **`MovieMetadata.init(from:selectionDisc:)` is not `@MainActor`.** The plan's
  refresh said to mark it `@MainActor` (its `TMDBMovie` argument is always built
  on MainActor in production). But `ChangeoverTests` does not set
  `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` (only the `Changeover` app target
  does — confirmed by grepping `project.pbxproj`), and roughly 15 existing test
  helper functions across `EncodeControllerTests`, `MakeMKVFallbackTests`,
  `PreflightTests`, `JobNotifierTests`, `JobOutcomeTests`, and
  `MovieMetadataSanitizationTests` call `MovieMetadata(from:)` synchronously from
  plain, non-`async`, non-`@MainActor` helpers. Marking the init `@MainActor`
  made those a hard compile error ("call to main actor-isolated initializer ...
  in a synchronous nonisolated context"), confirmed by a local
  `build-for-testing` run. Since `TMDBMovie` is a plain `Sendable`-shaped value
  type, the conversion never actually needed MainActor — left the whole type
  (and this init) plain `nonisolated`, which keeps every existing call site
  compiling and is arguably the more correct isolation for a pure value
  transform.
- **The subtitle picker is read-only**, per the ticket's own #0027 refresh
  ("`SubtitleGrouping`'s groups are consumed by nothing yet ... #0027's picker
  rows 'come from #0033's `SubtitleGrouping.groups(for:)`'") and the
  orchestrator's recorded decision ("Phase 2 output carries no subtitles, same
  as today").
- **`start`'s refusal message is one line covering both the title and the
  audio-track mismatch** ("don't match the current disc scan"), replacing the
  old two separate messages ("No title selected from the disc scan" / a title
  not on the held scan) — `EncodeSelection.make` doesn't distinguish which half
  failed, and inventing a second code path to re-derive that distinction only to
  match old test text wasn't worth it.

## Gotchas

- **`DiscInsertion.insertionID` had to change from `let insertionID = UUID()`
  to `var insertionID = UUID()`.** Swift's synthesized `Decodable.init(from:)`
  silently *skips* decoding an immutable stored property that carries its own
  initializer expression — the compiler even warns "immutable property will not
  be decoded because it is declared with an initial value which cannot be
  overwritten" — and just re-runs `UUID()` on every decode instead of reading
  the wire value. `RipRequestTests.discInsertionRoundTripsThroughJSON` (and the
  two other round-trip tests that embed a `DiscInsertion`) caught this
  immediately: a decoded `MovieMetadata`/`RipRequest` was never `==` to the
  original. Confirmed the mechanism stand-alone with a two-line `swift -e`-style
  script before fixing it. Nothing in the codebase mutates `insertionID` after
  construction, so the `var` is cosmetic for every call site except the
  decoder's own synthesized init.
- **`ChangeoverTests` does not inherit `SWIFT_DEFAULT_ACTOR_ISOLATION =
  MainActor`** — only the `Changeover` app target's build settings set it
  (confirmed via `grep -c SWIFT_DEFAULT_ACTOR_ISOLATION` returning exactly 2,
  both under app-target Debug/Release blocks). A type defined in the app module
  with no explicit isolation is still implicitly `@MainActor` there (that's why
  `folderName`/`fileName`/`pathSafe` on `MovieMetadata` were already marked
  `nonisolated` before this ticket), but an *explicit* `@MainActor` on an
  initializer is enforced the same way regardless of which target is doing the
  calling — hence the divergence recorded above. Worth remembering for any
  future ticket that touches `MovieMetadata`/`RipRequest`/`DiscInsertion`.
- **`EncodeSelection.make` accepts an empty track list**: `RipRequest
  .audioTrackNumbers == []` resolves vacuously and becomes `.tracks([])`, which
  `#0029`'s `audioArguments` turns into `.sourceDefault`, i.e. the disc's first
  track. *Corrected in review (d28308a):* the draft called this deliberate, but
  it let Start encode the first track while the picker showed every box
  unchecked. `StartGate.canStart` and `JobController.start` now refuse an empty
  pick on a title that has audio (`AudioTrackOptions.isSelectionMissingAudio`).
  `make` still accepts `[]`, because it only checks that indices resolve.
- **`#0031` Step A (the `MovieMetadata.baseName` field the original plan
  expected to land first) has still not landed** — `issues/0031.md` is still

## Long Description

This ticket is the *choosing*; [#0029](0029.md) is the *enforcing*. They are split
because the UI is testable and the encoder behaviour needs a disc, and because the
request shape defined here is protocol surface that Phase 4 inherits directly —
`RemoteControl.md` lines 324–329 already sketches it:

```swift
struct RipRequest: Codable {
    let metadata: MovieMetadata
    let titleIndices: [Int]
    let audioLanguages: [String]      // e.g. ["eng", "spa"]
    let subtitleLanguages: [String]
}
```

That sketch is superseded on one point: `titleIndices: [Int]` becomes a single
feature index plus a typed list of extras. See the plan and [#0031](0031.md).

Defining that type now, in the host app, and shaping the UI to produce it means the
Phase 4 package move is a file drag rather than a redesign of how a job is
described.

One finding from planning that should not be buried: **most DVD subtitles cannot be
carried into an MP4 as selectable tracks.** DVD subtitles are usually VOBSUB —
bitmap images — and MP4 supports only text-based subtitle tracks. HandBrake will
either drop them or require burning them into the picture. So "pick subtitle
languages" cannot mean the same thing as "pick audio languages" for this app's
output format, and the UI must not imply otherwise. `Roadmap.md` line 119 pairs them
as if they were symmetric; they are not. See [#0029](0029.md), which the fixtures
narrowed: `S_CC608/DVD` streams are converted to **text** by MakeMKV and are not
blocked by MP4, so the deferral applies to bitmap subs only.

### What the experiment changed here

`DiscSelection.md` moved work *out* of this ticket and *into* it in roughly equal
measure.

**Out: multi-title selection as a way of finding the movie.** `RipRequest` was
sketched with `titleIndices: [Int]` on the theory that the user might select several
titles to work out which one is the feature. [#0025](0025.md) now identifies the
feature from a single duration comparison plus a Play All guard (9/9 discs), so
the feature is **one
index**. Multiple titles survive only as *extras*, which have a different
destination ([#0031](0031.md)) and therefore belong in a different field with a
different type — not in a flat array where an extra and the feature are
indistinguishable.

**In: track selection turned out to be the genuinely hard half.** Title selection
was one comparison; every multi-track disc in the corpus carries duplicates that
language alone cannot separate. Three findings, each with fixture evidence:

1. **Language tags are optional.** `hornets-nest-min0.txt` contains **zero**
   attribute-3 lines across the whole file. Its feature (title 9) has two
   `DD Surround 5.1` audio tracks and one VOBSUB subtitle, none of them tagged with
   a language, and attribute 30 renders as `"DD Surround 5.1"` with no language
   suffix and `""` for the subtitle. A preference filter of `["eng","spa"]` matches
   nothing here and would drop every audio track, producing a **silent MP4**. The
   rule: *if no stream on the title carries a language tag, keep everything.*
2. **Duplicates are the norm, and deduplication is required.**
   `dragon-tattoo-min0.txt` title 0 streams 1 and 3 are both
   `DD Surround 5.1 English` at 448 Kb/s, 6 channels, `A_AC3`, differing only in the
   default flag (attribute 38: `"d"` versus `""`). `hanna-min0.txt` title 3 streams
   4 and 5 are both `DD Stereo English` at 192 Kb/s. Deduplicate on
   `(languageCode, codecId, bitrate, displayName)` and keep the first occurrence —
   which is also the one carrying the default flag on Dragon Tattoo.
3. **Attribute 22 partially solves commentary detection — and partially does not.**
   On `supertroopers-min0.txt` title 0, streams 4 and 5 are both `DD Stereo English`
   192 Kb/s but carry `22 = "1"` and `22 = "2"` where the feature audio carries
   `22 = "0"`: a cast commentary and a director commentary, flagged by MakeMKV.
   `hanna-min0.txt` title 3 stream 5 carries `22 = "1"` where the otherwise
   byte-identical stream 4 carries `0`. **But it misses cases**: on
   `super-troopers-2-min0.txt` title 0, streams 1 and 2 are both
   `DD Surround 5.1 English` at 448 and 384 Kb/s with `22 = "0"` on both — the
   384 Kb/s track is almost certainly a commentary and nothing in the metadata says
   so. So: treat a non-zero, non-4096 attribute-22 value as a commentary signal
   worth *excluding by default and showing in the list*, and accept that a
   bitrate-differing duplicate in the same language remains **unsolved**. Do not
   invent a "lower bitrate means commentary" rule — Dragon Tattoo's two 448 Kb/s
   English 5.1 tracks would break it in the other direction.

**Forced subtitles are detectable, and they are the one subtitle class worth
keeping** for a Plex movie, because they caption foreign dialogue in an otherwise
English film. Detect them from **attribute 22 == 4096**, not by string-matching
`"(forced only)"` out of attribute 30. All ten occurrences in the corpus are
`S_VOBSUB` streams — e.g. `SINFO:0,6,22,0,"4096"` alongside
`SINFO:0,6,30,0," English  (forced only)"` in `super-troopers-2-min0.txt`. Attribute
30 is a localized display string; attribute 22 is a number.

them lowercase and normalize once on the way in. Note the corpus uses the
bibliographic codes — `fre` not `fra`, `chi` not `zho` — and

### Available languages

A pure function on the selected title:

```swift
extension DiscTitle {
    var audioLanguages: [LanguageOption]      // code + display name + track count
    var subtitleLanguages: [LanguageOption]
}
```

Derive from `streams` filtered by `DiscStream.kind`, grouped by `languageCode`, in
first-appearance order — which on a DVD is usually the disc's own priority order and
is a better default ordering than alphabetical.

**Deduplicate before grouping.** Collapse streams with an identical
`(languageCode, codecId, bitrate, displayName)` tuple to their first occurrence, and
keep the count so the UI can say "2 tracks". Without this, Dragon Tattoo offers the
same 448 Kb/s English 5.1 track twice and the user has no way to tell them apart.

**Flag commentary rather than hiding it.** A stream whose attribute-22 flags carry a
non-zero value other than 4096 is a commentary; show it in the list, labelled, and
leave it unselected by default. Accept that some commentaries are unflagged (Super
Troopers 2) and will be offered as ordinary tracks.

**The whole-title no-language fallback is not the same as a per-stream `nil`.** Two
distinct rules, and getting them confused is how the silent MP4 happens:

- A *single* stream with no language code among tagged siblings → offer it as an
  explicit "Undetermined" option, as before.
- *No stream on the title carries a language code at all* (Hornets' Nest) → the
  language preference does not apply to this title. Keep every audio track and say
  so in the UI: "this disc does not tag its audio languages — keeping all tracks".
  Do not silently fall back to "first track only", which looks identical in the UI
  and is wrong on a disc with an English and a Spanish track.

Use `Locale.current.localizedString(forLanguageCode:)` for the display name rather
than `DiscStream.languageName` (attribute 4), which is localized to MakeMKV's UI
language, not the user's — and which is absent entirely on an untagged disc.

#### A rule the original plan gets wrong: never merge untagged streams

Merge duplicates only among streams that carry a language tag. Hornets' Nest's
feature has two untagged `DD Surround 5.1` tracks. Identical metadata with no
language is exactly what a Swedish original plus an English dub looks like. The
original key `(languageCode, codecId, bitrate, displayName)` would merge them and
silently lose a language.

`Changeover/AudioTrackOptions.swift`, pure and `nonisolated`:

```swift
nonisolated enum LanguageCode {
    /// Lowercased ISO 639-2/T. nil, "" and "und" → nil. Bibliographic → terminologic (fre→fra, ger→deu, chi→zho, dut→nld, …).
    static func normalize(_ code: String?) -> String?
}

nonisolated struct AudioTrackOption: Equatable, Sendable, Identifiable {
    var trackNumber: Int              // first occurrence; what --audio receives
    var duplicateTrackNumbers: [Int]  // identical *tagged* tracks merged into this row ("2 tracks")
    var languageCode: String?         // normalized; nil = untagged
    var displayName: String           // displayName, else languageName, else "Track N"
    var isCommentary: Bool
    var id: Int { trackNumber }
}

nonisolated enum AudioTrackOptions {
    static func options(for title: DiscTitle) -> [AudioTrackOption]
    static func isUntagged(_ title: DiscTitle) -> Bool
    static func preselection(_ options: [AudioTrackOption], preferred: [String], untagged: Bool) -> [Int]
}
```

**`options`**

- Audio streams are listed in `TrackNumber` order.
- Tagged streams are merged on
  `(languageCode, codecId, bitrate, channelCount, flags, displayName)`, keeping the
  first occurrence.
- `flags` is part of the key, so a commentary never merges into a main track.
- Untagged streams are never merged.

**`isUntagged`** is true when no audio stream has a normalized code.

**`preselection`**

- On an untagged title, select every non-commentary option, and the UI says why.
- Otherwise, select the non-commentary options in the preferred languages.
- If nothing matches, select the first non-commentary option and say why.
- If every option is a commentary, select the first one.
- The result is never `[]` for a title that has audio.

`EncodeController.AudioSelection` is defined by #0029 (see its refresh).
