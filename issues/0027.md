# 0027 — Audio and subtitle languages cannot be chosen anywhere in the app

| | |
|---|---|
| **Status** | open |
| **Module** | MetadataEntryView / AppSettings |
| **Platform** | macOS |
| **First seen** | 2026-09-11 |

## Description

`mac_plex_dvd_workflow.md` §3.3 says to keep English and Spanish audio and drop the
rest. Changeover offers no way to express that — there is no track UI, no language
preference, and the HandBrake invocation is a fixed string
(`Changeover/EncodeController.swift:20-28`). The user gets whatever the defaults
produce.

## Long Description

This ticket is the *choosing*; [#0029](0029.md) is the *enforcing*. They are split
because the UI is testable and the encoder behaviour needs a disc, and because the
request shape defined here is protocol surface that Phase 4 inherits directly —
`RemoteControl.md` lines 324–329 already sketches it:

```swift
struct RipRequest: Codable {
    let metadata: MovieMetadata
    let titleIndices: [Int]
    let audioLanguages: [String]      // e.g. ["eng", "spa"]
    let subtitleLanguages: [String]
}
```

Defining that type now, in the host app, and shaping the UI to produce it means the
Phase 4 package move is a file drag rather than a redesign of how a job is
described.

One finding from planning that should not be buried: **DVD subtitles cannot be
carried into an MP4 as selectable tracks.** DVD subtitles are VOBSUB — bitmap
images — and MP4 supports only text-based subtitle tracks. HandBrake will either
drop them or require burning them into the picture. So "pick subtitle languages"
cannot mean the same thing as "pick audio languages" for this app's output format,
and the UI must not imply otherwise. `Roadmap.md` line 119 pairs them as if they were
symmetric; they are not. See [#0029](0029.md) for the options.

## Steps to reproduce

1. Insert a DVD that carries English, Spanish and French audio.
2. Search the title, pick the poster, and look for a track list.

## Expected behavior

Once a title is selected, its actual audio and subtitle streams are listed with their
languages, with the user's preferred languages preselected. The selection is carried
into the job as an explicit `RipRequest`.

## Actual behavior

There is no track UI. `MetadataEntryView`
(`Changeover/MetadataEntryView.swift:11-26`) has a search bar, results list, folder
preview, log and a start button. `startRipping()` (`:142-155`) constructs a
`DVDPipeline` from a `MovieMetadata` and `AppSettings` and nothing else, and
HandBrake is invoked with a hard-coded `--aencoder copy:aac,copy:ac3 --subtitle scan`
(`Changeover/EncodeController.swift:24-26`).

## Notes

Two genuinely different verification stories, and the ticket should be honest about
which is which.

Unit-testable with no disc: the derivation of the available-language list from a
`DiscTitle`'s streams; the intersection of preferred languages with available ones;
the fallback when no preferred language is present; `RipRequest` JSON round-trip; the
`AppSettings` load/persist of the preferred-language lists.

Needs a disc: that the languages listed match what MakeMKV.app shows for the same
title. Whether the chosen languages actually survive into the `.mp4` belongs to
[#0029](0029.md) and should be verified there, not claimed here.

### `RipRequest`

Match `RemoteControl.md` lines 324–329, with two changes:

```swift
nonisolated struct RipRequest: Codable, Hashable, Sendable {
    var metadata: MovieMetadata
    var titleIndices: [Int]
    var audioLanguages: [String]
    var subtitleLanguages: [String]
}
```

`nonisolated` for the same reason as [#0022](0022.md): the project sets
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`
(`Changeover.xcodeproj/project.pbxproj:416,445`), and this value has to reach
`RipController` and `EncodeController`, both `nonisolated static`
(`Changeover/RipController.swift:9`, `Changeover/EncodeController.swift:9`). And
`Codable` requires `MovieMetadata` to become `Codable` too —
`Changeover/MovieMetadata.swift:5-26` is currently a plain struct with a
`TMDBMovie`-only initializer (`:10-14`). Add `Codable, Hashable, Sendable` and a
memberwise init alongside the existing one; it is three stored `String`s
(`:6-8`), so the synthesized conformance is free and Phase 4 needs it anyway.

Language codes are ISO 639-2 three-letter strings (`"eng"`, `"spa"`) exactly as
MakeMKV reports them in attribute 3, so no mapping layer is needed between the scan
and the request. Keep them lowercase and normalize once on the way in.

### Available languages

A pure function on the selected title:

```swift
extension DiscTitle {
    var audioLanguages: [LanguageOption]      // code + display name + track count
    var subtitleLanguages: [LanguageOption]
}
```

Derive from `streams` filtered by `DiscStream.kind`, grouped by `languageCode`, in
first-appearance order — which on a DVD is usually the disc's own priority order and
is a better default ordering than alphabetical. Streams with a `nil` language code
happen (untagged tracks are common on older DVDs) and must be representable: give
them an explicit "Undetermined" option rather than dropping them, or a user with a
disc whose only audio track is untagged ends up with a movie with no audio.

Use `Locale.current.localizedString(forLanguageCode:)` for the display name rather
than `DiscStream.languageName` (attribute 4), which is localized to MakeMKV's UI
language, not the user's.

### Preferences

Add to `Changeover/AppSettings.swift` next to the existing stored properties
(`:13-16`), with `Keys` (`:58-63`), `init()` loads (`:38-43`) and `persist()` writes
(`:48-54`):

```swift
var preferredAudioLanguages: [String] = ["eng", "spa"]
var preferredSubtitleLanguages: [String] = []
```

The `["eng", "spa"]` default is straight out of `mac_plex_dvd_workflow.md` §3.3 and
is the actual working default for this library. Note that the existing `init()`
pattern guards on `!v.isEmpty` for strings (`:39-42`); an array needs
`stringArray(forKey:)` and a `nil` check, and an *intentionally* empty list must
survive a round trip — which is why `preferredSubtitleLanguages` defaulting to empty
needs the `nil`-versus-empty distinction to be handled properly rather than with the
existing `isEmpty` idiom.

`SettingsView` (`Changeover/SettingsView.swift`) gets a field for each. A
comma-separated text field is adequate and matches the existing form's density; a
token field is nicer and can wait.

### The picker

`TrackSelectionView` sits under the selected title row from [#0026](0026.md), and
appears only when a title is selected. Two labelled groups — Audio, Subtitles — each
a list of toggles, one per available language, showing the track count per language
so a disc with two English audio tracks (stereo plus 5.1) is visible.

Preselection: intersect the title's available languages with the preferred lists. If
the intersection is empty for audio, select the first available track and say why —
silently producing a movie with no audio because the disc has no English is the worst
outcome available here, and it is the likeliest way this feature misfires on a
foreign-language disc.

For subtitles, surface the VOBSUB/MP4 constraint at the point of choosing rather than
letting the user discover it in the output: label the group to make clear whether the
selection burns in or is dropped, per whichever route [#0029](0029.md) takes. Do not
ship a picker that quietly does nothing.

State ownership follows [#0026](0026.md) and `Plan.md`'s conventions: the selection
lives on `JobController` ([#0001](0001.md)), the view takes it as a parameter and
uses `@Bindable` for the toggles — no `@State` copies, no `ObservableObject`.

### Threading the request through

`startRipping()` (`Changeover/MetadataEntryView.swift:142-155`) builds
`DVDPipeline(metadata:settings:log:)` today. Change `DVDPipeline`
(`Changeover/DVDPipeline.swift:9-13`) to hold a `RipRequest` instead of a bare
`metadata`, and keep `settings` as it is — the pipeline already captures the paths it
needs off `AppSettings` on the main actor before entering nonisolated code
(`:19-24`), which is the right pattern and should be preserved when the language
lists join them.

`metadata.folderName` / `.fileName` (`Changeover/MovieMetadata.swift:17-24`) are used
at `DVDPipeline.swift:17,39` and must keep working unchanged — reach them through
`request.metadata`.
