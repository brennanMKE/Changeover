# 0241 — A multi-film disc has no plan an agent can read

| | |
|---|---|
| **Status** | open |
| **Phase** | 4 — Agentic control |
| **Module** | BridgeStatusReader / AgentJobReport / AgentActions |
| **Platform** | macOS |
| **First seen** | 2026-10-08 |

## Description

`status` and `report` both assume one film per disc. On WILLIS — title 5 as
Perfect Stranger, title 6 as Mortal Thoughts — that assumption makes the
agent's own plan invisible to it.

Three places it shows, from one real session:

1. **Before Start.** After two `select` calls, `status.film` showed only the
   *last* one (Mortal Thoughts) and `report` said "films — nothing planned for
   this disc". There was no way to confirm the second select had **added** a
   film rather than **replaced** the first, so the agent had to press Start to
   find out. Starting an encode to discover what you were about to encode is
   the wrong order.
2. **During the job.** `status.film` was Mortal Thoughts (last selected) while
   `status.job.film` was Perfect Stranger (actually encoding). Two fields a
   field apart naming different films, with no list reconciling them.
3. **In the import result.** The `film` line named only Perfect Stranger,
   though the job will file both.

## Suggested fix

`status.films[]` — title index → film → state — the shape `job.extras` already
uses, so a consumer meets one idiom rather than two. `report.films` already has
`FilmEntry` with exactly that shape and is simply empty before Start, which is
the bug in (1) rather than a missing type.

Keep `status.film` for the single-film case rather than breaking every existing
consumer, but it must stop meaning "the last one selected" on a multi-film
disc — that is the value that misleads.

## Why it matters

The whole premise of `select` + `import` is that an agent can build up a plan
and then commit it. A plan it cannot read back is a plan it cannot check, and
the only way to see it was to run it.

## Relation

Same family as #0203, #0208, #0213, #0214, #0236 and #0240: the app knows, the
projection does not say. This one is an omission rather than a wrong value,

adjacent fields name different films with nothing saying why.
