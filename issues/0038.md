# 0038 — The confirmation row reports "Zero KB" for every title and the extras checkboxes are reachable only through a link that says "Not this one?"

| | |
|---|---|
| **Status** | open |
| **Phase** | 2 — Choose what gets ripped |
| **Module** | DiscTitleListView / DiscTitleFormatting |
| **Platform** | macOS |
| **First seen** | 2026-09-15 |

## Description

Two defects in the same row of the same view, both on the screen the Phase 2
demo is built around.

**"Zero KB".** A HandBrake scan reports no title size, so
`HandBrakeScanParser` sets `sizeBytes: 0` and documents `0 = unknown`
(`Changeover/HandBrakeScanParser.swift:181`). `DiscTitleFormatting.size(_:)`
hands that straight to `ByteCountFormatter` (`Changeover/DiscTitleFormatting.swift:18-20`),
which renders `0` as **"Zero KB"**. The confirmation row therefore reads
`Main feature — Title 3 · 1:50:45 · 21 chapters · Zero KB`
(`Changeover/DiscTitleListView.swift:157`), and every row of the full table
carries a "Zero KB" column (`:243`). It is a stated value, and it is false.
`Roadmap.md` line 101 promises "duration, chapter count and size"; showing a
wrong size is worse than showing none.

**Extras behind "Not this one?".** #0031 put the per-row "Extra" checkbox in
the full title table (`Changeover/DiscTitleListView.swift:262-269`). On a
`.single` disc — every movie disc in the corpus — the table is collapsed and
the only control that opens it is the link labelled **"Not this one?"**
(`:161`). A user who agrees with the detected feature and wants a featurette
has no visible way to get one: the one affordance on screen says the
opposite of what they want to do. #0031's review recorded this and #0020's
"Phase review inputs" carries it as a handoff.

Found by the Phase 2 phase-level review; the second half was first noted in
#0031's review.

## Expected behavior

- When the scan reports no size, the size is omitted from the confirmation
  row and shown as `—` in the table. A real size, when one exists, renders
  as today.
- The confirmation row offers extras directly — "Extras: none · Choose…" —
  and, once some are ticked, says so ("Extras: 2 · 0:48:10"). The disclosure
  that shows the full table is labelled for what it does ("Show all titles"),
  not for one reason someone might open it.

## Actual behavior

"Zero KB" on every row; extras reachable only by clicking "Not this one?".

## Notes

- Do not change `DiscTitle.sizeBytes` to an optional. It is wire format
  (#0022, Phase 4) and `0 = unknown` is already the documented contract; the
  fix is in formatting and layout only.
- A real per-title size is derivable when lsdvd is present (`lsdvd -x -Oj`
  reports cell sector ranges; `DVDMonitor` already runs lsdvd for identity).
  That is an enrichment for another ticket, not this one.
- The table's *rows* are already correct about what gets ripped:
  `JobController.toggleExtra` refuses the feature and `selectedExtrasPlan`
  is the same `ExtrasPlan.make` that `start` runs (#0031 review). Nothing
  here touches `StartGate`, `JobController` or the pipeline.
- Both halves are view-only and cannot be unit-tested beyond the formatter.
  No UI test is warranted or permitted; the rendering is checked on joe.

## Plan

### Files

Changed: `Changeover/DiscTitleFormatting.swift`, `Changeover/DiscTitleListView.swift`,
`ChangeoverTests/DiscTitleFormattingTests.swift`.

### Size

- `DiscTitleFormatting.size(_:)` returns `String?`: `nil` for `bytes <= 0`,
  the `ByteCountFormatter` string otherwise. Doc-comment the `0 = unknown`
  contract with the parser line as the reference.
- Confirmation row (`:157`): build the ` · ` segments from an array and
  append the size only when non-nil, so the row reads
  `— Title 3 · 1:50:45 · 21 chapters` on a HandBrake scan.
- Table row (`:243`): `Text(size ?? "—")`, keeping the fixed column width so
  the columns still align.
- Tests: `size(0)` is `nil`, `size(-1)` is `nil`, `size(6_795_724_800)` is
  the existing "6.8 GB"-style string.

### Extras affordance

In `confirmationRow(index:disc:)`:

- Rename the disclosure button: `showFullTable ? "Hide titles" : "Show all
  titles"`. It still preselects nothing new — the feature stays selected —
  so opening it is not a disagreement.
- Add a second line under the headline, driven by `jobs.selectedExtrasPlan`:
  - empty: `Extras: none` plus a `.link` button `Choose…` that sets
    `showFullTable = true`;
  - non-empty: `Extras: N · <total duration>` (reuse `extrasSummary`'s
    wording) plus `Change…`, same action.
- Leave `extrasSummary` where it is for the `.playAll`/`.none` layouts, but
  don't render it twice on `.single` — the new line replaces it there.
- Keep the "Rip this title as an extra, filed outside the Plex library" help
  text on the checkbox; it is the only place the destination is explained.

Optional and cheap: show the title count in the headline — `Title 3 of 16` —
so "it picked the right one out of sixteen" is visible without opening the
table. `disc.titles.count` is already in hand.

### Verification

- Unit: the three formatter tests above, via `./run-remote-tests.sh gordon`.
- Manual, on joe with a real disc (say which): the confirmation row shows no
  "Zero KB"; the table's size column shows `—`; "Extras: none · Choose…"
  opens the table; ticking a box updates the line; "Show all titles" does
  not change the selected feature.
