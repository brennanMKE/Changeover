# 0007 — The pipeline reports its outcome only as log text, so nothing can act on success or failure

| | |
|---|---|
| **Status** | open |
| **Phase** | 1 — Trustworthy single-disc rip |
| **Module** | DVDPipeline / PlexOrganizer / RipController / EncodeController |
| **Platform** | macOS |
| **First seen** | 2026-09-11 |

## Description

`DVDPipeline.run()` returns `Void` and signals failure by logging and returning early (`DVDPipeline.swift:16`, `:32`, `:48`). `PlexOrganizer.move` swallows its error entirely (`PlexOrganizer.swift:29-31`), after which the pipeline still logs `"── Done."`. There is no value anywhere in the app that says whether the movie actually landed in Plex.

## Long Description

Every other Phase 1 ticket needs this. Cleanup ([#0004](0004.md)) must only delete working files on a genuine success. Eject ([#0005](0005.md)) must only run on success. The notification ([#0006](0006.md)) must say which of the two happened and why. Preflight ([#0008](0008.md)) and failure classification ([#0009](0009.md)) both need a vocabulary of reasons to produce. Right now the only channel is a `(String) -> Void` log closure aimed at a `LazyVStack`.

The current signatures throw information away at every boundary:

- `RipController.rip` returns `String?` (`RipController.swift:13`) — `nil` at line 52 (non-zero exit) and `nil` at line 61 (launch failed) are indistinguishable to the caller.
- `EncodeController.encode` returns `Bool` (`EncodeController.swift:14`) — same collapse.
- `PlexOrganizer.move` returns `Void` and catches everything (`PlexOrganizer.swift:8`, `:29-31`).
- `MetadataEntryView.startRipping()` sets `isProcessing = false` unconditionally after `await pipeline.run()` (`MetadataEntryView.swift:152-153`), because there is nothing else it could do.

This is also the shape that goes on the wire in Phase 4. `Roadmap.md` lists `JobState` in the `ChangeoverProtocol` package; defining it as a plain `Codable` value type now is far cheaper than reshaping it across a package boundary later.

## Steps to reproduce

1. Make the Plex Movies destination unwritable — point `plexMediaRoot` at a read-only location, or `chmod a-w` the `Movies` folder.
2. Run a job to completion (a stub `makemkvcon`/`HandBrakeCLI` is enough).
3. Read the log: `"✗ ERROR moving file: …"` is immediately followed by `"── Done. Scan your Plex Movies library to pick up the new title."`
4. The UI returns to idle exactly as it would after a success.

## Expected behavior

`run()` returns a typed outcome. A failure names the stage it failed at and a machine-readable reason; a success carries the destination path. The UI, the cleanup step, the eject step and the notification all read that value rather than inferring anything from control flow or log text.

## Actual behavior

The pipeline returns nothing. A move failure is logged and then contradicted by a success message on the next line. Callers cannot distinguish any outcome from any other.

## Notes

This is the most testable ticket in Phase 1 and it needs no disc at all. Real unit tests to write and run:

- Each controller's failure paths map to the expected `JobFailure` (launch failure vs. non-zero exit are different reasons).
- `PlexOrganizer.move` throws when the destination is unwritable — exercisable against a temp directory with permissions removed.
- `DVDPipeline.run()` returns `.failed(.organize, …)` for that case and never logs the "Done" line.
- Round-trip `Codable` on the outcome types, since Phase 4 will put them on the wire.

A full pass with a real disc is still wanted to confirm no regression in the happy path; say so in `## Verification`.

## Plan

### New file: `Changeover/JobOutcome.swift`

Plain value types, `Codable`, `Sendable`, `Equatable`:

```swift
enum JobStage: String, Codable, Sendable { case preflight, rip, encode, organize }

enum FailureReason: Codable, Sendable, Equatable {
    case toolMissing(path: String)
    case toolLaunchFailed(String)
    case toolExited(code: Int32)
    case noTitlesProduced
    case destinationUnwritable(path: String)
    case diskFull
    case activationExpired          // MakeMKV key — see #0009
    case discUnreadable
    case cancelled
    case unknown(String)
}

struct JobFailure: Error, Codable, Sendable, Equatable {
    let stage: JobStage
    let reason: FailureReason
    let logTail: [String]           // last lines of tool output, for #0009
}

enum JobOutcome: Codable, Sendable, Equatable {
    case succeeded(destination: URL)
    case failed(JobFailure)
}
```

These are constructed inside `nonisolated static` functions, so mark them `Sendable` and keep them free of any MainActor-isolated members. No `actor`, no `@Observable` — they are values.

**Do not give `JobFailure` a `LocalizedError` conformance with a baked-in user-facing string.** Turning a reason into human text is [#0009](0009.md)'s job and it needs to be separately testable. Keep this file free of presentation.

### Signature changes

- `RipController.rip(...) async -> String?` (`RipController.swift:9-13`) → `async -> Result<URL, JobFailure>`. The three `continuation.resume` sites (lines 48, 52, 61) become: success with the selected file, `.toolExited(code:)`, and `.toolLaunchFailed`/`.toolMissing` respectively. [#0003](0003.md) adds a fourth: `.noTitlesProduced`.
- `EncodeController.encode(...) async -> Bool` (`EncodeController.swift:9-14`) → `async -> Result<URL, JobFailure>` (the output path on success). Termination handler at lines 48-55, launch failure at lines 59-63.
- `PlexOrganizer.move(...)` (`PlexOrganizer.swift:8-13`) becomes `throws` and the `do/catch` at lines 21-31 loses its `catch`. Keep the `log("✓ Moved to: …")` line — the log stays, it just stops being the only channel.
- `DVDPipeline.run()` (`DVDPipeline.swift:16`) returns `JobOutcome`. The three early returns (lines 32-33, 48-49, and the implicit end at 61) become explicit outcome values. The `"── Done."` line moves under the success branch only.
- `MetadataEntryView.startRipping()` / `JobController.start` consume it.

### Ordering

Land this before [#0002](0002.md) if possible, and definitely before [#0004](0004.md), [#0005](0005.md), [#0006](0006.md) and [#0009](0009.md). It is a mechanical refactor with no behavior change on the happy path, which makes it a good first commit in the phase.

### Risks

- **Continuation discipline.** `RipController` has three `resume` sites inside a `withCheckedContinuation` (lines 48, 52, 61) and `EncodeController` has two. `withCheckedContinuation` traps on a double resume. Adding branches here is exactly how that bug gets introduced — re-read each path after the change, and note that the `catch` at line 58 and the `terminationHandler` can both fire if `run()` throws after partially succeeding.
- **`Sendable` and `URL`.** `URL` is `Sendable`; the log closure is not, which is why it is typed `@escaping @MainActor (String) -> Void` (`RipController.swift:12`). Keep that annotation; do not "simplify" it to a bare closure.
- **Scope discipline.** Resist adding progress percentages or per-stage timing to `JobOutcome` in this ticket. Progress reporting is a Phase 3/4 concern and parsing `HandBrakeCLI` progress output is its own piece of work.
- Keep the log closure exactly as it is. The log is the human channel and the outcome is the machine channel; both are wanted, and collapsing them was the original mistake.
