# 0153 — A deleted scene the menu links to is dropped by the minimum-duration filter

| | |
|---|---|
| **Status** | open |
| **Phase** | 3 — Unattended multi-disc |
| **Module** | DiscTitleHeuristic / ExtrasSelection |
| **Platform** | macOS |
| **First seen** | 2026-10-07 |

## Description

On `PACIFIC_RIM_UPRISING` the disc's menu has a labelled **ALT. PARTY** button
that dispatches to title 26, and title 26 never appears in the scan's title
list. It is being removed by the minimum-duration filter before anything can
select it.

The missing scene is about 14 seconds, and that figure is measured rather than
guessed: the deleted-scenes Play All (title 25) runs 7:00, and the six scenes
that did survive sum to 6:46. The 14-second remainder is title 26.

## Why this matters

The filter exists to drop material nobody asked for — padding, filler, stray
PGCs the disc never surfaces. A title that a menu button `JumpTT`s to is the
exact opposite of that: the disc's authors put a labelled control on screen
pointing at it. Length is a good proxy for "nobody wants this" only when there
is no better evidence, and here there is better evidence.

## Suggested fix

Exempt a **dispatch-reachable** title from the duration floor, rather than
lowering the floor for everything. Lowering the floor would readmit filler on
every other disc; the exemption only admits titles the disc itself advertises,
and it explains itself in the UI — this title is here because a menu button
points at it.

The same evidence is worth using in the other direction: once the resolver
knows which titles the menu reaches, a title that **nothing** reaches is a
candidate for dropping whatever its length. That is a separate change and
should not be bundled in.

## Relation

Depends on the dispatch resolver that reads the launcher PGC's `(g4 constant ->
title)` table. Until that exists there is no notion of "reachable" to exempt
on, so this is blocked on that work rather than on the filter itself.
