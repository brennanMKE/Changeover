# 0237 — No CLI way to retry a failed read differently

| | |
|---|---|
| **Status** | open |
| **Phase** | 4 — Agentic control |
| **Module** | ChangeoverBridge / AgentActions / RipFlowController |
| **Platform** | macOS |
| **First seen** | 2026-10-08 |

## Description

When an encode fails part-way through a disc read, an agent has no way to try
again differently. There is no CLI option to:

- read from the **mounted volume** instead of the raw device (or the reverse);
- encode a **chapter or time range**, to get the undamaged majority of a film
  or to probe where the damage is;
- retry at all, beyond re-running `import` with the identical selection and
  expecting a different outcome.

Found after `job-20261008-123159-0D74` failed at 67 % with `discUnreadable` on
a disc that was unmounted at the start of the encode and mounted by the end.
Both plausible causes have an obvious next move and neither is expressible.

## Why it matters

The agentic premise is that an agent can carry a disc through to a result. A
failure it can only repeat identically is a dead end, and the disc sits in the
drive waiting for a person — which is the thing the bridge exists to avoid.

`JobController.retry(id:settings:)` already exists and replays the job's own
`RipRequest`. That is the right engine; what is missing is a way to vary one
input of it.

## Suggested shape

`retry --job <id>` as the verb, with an optional override:

- `--from mounted|raw` for the read source;
- `--chapters <a>-<b>` or `--range <start>-<end>` for a partial encode.

Each override echoed in the result, the way `--confirm` is (#0234), so the
record says what was varied. The default with no override is today's behaviour:
replay the request exactly.

The partial-encode case needs a decision this ticket does not make: a film
encoded from chapter 3 onwards is not the film, and must not be filed into Plex
as though it were.

## Relation

#0236 is the other half — without the evidence it asks for, an agent cannot
choose which retry to attempt, so these are worth doing in that order.
